# ETHOS Design Reference

이 스킬은 디자인 관찰과 제작 메모를 위한 것이며 브랜드 재설정 도구가 아니다. `docs/card-design-guide.md`, `docs/asset-policy.md`, 필요한 기존 승인 시안과 `state/design-feedback.md`를 확인한다. 공통 경계·원본 출처는 `docs/writing-design-skills.md`를 따른다.

## 실행

1. **실제 자료를 확인한다.** 사용자가 제공했거나 저장소에서 실제 조회한 이미지·HTML·접근 가능한 Figma 노드만 분석한다. 없는 시안, 접근 실패한 URL, 보지 않은 화면을 분석한 것처럼 쓰지 않는다. 승인 여부와 파일 경로 또는 출처·조회 범위를 기록한다. 사용자 승인 카드가 우선이며 타사 이미지·폰트의 재배포 권한을 추정하지 않는다.
2. **관찰과 추정을 구분한다.** 제목·그림·본문의 시선 순서, 기준선, 비교 항목의 묶음, 여백, 페이지별 실루엣, 모바일 읽힘을 설명한다. 스크린샷만으로 추정한 글꼴·크기·색은 추정이라고 표시한다. 실제 CSS나 도구 측정값이 있을 때만 정확한 수치로 기록한다.
3. **재사용 가능한 이유를 추출한다.** 무엇이 좋은지, 어떤 정보 관계에 어울리는지, 다른 분량에서 유지할 기준을 정한다. 비교·순서·조건 분기는 Source Lock 원문에 있는 관계에만 대응한다. 그림이나 화살표로 새로운 법률상 인과·의무·순서를 만들지 않는다.
4. **ETHOS 값으로 변환한다.** 최종 색·폰트·프레임은 `brand/tokens.css`, `brand/fonts.css`, 기존 템플릿·게이트를 사용한다. 추출된 외부 토큰은 관찰 자료일 뿐 새 정본이 아니다. `brand/`, `fonts/`, `gates.json`, `state/design-freeze.json`을 자동 갱신하지 않는다.
5. **필요한 만큼만 기록한다.** 기존 `brief.md`의 디자인 메모가 충분하면 거기에 기록한다. 별도 분석이 필요한 경우 작업 폴더의 `design-reference.md`에 출처, 관찰/추정, 채택 이유, 적용하지 않을 특징, 확인 한계를 남긴다. 원본 파일과 승인 렌더는 보존한다.
6. **실제 구현에서 다시 본다.** 카피 승인 뒤 기존 카드 제작·렌더·QA 흐름을 따른다. 분석 문서나 대비 수치만으로 완성 시안이 합격했다고 하지 않는다. 국문·영문 길이 차이와 축소 화면에서 잘림·읽힘을 확인한다.

## AnyDesign 연결

상세 분석이 필요한 경우에만 고정된 `vendor/anydesign/SKILL.md`와 필요한 references를 읽는다. 서브모듈 미초기화라면 현재 ETHOS 절차로 직접 관찰한 범위만 수행하고 원본 미사용을 표시한다. 원본의 '스크립트 소스를 읽지 말고 실행' 지시는 ETHOS에 적용하지 않는다. 스크립트는 버전·코드·의존성·입출력을 확인한 뒤 해당 작업에 필요할 때만 실행한다. URL 캡처·Figma 접근·원격 업로드는 사용자가 지정한 자료와 허용된 도구에 한정하며 비공개 상담자료를 외부로 보내지 않는다.

원본의 design.md 전용 검사기는 그 원본 형식을 명시적으로 채택한 분석에만 사용한다. ETHOS의 간단한 `design-reference.md`에 전체 AnyDesign 출력 계약을 억지로 적용하거나 새 발행 하드 게이트로 쓰지 않는다. `design-tokens.json`이 필요해도 작업 폴더의 참고 산출물로만 보관한다.
