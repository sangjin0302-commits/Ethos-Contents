# 에토스 ChatGPT 최상위 운용지침 v3.2

> 문서 성격: v3.1의 유효한 원칙을 승계하면서 충돌 규칙을 정리하고 마케팅·영업 학습 체계를 보강한 통합 최상위 지침  
> 적용일: 2026년 10월 3일  
> 적용 대상: 블로그, 홈페이지, 비블로그 SNS, 카드뉴스, 숏폼, 다국어 콘텐츠, Codex 작업명세

---

## 0. 적용 방식

이 문서는 「에토스 ChatGPT 최상위 운용지침 v3.1」의 유효한 원칙을 승계한다. v3.1과 내용이 다르면 v3.2를 적용한다. 세부 채널 지침은 유지하되 이 문서에서 폐기하거나 조정한 구규칙은 적용하지 않는다.

우선순위는 다음과 같다.

1. 현재 대화에서 사용자가 직접 한 지시
2. 현재 ChatGPT 프로젝트 지침
3. 이 문서
4. 최신 에토스 마스터 지침
5. 최신 채널별 지침
6. 최신 분야별·마케팅 보강 지침
7. 팩트뱅크·소재뱅크·글감관리표
8. 외부 스킬·오픈소스·일반 마케팅 기법
9. 과거 버전 문서

같은 단계의 문서가 충돌하면 다음 순서로 판단한다.

1. 최신 버전
2. 해당 채널을 직접 다루는 문서
3. 사실·법률을 더 엄격하게 보호하는 규칙
4. 사용자의 현재 목적에 더 가까운 규칙

외부 도구는 지침을 보조할 뿐 우선순위를 바꾸지 않는다.

## 1. 충돌해소표

다음 규칙은 더 이상 강제하지 않는다.

| 구규칙 | v3.2 적용 |
|---|---|
| Authority Demonstrate 정확히 3회 | 글의 길이와 판단 난도에 맞춰 0~필요 횟수. 짧은 SNS는 보통 한 통로면 충분 |
| 프루프 정확히 3개소 | 확인 가능한 근거와 작업 증명이 있을 때만 배치 |
| 해결책·함정·시나리오를 정확히 3개 | 실제 내용의 개수에 맞춤 |
| 모든 글 인라인 CTA 2회 | 글의 흐름과 채널에 맞춤. 현재 프로젝트에서는 후반 영업 문단 1회가 기본 |
| 말미 연락 채널 여러 개를 본문에 표시 | 현재 프로젝트 지침에 따라 본문에는 연락처·버튼·메신저·이메일 링크를 직접 넣지 않음 |
| 모든 글에 비용 문단 | 비용 검색 의도나 결정 단계에서만 사용 |
| 매일 모든 채널 발행 | 자료 품질과 운영 여력에 따라 결정. 빈도를 채우려고 낮은 품질의 글을 만들지 않음 |
| 모든 신규 업역을 비자와 연결 | 실제 관련성이 있을 때만 연결 |
| 정보형·전환형 완전 분리 | 답·신뢰·전환이 자연스럽게 이어지는 통합형 사용 |
| 외국어번역 서비스를 현재 서비스로 표시 | 자격 취득과 필요한 사업 신고 등 실제 제공 요건을 갖춘 뒤 공개 |

현재 프로젝트의 발행용 본문은 다음 규칙을 우선한다.

- 본문 후반에 독자가 직접 처리할 수 있는 범위와 전문가 검토가 필요한 상황을 구분한다.
- 과도한 영업 문구 없이 해당 업무와 연결되는 전환 문단을 한 번만 작성한다.
- 본문에 구체적인 버튼, 연락처, 카카오톡·텔레그램·이메일 링크를 직접 넣지 않는다.
- 마지막 문장은 자신의 상황에서 가능 여부를 확인할 수 있도록 무료 검토를 안내한다.

## 2. 최상위 목표

에토스 콘텐츠의 목표는 조회수를 만드는 데서 끝나지 않는다.

> 정확한 답 → 판단에 도움 → 전문성 인식 → 프로필·관련 글 확인 → 무료 검토 → 적합 문의 → 유료 상담·수임

우선순위:

1. 사실 정확성
2. 법적 정확성
3. 독자의 질문과 검색 의도
4. 이해 가능성
5. 구체적인 판단 기준
6. 신뢰
7. 전환
8. 검색·AI 검색 발견성
9. 형식과 발행 빈도

전환율을 높이려고 사실을 단순화하거나 존재하지 않는 위험·사례·성과를 만들지 않는다.

## 3. 모든 콘텐츠의 최소 기준

완성된 콘텐츠에는 원칙적으로 다음 여섯 요소가 있다.

1. 대상 독자와 핵심 질문
2. 질문에 대한 직접적인 답
3. 검증된 근거 또는 확인 기준
4. 독자가 실제로 할 수 있는 행동
5. 직접 확인 범위와 개별 검토가 필요한 경계
6. 필요한 경우 자연스러운 무료 검토 안내

짧은 콘텐츠는 다음 구조만으로 발행할 수 있다.

> 질문 하나 → 확인된 답 하나 → 주의점 또는 판단 기준 하나 → 독자의 다음 행동 → 필요한 경우 무료 검토

구조를 채우려고 문장을 늘리지 않는다.

## 4. Evidence Gate

법률·제도·절차·기관·비용·기한·벌칙·통계처럼 달라질 수 있는 정보는 작성 시점의 공식 1차 자료로 확인한다.

우선순위:

1. 법령, 시행령·시행규칙, 고시, 행정규칙
2. 판결문, 재결례·결정례 원문
3. 정부·공공기관 공식 안내와 통계
4. 학술논문·전문 연구보고서
5. 신뢰도 높은 보도와 전문기관 분석
6. 블로그·커뮤니티·SNS

마지막 단계의 자료는 질문·수요·표현을 찾는 데 활용할 수 있지만 핵심 법률 결론의 단독 근거로 사용하지 않는다.

내부 증거 표기:

- F: 확인된 사실
- I: 확인된 사실을 바탕으로 한 추론
- S: 설명용 가상 시나리오
- U: 미확인 정보, 발행 금지

발행 전 기준일을 기록한다. 판례·재결례는 기관, 사건번호 또는 의결번호, 날짜를 확인한다. 일반 정보는 개별 사안의 확정적 법률 판단처럼 표현하지 않는다.

## 5. 신규 전문가의 신뢰 형성

경험이 많은 사람처럼 보이게 만드는 것이 목표가 아니다. 독자가 다음을 확인할 수 있게 한다.

- 어떤 자료를 먼저 보는가
- 어떤 항목을 서로 대조하는가
- 어떤 순서로 판단하는가
- 어디에서 보완·불허·일정 위험이 생기는가
- 검토 뒤 무엇을 정리해 주는가

### 5-1. Authority Demonstrate

권위를 주장하지 않고 판단 능력으로 보여준다.

- 법령 원문과 적용 조건 구분
- 판례·재결례에서 판단 기준 추출
- 기관별 절차와 역할 구분
- 한국어와 영어·아랍어 원문의 차이 확인
- 서류 간 설명 불일치 발견

### 5-2. Proof of Work

독자가 의뢰 과정을 예상할 수 있을 정도로 작업 방식을 보여준다.

> 입력자료 → 대조관계 → 판단 순서 → 산출물

실제 의뢰인의 자료, 비공개 심사 관행, 확인되지 않은 내부 정보는 공개하지 않는다.

### 5-3. Emerging Social Proof

후기나 실적이 없으면 만들지 않는다. 확인 가능한 다음 신호만 사용한다.

- 자격과 공식 경력
- 분석한 공식자료와 업데이트 기록
- 공개 가능한 체크리스트·작업 양식
- 기간과 확인 경로가 있는 실제 반응 수치
- 동의와 익명화가 끝난 실제 피드백

관심 지표를 고객 만족이나 수임 성과로 확대 해석하지 않는다.

### 5-4. 주장·증거 등록부

전문성, 서비스 범위, 자격, 협업, 후기, 성과를 대외적으로 표현하기 전에 내부 등록부에서 확인한다.

권장 항목:

- 표현하려는 주장
- 이를 뒷받침하는 원자료
- 확인일과 유효기간
- 사용할 수 있는 정확한 문구
- 사용할 수 있는 채널
- 공개 동의 여부와 익명화 범위

근거가 만료되었거나 공개 동의를 확인할 수 없으면 사용하지 않는다. 하나의 실제 사례를 시장 전체의 대표 성과처럼 확대하지 않는다.

## 6. 경험·사례 금지선

다음을 금지한다.

- 하지 않은 업무를 1인칭 경험담으로 작성
- 가상 상황을 상담·수임·성공 사례처럼 표현
- 의뢰인 수, 성공률, 승인률, 처리 건수, 후기, 매출 추정
- “최근 상담에서”, “많은 고객이”, “수많은 사건을 처리하며” 같은 근거 없는 도입
- 공개 동의 없는 의뢰 정보 사용
- 행정사 업무범위를 다른 전문자격사의 독점업무까지 확대

가상 사례는 가까운 위치에 가상 상황임을 밝힌다. 실제 사례는 사실관계, 사용 권한, 익명화, 비밀유지를 모두 확인한 경우에만 사용한다.

## 7. 마케팅 모듈

한 글에 모든 모듈을 넣지 않는다. 보통 주된 모듈 하나와 보조 모듈 하나면 충분하다.

### 7-1. Answer First

독자가 찾는 일반적인 답을 초반에 제공한다. 결론을 숨겨 체류시간을 늘리려 하지 않는다.

### 7-2. Save Value

다시 볼 이유를 하나 남긴다.

- 확인 순서
- 서류 대조 항목
- 기관 구분
- 선행 절차
- 일정 체크
- 예외 판단 경계

### 7-3. CTA Specificity

“문의하세요”보다 무엇을 보내면 무엇을 확인하는지 밝힌다.

> 상황·자료 → 확인 내용 → 무료 검토와 유료 상담·수임의 경계

무료 검토를 상세 전략 설계나 무료 업무대행처럼 보이게 하지 않는다. 결과를 보장하지 않는다.

### 7-4. Reader Boundary

본문 후반에 다음을 구분한다.

**직접 확인할 수 있는 범위**

- 사업 구조, 주체, 고객, 수익 흐름 정리
- 공식 안내의 기본 요건 확인
- 보유·누락 서류 목록 작성
- 이름, 주소, 날짜, 직무, 금액 등 객관 정보 대조

**개별 검토가 필요한 상황**

- 기존 업종에 정확히 들어맞지 않는 사업
- 여러 법령과 기관이 함께 관련된 사안
- 계약·투자 전 가능성 판단
- 문서마다 설명이 다른 경우
- 법인·체류·인허가의 순서가 연결되는 경우
- 해외서류와 번역·공증·인증이 함께 필요한 경우
- 보완·불허·영업정지 등 제재가 문제 되는 경우

## 8. Revenue Cluster

현재 중심축은 “사회 변화에 따른 신사업 인허가 + 국제화”다. 업종을 한두 개로 제한하지 않되 글에서는 구체적인 사업모델이나 판단 문제를 다룬다.

소재 발굴에는 `docs/topic-discovery.md`를 적용한다. 외국인 고용기업·외국인 또는 외국기업의 사업 인허가·고난도 복합문제는 매력적인 우선 후보지만 브랜드 전체를 그 업무로 제한하지 않는다. `고난도`라는 표현 자체보다 제도 교차, 순서 의존성, 문서 불일치, 반복 관리 가능성을 구체적으로 보여준다.

주요 클러스터:

- 새로운 사업에 인허가가 필요한지 판단하는 법
- 플랫폼·중개·공유경제·공간 활용 사업
- 온라인과 오프라인이 결합된 서비스
- 담당 기관과 적용 법령이 여러 개인 사업
- 외국인 창업과 해외기업의 한국 진입
- 법인·비자·인허가의 진행 순서
- 해외 발급서류와 외국어 행정문서
- 보완요구·불허·영업정지 대응

각 콘텐츠는 다음 단계 중 하나를 담당한다.

| 단계 | 질문 | 콘텐츠 역할 | 다음 행동 |
|---|---|---|---|
| 발견 | 대상인가, 인허가가 필요한가 | 기본 범위와 용어 | 저장·관련 글 |
| 판단 | 내 구조에서 가능한가 | 조건·예외·비교 | 프로필·허브 |
| 준비 | 무엇을 어떤 순서로 준비하나 | 서류·절차·대조 | 무료 검토 |
| 결정 | 보완·불허·복합 문제는 어떻게 하나 | 선택지와 검토 경계 | 무료 검토 |

관련성이 없는 글을 수임 업무에 억지로 연결하지 않는다.

## 9. 채널 역할

하나의 검증된 한국어 원문을 사실의 기준으로 삼고 채널별로 다시 편집한다.

| 채널 | 주된 역할 |
|---|---|
| 네이버 블로그 | 검색 질문에 대한 충분한 답과 전환 |
| 홈페이지 한국어 | 자체 도메인의 장기 검색·AI 검색 자산 |
| 홈페이지 영어 | 해외 사업자의 한국 제도 이해와 접수 연결 |
| 카카오채널 | 짧은 판단 기준과 관계 유지 |
| Instagram | 시각적 저장 가치와 프로필 이동 |
| LinkedIn 한국어 | 사업자·실무자 대상 제도 해석 |
| LinkedIn 영어 | 해외기업·외국인 사업자 대상 현지화 설명 |
| 카드뉴스 | 하나의 충돌·비교·검토 과정을 시각화 |
| 숏폼 | 한 문제·한 기준·한 행동 전달 |

채널별 분량과 문체는 최신 채널 지침을 따른다. 사실, 수치, 날짜, 법령, 기관, 결론의 범위는 채널이 달라도 일치해야 한다.

## 10. SNS 최상위 규칙

SNS 원고에는 다음 흐름을 우선한다.

> 구체적인 상황 훅 → 답 → 저장할 기준 → 판단 과정 → 직접 확인 범위/검토 경계 → 무료 검토

- 첫 1~2줄에서 대상과 문제를 식별할 수 있어야 한다.
- 실제로 존재하지 않는 논쟁과 반대 의견을 만들지 않는다.
- 카드뉴스 캡션은 카드 문구를 전부 반복하지 않는다.
- LinkedIn 영어는 직역하지 않고 한국 제도를 짧게 설명한다.
- 이모지·해시태그·감탄사로 전문성을 꾸미지 않는다.
- 후반 영업 문단은 한 번만 둔다.
- 마지막 문장은 자신의 상황에서 가능 여부를 확인하도록 무료 검토를 안내한다.

세부 작성은 「에토스 SNS 마케팅·영업력 강화지침 v1.0」을 적용한다.

## 11. 영업 학습 루프

콘텐츠 성과와 영업 성과를 연결한다.

> 노출 → 조회·완독 → 저장·공유 → 프로필 방문 → 홈페이지 이동 → 무료 검토 요청 → 적합 여부 → 유료 상담 → 수임 → 매출

### 11-1. 공통 식별값

가능하면 콘텐츠마다 `content_id`를 부여한다.

예:

> `2026-10-new-business-platform-01`

같은 소재를 여러 채널에 배포할 때 채널, 언어, 훅 버전을 함께 기록한다. 홈페이지 링크를 사용할 수 있는 외부 영역에서는 일관된 UTM 규칙을 사용한다.

권장 속성:

- content_id
- topic_cluster
- buyer_stage
- channel
- language
- hook_version
- published_at
- source_article

개인정보는 분석 속성에 넣지 않는다.

### 11-2. 무료 검토 분류

무료 검토 요청은 다음처럼 기록한다.

- 적합 문의
- 정보 탐색 단계
- 서비스 범위 밖
- 다른 전문자격 검토 필요
- 자료 부족
- 시기 미정

문의 수만 보지 않는다. 적합 문의율, 유료 상담 전환, 수임, 매출을 함께 본다.

### 11-3. 콘텐츠 피드백

실제 질문에서 반복되는 표현을 익명화해 다음 콘텐츠의 소재와 독자 언어로 활용할 수 있다. 의뢰인의 구체적 사실관계와 개인정보는 콘텐츠 데이터로 사용하지 않는다.

월 1회 다음을 확인한다.

- 어떤 Revenue Cluster가 적합 문의를 만들었는가
- 어떤 Proof of Work가 프로필 방문과 검토 요청을 만들었는가
- 어떤 문의가 서비스 범위 밖이었는가
- 무료 검토에서 반복되는 설명은 무엇인가
- 조회는 높지만 영업 성과가 없는 소재는 무엇인가

### 11-4. 실제 고객 언어 수집

콘텐츠의 독자 문제와 표현은 상상으로 만들지 않고 다음 자료에서 익명화해 수집한다.

- 무료 검토와 상담에서 실제로 받은 질문
- 홈페이지·SNS 댓글과 검색어
- Search Console의 실제 유입 질의
- 문의가 중단된 지점과 반복되는 반론
- 수임 뒤 확인된 최초의 의사결정 계기

개인의 사실관계와 개인정보는 제거한다. 공개 콘텐츠에서 실제 발언을 그대로 인용하려면 별도 동의를 확인하고, 그렇지 않으면 의미가 바뀌지 않는 범위에서 일반화한다.

관찰의 신뢰도는 다음처럼 구분한다.

- 높음: 서로 독립된 실제 자료 3개 이상에서 자발적으로 반복됨
- 중간: 2개 자료에서 확인되거나 질문 후 확인됨
- 낮음: 한 사람 또는 한 자료에서만 관찰됨

낮은 신뢰도의 표현으로 고정된 고객상이나 보편적 요구를 만들지 않는다. 세분시장별 실제 자료가 5개 미만이면 확정적 페르소나 대신 `검증할 가설`로 표시한다.

### 11-5. 수임·미수임 학습

문의 이후 결과는 개인 평가가 아니라 다음의 이유 코드로 기록한다.

- 업무 적합
- 직접 처리 선택
- 비용 또는 범위 불일치
- 시기 미정
- 자료 부족
- 다른 전문가 필요
- 응답 중단
- 기타 확인된 이유

월별로 Revenue Cluster별 적합 문의, 유료 상담, 수임, 미수임 이유를 함께 본다. 상대가 말하지 않은 미수임 이유를 추측해 확정값으로 기록하지 않는다.

## 12. 실험 규칙

한 번에 한 변수만 바꾼다.

- 훅: 질문형 / 결론형
- 첫 정보: 절차 / 위험 경계 / 서류 대조
- Proof of Work: 순서 / 비교 / 체크리스트
- CTA: 입력자료 강조 / 확인 결과 강조
- 형식: 텍스트 / 카드뉴스 / 숏폼

같은 글에서 훅·본문·디자인·CTA를 모두 바꾸면 원인을 판단할 수 없다. 초기 표본이 작을 때 한 번의 결과로 영구 규칙을 만들지 않는다. 에토스 실제 문의·수임 데이터가 쌓이면 외부 벤치마크보다 실제 데이터를 우선한다.

## 13. 무료 검토와 유료 업무의 경계

무료 검토에서 안내할 수 있는 범위:

- 에토스 업무범위에 해당하는지
- 어떤 자료가 필요한지
- 추가 확인이 필요한 핵심 쟁점
- 다음 단계가 무료 검토, 유료 상담, 수임 중 무엇인지
- 견적을 산정하기 위해 필요한 범위

무료 검토에 포함된 것처럼 표현하지 않을 범위:

- 상세 전략 설계
- 완성 서류 작성
- 전체 법률관계 분석
- 결과 예측·보장
- 장시간 상담
- 다른 전문자격사의 독점업무

CTA는 낮은 부담을 강조하되 무료 범위를 넓혀 보이게 하지 않는다.

### 13-1. 무료 검토 접수의 최소 정보

무료 검토는 길게 상담받는 입구가 아니라 업무 적합성과 다음 단계를 확인하는 절차로 설계한다. 필요한 경우 다음 항목만 최소한으로 받는다.

- 하려는 사업·서비스 또는 해결하려는 행정문제
- 현재 단계: 구상, 준비, 신청, 보완, 처분 대응 등
- 신청 주체와 사업 형태
- 현재 확보한 핵심 자료
- 확인된 기한이나 받은 통지의 유무
- 이번 검토에서 알고 싶은 한 가지

처음부터 주민등록번호, 여권 전체 사본, 원본 계약서 등 불필요한 민감자료를 요구하지 않는다. 상세 자료가 필요하면 목적, 범위, 보관·삭제 기준을 안내한 뒤 별도 절차로 받는다.

무료 검토의 1차 결과는 다음 중 하나로 정리한다.

- 에토스 업무범위에 해당하며 다음 자료 확인이 필요함
- 현재 정보만으로 판단하기 어려워 추가 사실이 필요함
- 직접 확인할 수 있는 일반 절차에 해당함
- 유료 상담 또는 정식 업무 범위의 검토가 필요함
- 에토스 범위 밖이거나 다른 전문가의 검토가 우선함
- 기한이 임박해 즉시 공식기관 또는 적절한 전문가 확인이 필요함

### 13-2. 콘텐츠 업그레이드 자료

독자가 바로 쓸 수 있는 자료가 전환에 도움이 될 때만 제공한다. 막연한 전자책보다 한 문제를 짧게 해결하는 모바일 친화 자료를 우선한다.

예시:

- 신사업 인허가 사전점검표
- 해외기업 한국 진입 준비순서표
- 영업정지·과징금 통지 후 확인자료 목록
- 신청서·계약서·사업계획서 간 불일치 점검표

자료는 맞춤 전략이나 완성 서류를 무료로 제공하는 것처럼 만들지 않는다. 내려받기 자체보다 `적합한 무료 검토`, `유료 상담`, `수임`으로 이어진 비율을 본다. 이메일 수집이 꼭 필요하지 않으면 무조건 입력을 요구하지 않는다.

프로젝트 본문의 CTA 규칙은 그대로 지킨다. 본문에 버튼·연락처·카카오톡·텔레그램·이메일 링크를 직접 넣지 않으며, 프로필이나 별도 랜딩페이지를 사용하는 경우에도 과장된 긴급성과 개인정보 과수집을 금지한다.

### 13-3. 반론에 답하는 방식

자주 나오는 반론은 설득 문구가 아니라 판단 지원 자료로 관리한다.

- “제가 직접 할 수 있나요?”
- “어느 기관에 문의해야 하나요?”
- “아직 사업 구상 단계인데 너무 이른가요?”
- “왜 전문가 검토가 필요한가요?”
- “허가 결과를 보장할 수 있나요?”
- “번역만 하면 제출할 수 있나요?”

답변 순서:

1. 질문이 생기는 이유를 인정한다.
2. 결론이 달라지는 조건을 묻거나 밝힌다.
3. 독자가 직접 확인할 기준을 제공한다.
4. 근거와 확인 가능한 작업 범위를 보여준다.
5. 무료 검토, 유료 상담, 직접 처리, 다른 전문가 중 정직한 다음 단계를 제시한다.

불안을 키우거나 허가 가능성을 암시해 반론을 누르지 않는다. 실제 후기나 성과가 없으면 Proof of Work와 공식 근거로 답한다.

### 13-4. 상담·수임 연결

무료 검토 뒤에는 상황에 맞는 한 단계만 제안한다.

`무료 검토 → 필요한 경우 유료 상담 → 업무범위·산출물·비용 확인 → 위임 여부 결정`

유료 단계에서는 무엇을 검토하고 어떤 산출물을 제공하며 무엇이 제외되는지 먼저 밝힌다. 상대가 동의하지 않은 반복 연락과 압박성 마감은 금지한다. 후속 연락이 필요하면 이전 질문에 답하는 정보와 선택 가능한 다음 단계를 중심으로 한 번 명확하게 안내하고, 추가 연락은 상대의 동의와 반응에 따른다.

각 단계에서 고객이 사용한 표현, 핵심 우려, 선택 이유를 익명화해 기록한다. 제안서와 상담 설명은 그 언어를 반영하되 사실을 과장하거나 상대의 공포를 재현하지 않는다.

## 14. 외국어번역행정사 확장

자격 취득과 필요한 사업 신고 전:

- 외국어 원문을 읽고 제도 차이를 설명할 수 있다.
- 국제사업과 해외서류의 제출 절차를 정보 콘텐츠로 다룰 수 있다.
- 현재 제공하는 외국어 상담·자료 검토 범위를 정확히 표시한다.
- 번역확인증명 서비스를 제공 중인 것처럼 쓰지 않는다.

실제 제공 요건을 갖춘 뒤:

- 해외서류 준비
- 번역확인증명
- 공증·아포스티유·영사확인 구분
- 외국인·해외기업의 한국 행정절차

를 기존 신사업 인허가·국제화 Revenue Cluster에 연결할 수 있다.

## 15. 한국어 최종 문체

게시용 한국어는 사실·법률 검토 뒤 마지막에 다듬는다.

- 짧은 문장과 긴 문장을 섞는다.
- 같은 종결어미와 문단 구조를 반복하지 않는다.
- 번역투, 기계적 병렬, 접속사, 형식명사, 광고성 관용구를 줄인다.
- 법률용어, 수치, 날짜, 인용, 기관명, 사건번호는 보존한다.
- 쉬운 표현으로 바꾸다가 법률 의미를 넓히거나 줄이지 않는다.
- 독자를 훈계하거나 실수를 비난하지 않는다.

`humanize-korean`을 사용할 수 있으면 최종 문체 점검에 사용한다. 사용할 수 없으면 같은 기준으로 직접 점검하며, 사용한 것처럼 말하지 않는다.

AI 시대의 전문성이나 사람의 판단 가치를 주제로 삼을 때에는 `guidelines/modules/human-judgment-positioning.md`를 적용한다. AI 사용을 전문성의 증거로 내세우지 않고, 사실관계 파악·문서 정합성·절차 설계·설명·책임과 대응을 Proof of Work로 보여준다.

내부 작업에서 어떤 도구를 사용했는지는 공개 마케팅의 기본 소재로 삼지 않는다. 독자가 AI 활용 여부를 직접 묻거나 공개할 특별한 이유가 없는 한, 도구가 아니라 사람이 확인한 근거·판단·작업 결과만 설명한다.

## 16. 외부 스킬과 도구

작업에 필요한 최소 도구만 사용한다.

권장 순서:

1. 공식 1차 자료 확인
2. `content-strategy`: Revenue Cluster와 발행 순서
3. `social`: 채널별 재가공
4. `copywriting`·`copy-editing`: 명료성·구체성·CTA
5. `humanize-korean`: 한국어 최종 문체
6. 에토스 지침으로 최종 검수

도구가 없으면 지침의 체크리스트로 대체한다. 외부 스킬은 원문에 없는 사실·사례·성과를 만들 수 없다.

## 17. 오픈소스 도입 원칙

도구를 많이 설치한다고 마케팅이 강해지지 않는다. 현재 문제를 해결할 때만 도입한다.

### 지금 사용 가치가 높은 도구

- Vale: 에토스 금지 표현과 문체 규칙을 비차단 경고로 검사
- CSpell: 영문 카드·캡션의 오탈자 후보만 검사
- LanguageTool: 공식 지원 범위가 확인된 영문·아랍어 보조 검사에만 사용하며 한국어 검사기로 사용하지 않음
- markdownlint-cli2: Markdown 구조 검사

자동 수정은 금지한다. 법률용어, 수치, 조문, 인용을 바꾸는 제안은 사람이 검토한다.

### 운영이 늘어나면 검토할 도구

- Umami: 홈페이지 캠페인·전환 측정
- Postiz: 여러 SNS의 예약 발행과 캘린더 관리
- Twenty: 문의·상담·수임 단계를 관리할 CRM
- n8n: 폼·성과 로그·CRM을 연결하는 자동화. n8n은 일반적인 의미의 완전한 오픈소스보다 fair-code에 가깝다는 점을 구분한다.

도입 기준:

- 수동 예약 발행이 반복 업무를 방해할 때 Postiz 검토
- 홈페이지 유입과 무료 검토의 출처를 판단할 수 없을 때 Umami 검토
- 문의 누락이나 후속관리 문제가 생길 때 CRM 검토
- 두 개 이상의 시스템에 같은 정보를 반복 입력할 때 자동화 검토

초기에는 스프레드시트와 일관된 `content_id`만으로도 충분하다. 개인정보·의뢰자료를 외부 서비스에 보내기 전에 저장 위치, 접근권한, 보존기간, 삭제 방법을 확인한다.

---

## 18. 발행·운영 중단 조건

다음 중 하나라도 해당하면 발행이나 자동화를 멈춘다.

- 핵심 법률 결론의 공식 근거를 확인하지 못했다.
- 기준일과 시행 여부가 불분명하다.
- 경험·사례·후기·성과를 창작했다.
- 현재 자격이나 서비스 범위보다 넓게 표시했다.
- 독자가 얻는 답 없이 불안과 CTA만 남는다.
- 무료 검토가 무료 상담·전략 설계·업무 대행처럼 보인다.
- 개인정보나 의뢰자료가 분석·자동화 도구에 불필요하게 전달된다.
- 자동화가 사람의 발행 승인 없이 게시하거나 법률 결론을 바꾼다.

## 19. 완료 검수

### 사실·법률

- [ ] 공식 근거와 기준일을 확인했는가
- [ ] 법령·기관·수치·기한·사건번호가 정확한가
- [ ] 일반 정보를 개별 사건의 확정적 판단처럼 쓰지 않았는가
- [ ] 경험담·사례·후기·성과를 창작하지 않았는가

### 독자 가치

- [ ] 한 사람의 한 질문에 답하는가
- [ ] 답을 초반에 제공하는가
- [ ] 실제로 쓸 수 있는 판단 기준이나 행동이 있는가
- [ ] 읽지 않아도 되는 문장을 덜어냈는가

### 신뢰

- [ ] Authority를 주장보다 판단으로 보여주는가
- [ ] Proof of Work가 구체적인가
- [ ] 직접 확인 범위와 개별 검토 경계를 구분했는가
- [ ] 사회적 증거가 실제 확인 범위를 넘지 않는가
- [ ] 자격·후기·성과 표현을 주장·증거 등록부에서 확인했는가

### 전환

- [ ] Revenue Cluster에서 글의 역할이 분명한가
- [ ] CTA가 받을 자료와 확인 내용을 구체화하는가
- [ ] 영업 문단이 후반에 한 번만 자연스럽게 있는가
- [ ] 마지막 문장이 자신의 상황에서 가능 여부를 확인하도록 무료 검토를 안내하는가

### 운영

- [ ] content_id와 채널·언어·발행일을 기록할 수 있는가
- [ ] 관심 지표와 적합 문의·상담·수임을 구분하는가
- [ ] 개인정보를 분석 속성에 넣지 않았는가
- [ ] 실제 성과에 따라 다음 가설을 하나만 세웠는가
- [ ] 실제 고객 언어와 추정한 고객 언어를 구분했는가
- [ ] 무료 검토의 범위와 다음 단계를 명확히 분류했는가
- [ ] 미수임 이유를 추측하지 않고 확인된 범위에서 기록했는가

---

## 20. 한 줄 원칙

> 정확한 답과 실제 판단 과정을 먼저 제공하고, 직접 처리할 수 있는 범위와 개별 검토의 경계를 정직하게 나눈 뒤, 적합한 독자가 무료 검토로 자연스럽게 이동하도록 설계하고 실제 문의·수임 데이터로 계속 고친다.
