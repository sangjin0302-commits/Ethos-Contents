# 에토스 ChatGPT 프로젝트 콘텐츠·스킬 연계 지침 v1.2

> 2026-10-15 v1.2 — 개선 2단계: 외부 스킬은 필요한 부분만 선택하고 채널 검수를 중복 실행하지 않는다.

이 지침은 에토스의 블로그·SNS·카드뉴스 콘텐츠를 만들 때 프로젝트 자료와 외부 마케팅·윤문 스킬을 연결하기 위한 실행 규칙이다. 사실·법률·윤리 보호를 완화하지 않으며, 채널 명세 밖의 추가 의무와 중복 호출을 만들지 않는다.

## 1. 적용 우선순위

작업에는 다음 순서를 적용한다.

1. 사용자의 현재 요청
2. ChatGPT 프로젝트의 짧은 부트스트랩 지침
3. 저장소의 `MANIFEST.md`
4. MANIFEST가 지정한 core·채널·모듈
5. 이 지침에서 연결하는 외부 스킬과 일반 마케팅 기법

상위 규칙과 하위 규칙이 충돌하면 상위 규칙을 따른다. 외부 스킬은 에토스의 사실성, 브랜드, 법률 검증, 경험담 금지, CTA 원칙을 바꿀 수 없다. 오래된 지침의 문구가 최신 상위 지침과 충돌하면 최신 상위 지침을 적용한다.

## 2. 작업 시작 시 분류

원고를 만들기 전에 내부적으로 결과물, 독자의 막힌 문제, 글의 목적과 필요한 근거를 정한다. 이미 제공된 정보는 다시 묻지 않는다. 요청 유형별 빠른 조회 경로를 따르고, 같은 작업에서 읽은 동일 버전을 다시 읽지 않는다.

- **기본 편집**: 자연 초안 뒤 사실·법률·논리·마케팅을 통합 검토하고 필요한 부분만 윤문한다. 각 관점을 별도 스킬 호출이나 전면 재작성으로 만들지 않는다.
- **집중 검토**: 근거 충돌, 복잡한 조건 연결, 기한·위반차수 계산이나 업무범위 의문이 남으면 해당 쟁점과 영향을 받는 결론만 깊게 확인한다. 실제 오류가 남으면 검토를 이어가되, 문체 점수 때문에 반복하지 않는다.

이는 도구 사용 강도이며 블로그 A·B·C의 근거 확인 경로를 대체하지 않는다. 상세 운용은 `docs/tooling-policy.md`, 편집 순서는 `docs/language-quality-workflow.md`에 있다. 이 요약과 채널 명세로 해결되면 두 파일을 매번 추가 조회하지 않는다.

## 3. 외부 스킬 선택 규칙

아래는 역할별 선택지다. 작업 이름이 맞는다는 이유만으로 외부 스킬을 반드시 실행하지 않는다. 채널 명세로 이미 해결한 검수를 반복하거나 모든 스킬을 한 원고에 적용하지 않는다.

### 콘텐츠 전략

주제 선정, 콘텐츠 기둥, 발행 순서, 콘텐츠 캘린더, Revenue Cluster를 설계하는 작업에서 `content-strategy`를 사용할 수 있다. 단순 원고 수정에는 전략 도구를 추가하지 않는다. 소재와 성과를 판단할 때에는 해당 작업의 글감관리표·공식 근거 조회 규칙을 따른다.

검색형 신규 글은 `docs/topic-discovery.md`의 정보이득 한 문장을 먼저 남긴다. 고객 언어를 분석할 때에는 `customer-research`를 보조로 사용할 수 있지만 실제 문의 원문·개인정보·미공개 실적은 권한 있는 내부 시스템 밖으로 옮기지 않으며 한 건을 일반화하지 않는다. 내부링크·허브 설계에는 `site-architecture`를 참고하되 기존 공개 URL을 우선하고 사이트 구조 변경을 이 저장소에서 구현한 것으로 보지 않는다. 반복 문의를 상담준비 자료로 바꾸는 작업에는 `sales-enablement`를 참고할 수 있으나 승인 원고·공식 근거·서비스 범위를 Source Lock으로 사용한다.

네 스킬의 적용 결과는 각각 `정보이득 / 고객언어 근거 / 허브·스포크 연결안 / 상담준비 자료`다. 고정 발행 비율, 링크 개수 할당량, 가상 고객 인용, 확인되지 않은 ROI·후기·성과는 가져오지 않는다.

### SNS 제작

카카오, LinkedIn, Instagram, Threads, X, 아랍어 SNS, 캐러셀 캡션, 숏폼 대본은 `docs/sns-authoring-spec.md`와 필요한 원문으로 시작한다. 명세만으로 해결되지 않는 채널 재구성에 `social`을 선택할 수 있다. 외부 스킬의 발행 빈도, 해시태그 수, 훅 공식, 분량을 강제하지 않는다.

### 마케팅 문구

새로운 제목·도입·가치제안·CTA의 약한 부분에는 `copywriting`, 기존 원고의 명료성·설득 흐름에는 `copy-editing`을 선택할 수 있다. 기본 경로에서는 독자의 질문, 실제 자료와 수행 업무, 다음 행동을 한 번에 살핀다. 둘을 연이어 실행하거나 외부 스킬의 다중 검토·점수 평가를 그대로 가져오지 않는다. `docs/marketing-checklist.md`는 필요한 절만 참고한다.

### 윤리적 설득과 검색

독자의 의사결정 부담이나 검색 의도를 따로 검토할 필요가 있을 때만 관련 스킬을 선택한다. `docs/ethical-persuasion.md`의 허용 범위를 넘는 허위 희소성·손실 과장·가짜 사회적 증거를 쓰지 않는다. SEO 때문에 기존 제목의 질문과 유용한 도입을 없애거나, 어색한 반복과 미확인 숫자를 만들지 않는다.

### 논리 점검

질문에 답했는지, 근거가 결론을 뒷받침하는지, 주체·조건·예외가 설명 중에 바뀌지 않았는지를 기존 통합 검토에서 살핀다. 별도 사고 정리 도구는 복잡한 쟁점에서 필요할 때만 고려하며, 그 출력으로 공식 근거를 대신하지 않는다. 이 규칙을 이유로 새 MCP 서버나 논리 도구를 설치하지 않는다.

### 한국어 최종 윤문

자연스러움 검수는 유지하되 외부 `humanize-korean` 호출과 문장 변경을 의무화하지 않는다. 이미 읽히는 문장은 그대로 둔다. 사실·법률 검토 후 어색한 부분이 있으면 `vendor/im-not-ai/quick-rules.md`를 그 작업에서 한 번 읽어 직접 적용하거나 사용 가능한 도구의 부분 제안을 활용한다. 수동 윤문과 외부 자동 윤문을 모두 할 필요는 없다.

사실과 결론, 법령명·조문·판례·재결례·기관명, 수치·날짜·기한, 인용·출처, 고유명사·전문용어, 조건·예외, CTA와 무료·유료 범위를 보존한다. 새 주장·사례·비유·성과를 윤문으로 추가하지 않는다. 자동 제안에서 인용문·법조문·코드·고정 서식은 제외한다.

자동 윤문 제안의 기존 변경률 30% 이하와 의미 보호 기준은 유지한다. 기준을 벗어난 제안은 채택하지 않지만, 이 때문에 원고 전체를 폐기하거나 비율을 맞추려고 반복 호출하지 않는다. 필요한 부분을 직접 편집한 뒤 바뀐 문장과 영향을 받는 요약·결론을 다시 확인한다. 검사 코드의 임계값을 바꾸는 규칙이 아니다.

### 스킬을 실행하지 않는 경우

없는 도구를 설치하거나 찾아다니느라 일반 원고 작성을 멈추지 않는다. 실제로 한 검수 방식만 기록한다. 외부 스킬 미사용은 검수 미실행과 다르다.

| 목적 | 기본 방식 | 실제 실행 기록 |
|---|---|---|
| 자연스러움 | 채널 명세로 검수하고, 필요한 윤문에만 실제로 읽은 규칙집 적용 | 카드 단계 값은 `pass`·`pending`만; 수동 검수·부분 윤문·도구 제안 여부는 기존 메모에 구분 |
| 소재·순서 설계 | 그 작업에 필요한 글감관리표와 소재·전략 지침 | 분석을 실제로 요청받은 경우에만 사용한 자료 기록 |
| SNS 재구성 | `docs/sns-authoring-spec.md`와 승인 원문 | 추가 스킬이 필요하지 않으면 별도 실행 없음 |
| 카피 편집 | 질문·직접 답·수행 업무·다음 행동을 함께 점검 | 별도 점수표나 반복 보고서 없음 |

카드 ChatGPT 초안은 하지 않은 윤문을 `pending`으로 남긴다. 실제 검수를 마친 담당자만 해당 단계에 `pass`를 쓴다. `manual-equivalent`나 스킬 이름을 단계 값으로 넣지 않는다. 도구를 사용한 것처럼 보고하지 않으며, 사용자에게 필요한 미확인 사항만 짧게 알린다.

## 4. 사실·법률 검증 게이트

근거 확인은 각 채널의 경로를 따른다. 새로운 법률 주장이나 변경 가능성이 있는 내용은 작성 시점의 공식 1차 자료로 확인한다. 검증된 원고의 수정은 필요한 변경 확인과 원문 대조를 유지하고, 승인 원문을 파생하는 작업은 Source Lock 범위를 지킨다. 같은 근거를 별도 스킬마다 반복 조사하지 않는다.

- 법령은 해당 사안에 적용되는 시행 법령 원문을 확인한다.
- 법령, 행정해석, 판례·재결례, 기관 안내를 서로 구분한다.
- 실제 확인한 기준일과 범위를 표시한다. 날짜만 바꿔 최신이라고 표시하지 않는다.
- 사실로 확인하지 못한 내용은 추정으로 단정하지 않는다.
- 일반 정보를 개별 사안의 확정적 결론처럼 표현하지 않는다.
- 출처가 필요한 문장에는 독자가 확인할 수 있는 출처를 가까이 둔다.
- 인용 검증은 채널 명세의 단계에서 수행한다. 기존 검증이 없거나 인용 오류·변경 의문이 있을 때 필요한 공식 자료를 확인한다. 도구가 없으면 가능한 공식 원문 대조 방식과 확인하지 못한 부분을 기록한다.

공식 근거를 확인할 수 없으면 초안에서는 확인 필요를 표시하거나 문장을 제외한다. 미확인 법률 결론을 남긴 채 발행용 완성본으로 내지 않는다. 마케팅 완성도나 속도를 이유로 근거 없는 내용을 채우지 않는다.

## 5. 신규 전문가 신뢰 형성

경험이 부족한 점을 감추려고 경력, 의뢰 사례, 처리 건수, 고객 반응, 성공 결과를 만들지 않는다. 실제 경험으로 확인되지 않은 1인칭 경험담은 사용하지 않는다.

Authority는 자기소개가 아니라 판단과 수행 과정으로 보여준다.

- 어떤 자료의 어느 항목을 먼저 확인하는지
- 서로 다른 문서가 어디에서 충돌하는지
- 그 결과 무엇을 정리하거나 작성하는지
- 관할 기관에 무엇을 확인하고 어떤 절차를 준비하는지
- 선행 요건과 신청 순서를 어떻게 구분하는지

실제 사례와 가상 예시는 명확히 구분한다. 가상 예시는 설명을 위한 구성임을 밝히고 실제 의뢰나 성공 사례처럼 쓰지 않는다. 제공하지 않는 보고서·보완 대응·처리기간을 구체화라는 이유로 새로 약속하지 않는다.

## 6. 조건부 마케팅 모듈

아래 모듈은 글의 목적에 도움이 될 때만 사용한다. 정해진 횟수를 채우거나 단계별 도구 호출을 늘리기 위해 넣지 않는다.

### Proof of Work

독자가 맡길 일을 이해해야 할 때 실제 자료, 작업 순서, 준비되는 문서와 다음 행동을 연결한다. 서류 작성을 낮춰 말하지 않으며, 실제 의뢰자료나 결과를 꾸며내지 않는다.

### CTA Specificity

독자가 무엇을 보내면 무엇을 우선 확인받는지 구체화한다. 결과 보장, 무료 범위 확대, 긴급성 조작은 금지한다.

### Emerging Social Proof

검증된 후기나 실적이 충분하지 않으면 대신 만들어내지 않는다. 확인 가능한 자격·경력, 공식 자료를 적용하는 과정, 실제로 만든 작업 양식과 체크리스트, 발행 콘텐츠, 실제 운영하는 응답 방식만 근거로 쓴다. 콘텐츠 수나 조회를 수임 성과로 바꾸어 표현하지 않는다.

### Revenue Cluster

시리즈나 전략 설계가 요청된 경우에만 실제 수요와 업무에 근거해 중심 업무와 지원 콘텐츠의 연결을 검토한다. 각 글은 독립적으로 유익해야 하며 관련 없는 글을 억지로 핵심 서비스에 연결하지 않는다.

현재 우선 축은 신사업 인허가, 해외 사업자의 한국 진입, 두 축과 실제로 연결되는 비자·법인·행정심판·계약·행정문서다. 외국어번역행정사 업무는 자격 취득과 사업 신고 등 실제 제공 요건이 갖춰진 뒤 공개 서비스 축으로 추가한다. 그 전에는 외국어 상담·자료 검토와 번역확인증명 업무를 혼동하게 표현하지 않는다.

## 7. 매체별 작성 원칙

### 블로그

`docs/blog-authoring-spec.md`를 먼저 읽고 필요한 원문·근거를 확인한다. 독자의 질문에 직접 답하고, 구체적인 판단 기준과 수행 업무를 쉽게 설명한다. 기존 제목·도입과 8,000~11,000자의 깊이를 유지한다. 이 모듈을 읽었다고 원고 전체의 추가 검수나 전략 설계를 하지 않는다.

### 비블로그 SNS

`docs/sns-authoring-spec.md`와 승인된 블로그 또는 검증된 자료로 시작한다. 채널별로 질문 하나와 필요한 작업을 보여주되 Source Lock 밖의 경험·사례·수치·판례를 추가하지 않는다. 빠른 명세로 해결되지 않는 세부만 추가 조회한다.

### 카드뉴스

필수 읽기는 `docs/card-authoring-spec.md`와 승인 원문이다. ChatGPT는 국문 카피와 디자인 방향 초안을 만들고, 하지 않은 최종 윤문을 `pending`으로 남긴다. 윤문·현지화·렌더·QA는 Codex, 최종 승인은 사람이 맡는다. 카드 선정·디자인·모바일 검사 문서를 초안 작성자에게 일괄 조회시키지 않는다. 승인 세트 보호와 JSON·글자 한도·필수 검사는 유지한다.

## 8. CTA와 전환 원칙

독자가 직접 확인할 부분과 전문가가 실제 자료를 함께 살펴야 할 부분을 해당 문제에 맞게 설명한다. 자료 정리·문서 작성 같은 수행 업무와 허가·처분 변경 같은 외부의 결정은 구분한다.

상담 안내의 유무와 위치는 채널 명세를 따른다. 블로그는 후반 무료 검토 서술 문단 한 번이며 네이버의 기존 상담 이미지 네 개는 한 영역으로 유지한다. 다른 채널에 블로그 이미지·링크 배치나 영업 문단을 그대로 강제하지 않는다. 무료 검토, 유료 상담, 수임 업무의 범위를 혼동하게 표현하지 않는다.

## 9. 최종 검수와 종료

이 절은 별도의 열두 단계 검수가 아니다. 각 채널의 최종 점검에 사실·법률·업무범위, 독자 질문과 답, 수행 업무와 다음 행동, 자연스러운 설명을 함께 적용한다. 블로그의 최종 세 질문과 카드 담당자별 승인 요건은 유지한다.

발견된 오류는 해당 부분과 영향을 받는 결론을 수정하고 의미를 재확인한다. 근거·필수 형식·업무범위 문제가 해결되고 질문에 답하며 실제 작업이 이해되면 편집을 마친다. 문형 비율이나 더 높은 점수 때문에 읽히는 글을 계속 다시 쓰지 않는다.

성과 측정과 새 도구 도입은 별도 작업이다. 원고를 한 편 쓸 때마다 발행 실험이나 지표 보고서를 의무화하지 않는다. 실제 비교에서는 조회·수정·호출 횟수와 시간을 관측한 만큼만 기록하고 개선을 추정하지 않는다. 사용자 요청이 없으면 내부 점수와 장황한 스킬 보고를 원고에 넣지 않는다.

## 10. 핵심 원칙

마케팅 스킬은 독자의 이해와 다음 행동을 돕는 도구일 뿐 사실을 만드는 도구가 아니다. 법률에는 엄격하게, 설명에는 유연하게 적용한다. 기존 제목과 도입을 살리고, 쉬운 예시뿐 아니라 그 사이의 본문도 연결하며, 필요한 작업이 구체적으로 보이면 불필요한 도구 실행과 재작성을 멈춘다.
