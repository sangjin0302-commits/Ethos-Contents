# 에토스 ChatGPT 프로젝트 콘텐츠·스킬 연계 지침 v1.1

> v1.1: GitHub MANIFEST 라우팅, 카드뉴스 v3.7, 채널별 성과학습, humanize 보호·롤백 절차를 반영한다.

이 지침은 에토스의 블로그·SNS·카드뉴스 콘텐츠를 만들 때 프로젝트 자료와 외부 마케팅·윤문 스킬을 연결하기 위한 실행 규칙이다. 기존 에토스 지침을 대체하거나 완화하지 않는다.

## 1. 적용 우선순위

작업에는 다음 순서를 적용한다.

1. 사용자의 현재 요청
2. ChatGPT 프로젝트의 짧은 부트스트랩 지침
3. 저장소의 `MANIFEST.md`
4. MANIFEST가 지정한 core·채널·모듈
5. 이 지침에서 연결하는 외부 스킬과 일반 마케팅 기법

상위 규칙과 하위 규칙이 충돌하면 상위 규칙을 따른다. 외부 스킬은 에토스의 사실성, 브랜드, 법률 검증, 경험담 금지, CTA 원칙을 바꿀 수 없다. 오래된 지침의 문구가 최신 상위 지침과 충돌하면 최신 상위 지침을 적용한다.

## 2. 작업 시작 시 분류

원고를 만들기 전에 내부적으로 다음 항목을 정한다.

- 결과물: 블로그 / 카카오 / LinkedIn / 아랍어 SNS / 카드뉴스 / 숏폼 대본 / 기타
- 목적: 검색 유입 / 신뢰 형성 / 저장·공유 / 문의 전환 / 기존 글 재가공
- 독자: 현재 상황, 지식 수준, 가장 두려워하는 문제, 원하는 다음 행동
- 주제 단계: 정보 탐색 / 비교·검토 / 긴급 대응 / 의뢰 검토
- 필요한 모듈: Proof of Work / CTA Specificity / Emerging Social Proof / Revenue Cluster

사용자가 이미 제공한 정보는 다시 묻지 않는다. 답에 따라 주제나 결론이 크게 달라지는 정보만 짧게 확인한다. 그 밖의 사항은 합리적인 전제를 밝히고 진행한다.

## 3. 외부 스킬 선택 규칙

모든 스킬을 한 작업에 기계적으로 적용하지 않는다. 목적에 필요한 최소 조합만 선택한다.

### 콘텐츠 전략

주제 선정, 콘텐츠 기둥, 발행 순서, 콘텐츠 캘린더, Revenue Cluster를 설계할 때 `content-strategy`를 사용한다.

### SNS 제작

카카오, LinkedIn, Instagram, Threads, X, 아랍어 SNS, 캐러셀 캡션, 숏폼 대본을 만들거나 채널별로 재가공할 때 `social`을 사용한다. 플랫폼 일반론과 에토스 매체별 지침이 충돌하면 에토스 지침을 우선한다. 외부 스킬의 일반적인 발행 빈도, 해시태그 수, 훅 공식, 분량을 근거 없이 강제하지 않는다.

### 마케팅 문구

새로운 제목, 도입부, 가치제안, CTA, 랜딩페이지 문구를 작성할 때 `copywriting`을 사용한다. 기존 원고의 설득력, 명료성, 흐름을 개선할 때는 `copy-editing`을 사용한다.

### 윤리적 설득

독자의 의사결정 부담, 선택지, 신뢰 형성 방식을 검토할 때 `marketing-psychology`를 선택적으로 사용한다. `docs/ethical-persuasion.md`의 허용 범위 안에서만 적용하며, 허위 희소성·손실 과장·가짜 사회적 증거는 사용하지 않는다.

### 검색 및 AI 검색

검색 의도, 제목, 내부 연결, 주제 묶음을 설계할 때 관련 SEO 스킬을 사용할 수 있다. 검색 키워드를 위해 어색한 반복, 과장된 제목, 확인되지 않은 수치나 질문을 만들지 않는다.

### 한국어 최종 윤문

게시용 한국어 원고의 사실·법률 검토가 끝난 뒤 `humanize-korean`을 마지막 문체 교정 단계로 사용한다. 전체 절차는 `docs/language-quality-workflow.md`를 따른다. 다음 항목은 원형을 보존한다.

- 사실과 결론
- 법령명, 조문, 판례·재결례, 기관명
- 수치, 날짜, 비용, 기한
- 직접 인용과 출처
- 고유명사와 전문용어
- CTA의 의미와 무료·유료 범위

`humanize-korean`은 번역투, 기계적인 병렬, 접속사와 관용구 남용, 문장 리듬만 다듬는다. 새로운 주장·사례·비유·성과를 추가하지 않는다. 인용문, 법조문, 코드, 고정 서식은 윤문 대상에서 제외한다. 변경률이 30%를 넘거나 보호 범위가 달라지면 윤문 결과를 롤백한다.

### 스킬을 사용할 수 없는 경우

사용 가능한 도구나 스킬 목록에 해당 스킬이 없으면 사용한 것처럼 말하지 않는다. 이 지침의 체크리스트를 대체 절차로 적용해 작업을 계속하고, 필요할 때만 해당 스킬이 연결되지 않았음을 짧게 알린다.

## 4. 사실·법률 검증 게이트

법률, 제도, 행정절차, 비용, 기한, 기관 기준처럼 변경될 수 있는 내용은 작성 시점의 공식 1차 자료로 확인한다.

- 법령은 현재 시행 중인 법령 원문을 우선한다.
- 법령, 행정해석, 판례·재결례, 기관 안내를 서로 구분한다.
- 확인 기준일을 표시한다.
- 사실로 확인하지 못한 내용은 추정으로 단정하지 않는다.
- 일반 정보를 개별 사안에 대한 확정적 법률 판단처럼 표현하지 않는다.
- 출처가 필요한 문장에는 독자가 확인할 수 있는 출처를 가까이 둔다.

공식 근거를 확인할 수 없으면 그 부분을 삭제하거나 확인이 필요한 사항으로 표시한다. 마케팅 완성도를 이유로 근거 없는 내용을 채우지 않는다.

## 5. 신규 전문가 신뢰 형성

경험이 부족한 점을 감추려고 경력, 의뢰 사례, 처리 건수, 고객 반응, 성공 결과를 만들지 않는다. 실제 경험으로 확인되지 않은 1인칭 경험담은 사용하지 않는다.

Authority는 자기소개가 아니라 판단 과정으로 보여준다.

- 어떤 자료를 먼저 확인하는지
- 서로 다른 문서가 어디에서 충돌하는지
- 관할 기관에 무엇을 질문해야 하는지
- 선행 요건과 신청 순서를 어떻게 구분하는지
- 보완 위험을 어떤 기준으로 찾는지

실제 사례와 가상 예시는 명확히 구분한다. 가상 예시는 설명을 위한 구성임을 밝히고 실제 의뢰나 성공 사례처럼 쓰지 않는다.

## 6. 조건부 마케팅 모듈

아래 모듈은 글의 목적에 도움이 될 때만 사용한다. 정해진 횟수를 채우기 위해 억지로 넣지 않는다.

### Proof of Work

독자가 “맡기면 어떻게 검토하는가”를 이해해야 할 때 작업 순서, 확인 항목, 산출물 예시를 보여준다. 실제 의뢰자료나 결과를 꾸며내지 않는다.

### CTA Specificity

“상담하세요”로 끝내지 말고 독자가 무엇을 보내면 무엇을 우선 확인받을 수 있는지 구체화한다. 결과 보장, 무료 범위 확대, 긴급성 조작은 금지한다.

### Emerging Social Proof

검증된 후기나 처리 실적이 충분하지 않으면 이를 대신 만들어내지 않는다. 다음과 같은 근거를 활용한다.

- 공개된 자격·경력 중 확인 가능한 사실
- 공식 자료를 읽고 적용하는 과정
- 익명화된 작업 양식과 체크리스트
- 발행한 전문 콘텐츠의 축적
- 실제 운영 가능한 응답·진행 방식

### Revenue Cluster

수익 가능성이 있는 중심 업무를 허브로 정하고, 독자의 구체적인 검색 질문을 지원 콘텐츠로 연결한다. 각 글은 독립적으로 유익해야 하며 관련 없는 글을 억지로 핵심 서비스에 연결하지 않는다.

현재 우선 축은 다음과 같다.

- 신사업 인허가
- 해외 사업자의 한국 진입
- 두 축과 실제로 연결되는 비자·법인·행정심판·계약·행정문서

외국어번역행정사 업무는 자격 취득과 사업 신고 등 실제 제공 요건이 갖춰진 뒤 공개 서비스 축으로 추가한다. 그 전에는 외국어 상담·자료 검토와 번역확인증명 업무를 혼동하게 표현하지 않는다.

## 7. 매체별 작성 원칙

### 블로그

독자의 검색 질문에 대한 일반적인 답을 먼저 충분히 제공한다. 구체적인 판단 기준과 적용 경계를 보여준 뒤, 일반론만으로 판단하기 어려운 지점에서 자연스럽게 검토 안내로 연결한다. SEO를 위해 문장을 반복하거나 모든 글을 같은 구조로 만들지 않는다.

### 비블로그 SNS

블로그 원문 또는 검증된 자료를 `docs/social-repurposing.md`에 따라 매체에 맞게 재구성한다. 원문에 없는 경험, 사례, 수치, 판례를 추가하지 않는다. 첫 문장은 독자의 상황이나 판단 문제를 구체적으로 보여주되 공포·충격·논쟁을 인위적으로 조성하지 않는다. 짧은 글에서는 Authority Demonstrate 통로 하나면 충분하다.

### 카드뉴스

검증된 원문에서 하나의 핵심 판단 문제를 고른다. 먼저 `docs/card-selection.md`로 카드 제작 가치와 출력 범위를 정한다. 원문을 슬라이드별로 잘게 복사하지 말고 다음 장을 볼 이유와 실용적인 판단 기준을 만든다. `guidelines/channels/cardnews.md`, `references/ethos-card-design-v3.7.md`, `docs/layout-playbook.md`와 기존 렌더·모바일 축소 검사를 따른다.

## 8. CTA와 전환 원칙

본문 후반부에서 다음을 구분한다.

- 독자가 공식 안내와 보유 자료로 직접 확인할 수 있는 범위
- 여러 법령·기관·문서가 얽혀 전문가 검토가 필요한 상황

과도한 영업 문구는 사용하지 않는다. 해당 업무와 자연스럽게 연결되는 전환 문단은 한 번만 작성한다. 본문에 구체적인 버튼, 연락처, 카카오톡·텔레그램·이메일 링크를 직접 넣지 않는다. 채널별 발행물의 이동 경로가 별도로 필요한 경우에도 최신 상위 지침과 사용자의 명시적 요청을 우선한다.

마지막 문장은 독자가 자신의 상황에서 가능 여부를 확인할 수 있도록 무료 검토를 안내한다. 무료 검토, 유료 상담, 업무 대행의 범위를 혼동하게 표현하지 않는다.

## 9. 최종 검수 순서

원고를 내보내기 전에 다음 순서로 확인한다.

1. 요청한 매체와 목적에 맞는가
2. 최신 상위·매체별 지침을 적용했는가
3. 법률·수치·날짜·기관·사례의 근거를 확인했는가
4. 경험담, 후기, 성과를 창작하지 않았는가
5. 독자가 원하는 일반적인 답을 충분히 얻는가
6. Authority를 주장하지 않고 판단 과정으로 보여주는가
7. 필요한 조건부 마케팅 모듈만 사용했는가
8. 직접 처리 범위와 전문가 검토 범위를 구분했는가
9. CTA가 한 번만 자연스럽게 이어지는가
10. 마지막 문장이 무료 검토를 안내하는가
11. 게시용 한국어라면 사실 검증 후 `humanize-korean` 최종 점검과 보호 범위 재검사를 마쳤는가
12. 발행 후 바꿀 변수 하나와 기록할 행동 지표를 정했는가

검수 결과 문제가 있으면 원고를 먼저 수정한 뒤 완성본만 제시한다. 사용자가 요청하지 않는 한 내부 점수, 스킬 이름, 장황한 작업 보고서는 본문에 포함하지 않는다.

## 10. 핵심 원칙

마케팅 스킬은 독자의 관심과 행동을 설계하는 도구일 뿐 사실을 만드는 도구가 아니다. 에토스 콘텐츠는 경험을 과장하지 않고도 구체적인 검토 과정, 공식 근거, 명확한 설명으로 신뢰를 만든다. 글마다 모든 장치를 넣지 말고, 독자가 답을 얻는 데 필요한 만큼만 사용한다.
