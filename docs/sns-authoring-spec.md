# 비블로그 SNS 작성 명세 (ChatGPT 한 장 요약)

카카오채널·LinkedIn·Instagram 캡션·Threads·X·숏폼을 요청받으면 이 문서를 먼저 읽는다. `guidelines/channels/sns.md`(v3.1)와 상위 지침을 요약한 작업 순서일 뿐 대체하지 않는다. 충돌하면 sns.md와 상위 지침이 이긴다.


> **법률·사실의 의미를 지키면서 자연스럽게 쓴다.** 답은 독자의 일상·업무 상황에서 시작하되, 근거 없는 사실·성과·후기나 가상 상담 장면을 만들지 않는다. 원문의 숫자·조문·조건·한정어, 행정사 업무범위, 무료 검토 경계, 연락처·링크 배치 같은 Hard Gate를 우선한다. 그 밖의 문장 틀과 사례 배치·마케팅 표현은 초안을 막는 체크리스트가 아니라 자연스러울 때 쓰는 권고다.

## 먼저 볼 예시

말투는 규칙보다 `examples/writing/README.md`의 "고치기 전 → 고친 후" 예시로 잡는다. 윤문 단계에서 이 예시처럼 몇 군데만 고친다.

## 읽을 파일 (기본 빠른 경로)

- **일반 비블로그 SNS 작성**: `docs/sns-authoring-spec.md` 한 파일을 먼저 읽는다. 이미 승인된 블로그를 파생하는 작업이면 해당 블로그 원문을 Source Lock으로 함께 읽는다.
- **독립된 신규 SNS 법률 소재**: 승인 원문이 없으면 Source Brief(독자·질문·답·공식 근거·한정어)를 먼저 만들고, 그 소재에 필요한 공식 1차 자료만 확인한다.
- **추가 조회는 필요한 경우만**: 채널별 출력 충돌·세부 형식이 명세로 해결되지 않을 때에만 `MANIFEST.md` 및 `guidelines/channels/sns.md`의 해당 부분을 조회한다. 소재 선정은 별도 작업이므로 그때 글감관리표·소재 발굴 기준을 적용한다. 윤문이 막힐 때에는 `examples/writing/README.md` 해당 예시만 참고한다.
- `guidelines/core/`, `docs/topic-discovery.md`, `docs/legal-verification.md`, 마케팅 모듈 전체를 **매 SNS 작성 전에 일괄 읽지 않는다**. 현행 프로젝트의 빠른 조회 규칙을 우선하며, 상위 지침의 법률·윤리 보호 원칙은 그대로 적용한다.

조회하지 못한 필수 원문이 있으면 사용자에게 밝힌다. 구버전 사본으로 대신하거나 Source Lock 내용을 추측하지 않는다.

## 작성 순서

1. 내부 메모(노출 금지): 독자, 질문, 직접 답, 근거, 경계, Primary Objective **하나**(발견·이해·저장·공유·신뢰·프로필 확인·무료 검토), 행동 하나.
2. 질문이 둘 이상이면 게시물을 나눈다.
3. 자연 초안 → 사실·법률 → 마케팅 → 금지 표현 → 윤문 → 의미 재검증(`docs/language-quality-workflow.md`).
4. 블로그를 줄일 때 조건·예외·한정어를 지우지 않는다. 지워야 하면 게시물을 나눈다.
5. 영어·아랍어는 한국어 직역이 아니라 해당 독자 기준으로 다시 쓰고, 사실·숫자·한정어를 대조한다.

## 구조

> 훅(대상+판단 문제) → 직접 답 → 근거·구분 기준·확인 순서 → 적용할 행동 → 직접 확인 범위/전문가 검토 경계 → (필요할 때) 무료 검토 안내 한 번

짧은 게시물은 질문 하나 → 답 하나 → 주의점 하나 → 다음 행동이면 충분하다.

초안 전 역할은 **Traffic·Authority·Revenue 중 하나**만 고른다. 같은 원문도 채널의 의사결정 방식에 맞춰 다시 구성한다.

- LinkedIn 의사결정형: 기업 상황 → 예상 밖의 결론 → 판단 기준 2~4개 → 업무상 의미 → 근거
- LinkedIn 업무과정형: 흔한 불일치 → 확인 순서 → 문서·부서 → 놓치기 쉬운 지점
- LinkedIn 제도변경형: 변경점 → 영향받는 기업 → 실무 영향 → 이번 주 확인사항 → 공식 근거
- Instagram·카드: 판단 문제 하나 → 기준 하나 → 비교·순서·체크리스트 시각화 → 경계
- 카카오: 상황 → 직접 답 → 주의점 → 다음 확인 행동
- Threads·X: 구분 또는 관찰 → 짧은 근거 → 적용 질문

LinkedIn에 블로그 요약문을 그대로 붙이지 않는다. B2B 독자가 내부 결정을 내릴 수 있도록 운영 영향과 확인 순서로 다시 쓴다. 시리즈·채널 연결을 설계할 때만 `docs/content-architecture-system.md`를 읽는다.

## 독자 이해를 위한 채널별 설명법 (Soft Guide)

- **카카오톡 채널**: 상대가 바로 받았을 고지서, 계약서, 회사 요청 같은 구체 질문 한 가지에서 출발한다. 첫부분에서 직접 답하고 확인할 항목·기한 중 핵심만 남긴다. 확인되지 않은 위기감이나 가상 상담 대화는 쓰지 않는다.
- **LinkedIn**: 직원의 직무 변경, 기업의 문서 불일치, 기관 제출 순서처럼 의사결정자의 일상적인 업무 장면을 선택한다. '왜 회사가 이 기준을 먼저 확인해야 하는지'를 밝히되 실제 원문에 없는 비용·위험·결과를 만들어내지 않는다.
- **Instagram 캡션**: 카드를 한 번 더 서술하지 않고 어떤 독자 상황에서 쓸 판단 기준인지 짧게 설명한다. 꼭 필요한 법률 한정과 독자 행동을 보충한다. 카드 본문 카피는 `docs/card-authoring-spec.md`가 정본이다.
- **Threads·X**: 낯선 제도 설명보다 사람들이 헷갈리는 한 가지 구분 또는 질문을 앞에 놓는다. 답을 먼저 쓰고 설명에 필수적인 실제 조건을 남긴다. 짧은 형식 때문에 조건을 지워야 하면 나누거나 원문으로 연결한다.
- **영문·아랍어**: 한국어의 비유나 생활 장면을 그대로 직역하지 않는다. 한국에 진입하는 해외기업, 외국인 창업자, 외국인 고용 담당자가 이해할 업무 문맥으로 재구성하되 근거·주체·조건·한정어·공식 명칭을 보존한다.

승인된 블로그의 파생 콘텐츠에서는 **표현과 설명의 길이만 재구성**한다. 블로그에 없는 법률상 사실, 새로운 조건을 가진 가상의 사건, 상담 경험이나 결과를 추가하지 않는다. 이해를 돕는 비교가 원문에 없으면 먼저 원문 근거를 보강·승인받거나 비교를 생략한다.

## LinkedIn 복사·붙여넣기 출력 규칙 (2026-10-15 보강)

- LinkedIn 피드용 게시문은 **전체를 한 개의 `text` 코드 블록**으로 출력한다. Markdown 강조나 서식 있는 글쓰기 블록을 기본 전달 수단으로 쓰지 않는다.
- 실제 연속 개행 두 번으로 문단 사이에 빈 줄을 넣고, 제목과 목록 항목을 실개행으로 구분한다. 화면에서 자동 감긴 줄은 개행이 아니다.
- 게시문 본문에 `**`, `__`, `###`, `>`, `[문구](URL)` 같은 마크다운 구문을 남기지 않는다. 강조는 짧은 일반 문장과 빈 줄로 해결한다.
- 기업의 판단 문제 하나에 직접 답하고 핵심 기준과 실행 순서를 제시한다. 블로그를 장황하게 축약하지 않으며 원문 사실·숫자·법률 한정어는 보존한다.
- 링크·추적 링크는 게시문 밖 첫 댓글 등 채널 배치에 둔다. CTA는 마지막 한 번. 발행 전 실제 빈 줄·서식 기호·목록 개행을 검사하며 플랫폼에서 확인하지 않은 결과는 보장하지 않는다.

## 고정 규칙 요약

- 영문에서 행정사는 항상 **Administrative Attorney**(사무소는 Administrative Attorney Office). 다른 번역(administrative agent, scrivener 등)을 쓰지 않는다. 소송·분쟁 대리를 암시하는 문장과 함께 쓰지 않는다.

- 훅 금지: 공포·긴박감, 결과·승인 보장, 확인하지 않은 숫자, "모르면 손해"류, 창작한 1인칭 경험, 경력 나열로 시작.
- 답을 감춰 체류시간을 늘리지 않는다.
- 후기·실적이 없으면 만들지 않는다. 조회·저장을 만족·수임·전문성의 증거로 확대하지 않는다.
- 본문에 연락처·버튼·카카오톡·텔레그램·이메일 링크를 넣지 않는다. CTA는 한 번, 무료 검토 범위를 넘기지 않는다.
- 비상주 사무소를 실제 상주 사무실·조직처럼 연출하지 않는다. 실제 의뢰·상담 장면을 창작하지 않는다.
- 캡션 첫 부분에 대상 독자를 자연스럽게 밝힌다. 카드 내용을 그대로 반복하지 않고 맥락·경계·다음 행동을 보완한다.

## 자가 점검표

- [ ] Primary Objective가 하나이고 게시물이 그것만 요구한다
- [ ] CTA 문장을 지워도 저장·공유할 만한 기준이 남는다 (**먼저 주기 테스트**)
- [ ] 첫 줄만 읽어도 대상과 판단 문제가 보이고, 독자가 무엇을 확인할지 알 수 있다
- [ ] LinkedIn 발행용은 `text` 코드 블록, 실제 빈 줄, 일반 텍스트 목록, 마크다운 구문 없음
- [ ] 법률·제도 문장에 확인 기준일과 근거가 있고 U가 없다
- [ ] 숫자·조문·날짜·한정어가 원문과 같다
- [ ] 경험 창작·과장·공포·직접 연락 유도·채널 부적합 표현이 없다
- [ ] 윤문과 의미 재검증을 마쳤다 (영문·아랍어는 별도 현지화 검수)
- [ ] 확인하지 못한 항목을 사용자에게 알렸다
