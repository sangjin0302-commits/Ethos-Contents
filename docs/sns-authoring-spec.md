# 비블로그 SNS 작성 명세 (ChatGPT 한 장 요약)

카카오채널·LinkedIn·Instagram 캡션·Threads·X·숏폼을 요청받으면 이 문서를 먼저 읽는다. `guidelines/channels/sns.md`(v3.1)와 상위 지침을 요약한 작업 순서일 뿐 대체하지 않는다. 충돌하면 sns.md와 상위 지침이 이긴다.


> **법률·사실의 의미를 지키면서 자연스럽게 쓴다.** 답은 독자의 일상·업무 상황에서 시작하되, 근거 없는 사실·성과·후기나 실제 상담인 것처럼 꾸민 장면을 만들지 않는다. 문맥에서 예시임이 드러나는 이름과 짧은 대화는 허용한다. 원문의 숫자·조문·조건·한정어, 행정사 업무범위, 무료 검토 경계, 연락처·링크 배치 같은 Hard Gate를 우선한다. 그 밖의 문장 틀과 사례 배치·마케팅 표현은 초안을 막는 체크리스트가 아니라 자연스러울 때 쓰는 권고다.

**게시용 파일 우선**: 완성된 국·영·아랍어 SNS 게시글은 원칙적으로 채널·언어별 `.txt` 다운로드 파일로 전달한다. 문단 사이 실제 빈 줄, LinkedIn 일반 텍스트 형식, 해시태그, 아랍어 RTL을 유지한다. 채팅에는 파일 링크와 짧은 안내만 둔다. 짧은 제목 후보·한 줄 카피·즉답은 채팅으로 충분하다. 사용자가 “그대로 채팅에 출력”이나 코드블록 출력을 직접 요청하면 그 형식을 우선한다. 파일을 실제로 만들지 못한 경우 링크를 지어내지 않는다. 기존 아래의 LinkedIn 코드블록 규칙은 채팅에서 본문을 직접 출력할 때 적용하며, 파일 전달이 기본이다.

## 먼저 볼 예시

말투는 규칙보다 `examples/writing/README.md`의 "고치기 전 → 고친 후" 예시로 잡는다. 윤문 단계에서 이 예시처럼 몇 군데만 고친다.

## 읽을 파일 (기본 빠른 경로)

- **일반 비블로그 SNS 작성**: `docs/sns-authoring-spec.md` 한 파일을 먼저 읽는다. 이미 승인된 블로그를 파생하는 작업이면 해당 블로그 원문을 Source Lock으로 함께 읽는다.
- **독립된 신규 SNS 법률 소재**: 승인 원문이 없으면 Source Brief(독자·질문·답·공식 근거·한정어)를 먼저 만들고, 그 소재에 필요한 공식 1차 자료만 확인한다.
- **추가 조회는 필요한 경우만**: 채널별 출력 충돌·세부 형식이 명세로 해결되지 않을 때에만 `MANIFEST.md` 및 `guidelines/channels/sns.md`의 해당 부분을 조회한다. 소재 선정은 별도 작업이므로 그때 글감관리표·소재 발굴 기준을 적용한다. 윤문이 막힐 때에는 `examples/writing/README.md` 해당 예시만 참고한다.
- `guidelines/core/`, `docs/topic-discovery.md`, `docs/legal-verification.md`, 마케팅 모듈 전체를 **매 SNS 작성 전에 일괄 읽지 않는다**. 현행 프로젝트의 빠른 조회 규칙을 우선하며, 상위 지침의 법률·윤리 보호 원칙은 그대로 적용한다.

조회하지 못한 필수 원문이 있으면 사용자에게 밝힌다. 구버전 사본으로 대신하거나 Source Lock 내용을 추측하지 않는다.

## 작성 순서

초안 전에 중심 질문을 정하고 기존 `research/`와 승인 원문을 재사용해 판결·재결·공식 질의회신·통계·보도·행정자료 등 실제 근거를 살핀다. 질문에 적합한 근거를 설명의 중심에 두며 자료 종류별 의무 개수나 없는 근거를 억지로 채우는 규칙은 없다. 새 조사가 필요하면 공통 정본 `docs/brand-philosophy.md`와 근거 확인 기준 `docs/evidence-gate.md`를 따른다. 적합한 사건자료가 없으면 검증된 법령·공식 안내로 설명한다. 실제 사건에 원문 밖 대화·감정·피해액·결과를 더하지 않는다. 새 근거·장면은 원문 또는 신규 Source Brief를 보강·검증·승인한 뒤 사용한다.

1. 내부 메모(노출 금지): 독자, 질문, 직접 답, 근거, 경계, Primary Objective **하나**(발견·이해·저장·공유·신뢰·프로필 확인·무료 검토), 행동 하나.
2. 질문이 둘 이상이면 게시물을 나눈다.
3. 자연 초안 → 사실·법률 → 마케팅 → 금지 표현 → 윤문 → 의미 재검증(`docs/language-quality-workflow.md`).
4. 블로그를 줄일 때 조건·예외·한정어를 지우지 않는다. 지워야 하면 게시물을 나눈다.
5. 영어·아랍어는 한국어 직역이 아니라 해당 독자 기준으로 다시 쓰고, 사실·숫자·한정어를 대조한다.

## 구조

> 훅(대상+판단 문제) → 직접 답 → 근거·구분 기준·확인 순서 → 적용할 행동 → 직접 확인 범위/전문가 검토 경계 → (필요할 때) 무료 검토 안내 한 번

위 구조는 선택 가능한 전개 예시이며 필수 문장 틀이 아니다. 기본은 사람들이 헷갈리는 이유를 풀어 법률을 이해하고 자기 문제와 맡길 일을 판단하게 하는 칼럼형 설명이다. 자료 받기→작성→제출이나 장면→조문→CTA를 모든 글에 강제하지 않는다. 짧은 게시물은 질문 하나 → 답 하나 → 주의점 하나 → 다음 행동이면 충분하며 별도 3줄 요약을 추가하지 않는다. 사용자가 매뉴얼·절차서를 요청한 경우 그 형식을 우선한다.

초안 전 역할은 **Traffic·Authority·Revenue 중 하나**만 고른다. 같은 원문도 채널의 의사결정 방식에 맞춰 다시 구성한다.

- LinkedIn 의사결정형: 기업 상황 → 예상 밖의 결론 → 판단 기준 2~4개 → 업무상 의미 → 근거
- LinkedIn 업무과정형: 흔한 불일치 → 확인 순서 → 문서·부서 → 놓치기 쉬운 지점
- LinkedIn 제도변경형: 변경점 → 영향받는 기업 → 실무 영향 → 이번 주 확인사항 → 공식 근거
- Instagram·카드: 판단 문제 하나 → 기준 하나 → 비교·순서·체크리스트 시각화 → 경계
- 카카오: 상황 → 직접 답 → 주의점 → 다음 확인 행동
- Threads·X: 구분 또는 관찰 → 짧은 근거 → 적용 질문

LinkedIn에 블로그 요약문을 그대로 붙이지 않는다. B2B 독자가 내부 결정을 내릴 수 있도록 운영 영향과 확인 순서로 다시 쓴다. 시리즈·채널 연결을 설계할 때만 `docs/content-architecture-system.md`를 읽는다.

## 쉬운 설명으로 맡길 일을 보여주기 (2026-10-15 보강, Soft Guide)

공통 철학은 `docs/brand-philosophy.md`이다. 아래 요약으로 작성하며 매번 정본을 추가 조회하지 않는다. 문제 해결형 전문성은 구호가 아니라 **독자가 품은 생각과 의문을 풀면서 법률 근거·조건 차이·자기 적용·실제 맡길 업무**를 연결해 보여준다. 필요한 절차·비용·기한은 보조 정보로 남긴다.

- 새 글·후속편·새 시리즈·수정본과 모든 파생 콘텐츠에 이야기·법률 전문성·전환성을 함께 적용한다. Traffic·Authority·Revenue는 주된 역할이며 다른 두 요소를 생략하는 구분이 아니다. 정보 글도 실제 의뢰 판단을 후속 영업 글에 전부 미루지 않되 모든 문장에 상담 권유를 넣지 않는다. 숏폼은 대본·자막 전체에서 연결한다.
- '신청서와 증명서의 이름이 다르다면?'처럼 조건문으로 예시임을 드러낸다. 본문·캡션·자막에 '설명을 위한 가상 상황입니다', '가상의 사례입니다', '실제 상담 사례가 아닙니다' 같은 독립 안내문을 붙이지 않는다. 민수·지연·준호 등 다양한 예시 이름과 인물 간 짧은 대화를 허용한다. 서로 다른 생각·오해·여건을 보여 줄 때 쓰며 이름·대화를 의무화하거나 같은 설명에 이름만 바꾸지 않는다. 조건문 외에도 「예를 들어 민수 씨와 지연 씨가 같은 양식을 본다면」처럼 문맥에서 예시임을 드러낼 수 있다. 허구를 에토스의 실제 고객·상담·수임·후기·성과로 주장하거나 공무원·판사·기관의 말을 창작하는 것은 금지한다. 대사 속 오해는 인접한 설명에서 풀고 법률 결론은 공식 근거에 맞춘다. 대사는 법률 근거가 아니다. 생활 장면을 새 법률 결론의 근거로 쓰지 않는다.
- 독자가 묻는 문제에 먼저 답한다. 제목의 질문과 원문의 유용한 장면을 보존하며, 실제 기한 안내나 상담 권유로 직접 답을 대신하지 않는다. 검색어를 넣으려고 질문의 뜻을 바꾸지 않는다.
- '검토·지원·대응합니다'만 반복하지 않는다. 원문에 있는 자료의 어느 항목을 맞추고 무엇을 정리하는지 설명한다. LinkedIn은 담당자가 준비할 자료와 업무 순서, 카카오는 지금 받은 서류의 확인 항목, Threads·X는 혼동 하나와 그 답에 집중한다. 짧은 글에 전체 업무과정을 억지로 담지 않는다.
- 사람에게 설명하듯 문장을 잇는다. 예시 다음에는 왜 그 차이가 중요한지 풀어 쓰고, 문장마다 '확인하세요'로 끝내거나 명사를 나열한 메모로 압축하지 않는다. 전문용어는 뜻을 붙여 남기고 의무·재량·예외의 강도를 바꾸지 않는다.
- **짧고 자연스러운 문장으로 쓴다.** 카카오·LinkedIn·Instagram 캡션·Threads·X·숏폼의 국문 문장은 한 번에 한 가지 생각을 설명하고, 누가 무엇을 하는지 쉬운 동사로 말한다. '정하는 일이 여기에 연결됩니다', '이러한 차이가 나타납니다'처럼 실제 의미가 없는 연결말은 지우고 필요한 행동·이유를 바로 쓴다. 낯선 용어는 쉬운 뜻을 붙인다. 짧은 게시물을 문장마다 줄바꿈하는 메모로 만들거나 숫자·조건·예외를 생략하지 않는다. 영문·아랍어도 한국어 문장 틀을 직역하지 말고 해당 언어권 독자가 실제 쓰는 자연스러운 표현으로 바꾸되 법률 의미는 동일하게 유지한다. 이 원칙은 별도 전면 재작성·추가 검수 단계를 만들지 않고 기존 윤문에서 적용한다.
- 전문직을 모르는 독자도 무엇을 맡길 수 있는지 알게 하되, 원문과 승인된 서비스 범위에 없는 보고서·보완 대응·처리기한을 새로 약속하지 않는다. 수행 업무와 허가·처분 변경 등 외부의 결정은 구분한다. 서류 작성 자체를 낮춰 말하지 않는다.
- 마지막 안내가 필요한 글에서만 실제 보낼 자료와 무료로 받을 안내를 독자의 말로 쓴다. 본문에 근거 없는 '자료 없이도 가능', '즉시 회신', '무료 작성'으로 접수 부담을 낮추지 않는다. 채널별 링크 배치와 후반 CTA 한 번은 유지한다.
- 작성 시점의 공식 근거를 확인하고 파생물은 Source Lock을 지킨다. 국문·영문·아랍어에서 주체·대상·의무·재량·조건·예외·기간·숫자·출처와 '또는', '이하', '수 있다'의 의미를 대조한다. 짧게 쓰기 위해 핵심 조건을 원문 링크에만 떠넘기지 않는다. 뜻을 붙인 법정 용어와 수수료·기한·필수서류 목록은 찾기 쉽게 남긴다.
- 실제 제공 범위에 근거가 있는 작성·제출 작업과 독자가 직접 할 일을 보여주고, 무료 사전 검토에서 먼저 확인할 내용과 유료 작업을 구분한다. 내용은 이해했지만 직접 작성할 시간이나 여력이 없는 독자도 맡길 일을 판단하게 한다. 자료가 모두 완성돼야 문의할 수 있는 것처럼 쓰지 않되 현재 보유한 자료로 확인할 범위를 한정한다. 미확인 보고서·처리기한·등록 성공·보완 대행을 새로 약속하지 않는다. 승인된 서비스 범위에 없는 작업은 원문 보강사항으로 남겨 확인·승인을 받는다.

실제 수임범위와 원문에 근거가 있는 경우의 표현 예: '문서 정합성을 검토합니다'보다 '계약서와 신청서의 날짜가 같은지 맞춰 보고, 서로 다른 부분을 정리합니다.' 이 예문은 모든 업무의 서비스 약속이 아니다. 이 절은 새로운 분량·사례 수·어미 비율·점수 기준이나 추가 검수 패스를 만들지 않는다.

## 독자 이해를 위한 채널별 설명법 (Soft Guide)

- **카카오톡 채널**: 상대가 바로 받았을 고지서, 계약서, 회사 요청 같은 구체 질문 한 가지에서 출발한다. 첫부분에서 직접 답하고 확인할 항목·기한 중 핵심만 남긴다. 확인되지 않은 위기감이나 실제 상담인 것처럼 꾸민 대화는 쓰지 않는다. 승인 원문의 예시 대화로 독자의 오해를 드러낼 수 있다.
- **LinkedIn**: 직원의 직무 변경, 기업의 문서 불일치, 기관 제출 순서처럼 의사결정자의 일상적인 업무 장면을 선택한다. '왜 회사가 이 기준을 먼저 확인해야 하는지'를 밝히되 실제 원문에 없는 비용·위험·결과를 만들어내지 않는다.
- **Instagram 캡션**: 카드를 한 번 더 서술하지 않고 어떤 독자 상황에서 쓸 판단 기준인지 짧게 설명한다. 꼭 필요한 법률 한정과 독자 행동을 보충한다. 카드 본문 카피는 `docs/card-authoring-spec.md`가 정본이다.
- **Threads·X**: 낯선 제도 설명보다 사람들이 헷갈리는 한 가지 구분 또는 질문을 앞에 놓는다. 답을 먼저 쓰고 설명에 필수적인 실제 조건을 남긴다. 짧은 형식 때문에 조건을 지워야 하면 나누거나 원문으로 연결한다.
- **숏폼 대본·자막**: 받은 자료나 막힌 일 한 가지에서 직접 답, 조건 비교, 다음 행동으로 장면을 잇는다. 대본·자막 전체에서 실제 맡길 작업을 이해할 수 있게 하며, 핵심 법률 조건은 영상 안에도 남긴다. 속도나 자막 길이를 맞추려고 조건·예외를 삭제하거나 실제 상담인 것처럼 꾸민 대화를 넣지 않는다. 승인 원문의 예시 인물·대화는 사용할 수 있다. 기존 채널 분량·CTA·링크 배치를 따른다.
- **영문·아랍어**: 한국어의 비유나 생활 장면을 그대로 직역하지 않는다. 한국에 진입하는 해외기업, 외국인 창업자, 외국인 고용 담당자가 이해할 업무 문맥으로 재구성하되 근거·주체·조건·한정어·공식 명칭을 보존한다.

승인된 블로그의 파생 콘텐츠에서는 **표현과 설명의 길이만 재구성**한다. 블로그에 없는 법률상 사실, 새로운 조건을 가진 가상의 사건, 상담 경험이나 결과를 추가하지 않는다. 새 인물·대화·장면·비교가 필요하면 먼저 원문 초안에 보강하고 사실·법률을 검증하여 승인받은 뒤 사용하거나 해당 예시를 생략한다. 신규 SNS의 Source Brief도 같은 검증·승인 범위로 관리한다.

## LinkedIn 복사·붙여넣기 출력 규칙 (2026-10-15 보강)

- LinkedIn 피드용 게시문은 **전체를 한 개의 `text` 코드 블록**으로 출력한다. Markdown 강조나 서식 있는 글쓰기 블록을 기본 전달 수단으로 쓰지 않는다.
- 실제 연속 개행 두 번으로 문단 사이에 빈 줄을 넣고, 제목과 목록 항목을 실개행으로 구분한다. 화면에서 자동 감긴 줄은 개행이 아니다.
- 게시문 본문에 `**`, `__`, `###`, `>`, `[문구](URL)` 같은 마크다운 구문을 남기지 않는다. 강조는 짧은 일반 문장과 빈 줄로 해결한다.
- 기업의 판단 문제 하나에 직접 답하고 핵심 기준과 실행 순서를 제시한다. 블로그를 장황하게 축약하지 않으며 원문 사실·숫자·법률 한정어는 보존한다.
- 링크·추적 링크는 게시문 밖 첫 댓글 등 채널 배치에 둔다. CTA는 마지막 한 번. 발행 전 실제 빈 줄·서식 기호·목록 개행을 검사하며 플랫폼에서 확인하지 않은 결과는 보장하지 않는다.

## 고정 규칙 요약

- 영문에서 행정사는 항상 **Administrative Attorney**(사무소는 Administrative Attorney Office). 다른 번역(administrative agent, scrivener 등)을 쓰지 않는다. 소송·분쟁 대리를 암시하는 문장과 함께 쓰지 않는다.

- 훅 금지: 공포·긴박감, 결과·승인 보장, 확인하지 않은 숫자, "모르면 손해"류, 창작한 1인칭 경험, 경력 나열로 시작.
- 답을 감춰 체류시간을 늘리지 않는다.
- 후기·실적이 없으면 만들지 않는다. 조회·저장을 만족·수임·전문성의 증거로 확대하지 않는다.
- 본문에 연락처·버튼·카카오톡·텔레그램·이메일 링크를 넣지 않는다. CTA는 한 번, 무료 검토 범위를 넘기지 않는다.
- 비상주 사무소를 실제 상주 사무실·조직처럼 연출하지 않는다. 실제 의뢰·상담 장면을 창작하지 않는다.
- 캡션 첫 부분에 대상 독자를 자연스럽게 밝힌다. 카드 내용을 그대로 반복하지 않고 맥락·경계·다음 행동을 보완한다.

`docs/blog-authoring-spec.md` 6절의 최종 3질문을 공통 편집 관점으로 참고하되 기존 채널 QA는 유지한다. 그 점검 안에서 중심 질문에 적합한 실제 근거가 설명을 이끄는지, 독자에게 필요한 조건과 맡길 일이 남는지를 함께 본다. 새 점수표나 검수 패스는 추가하지 않는다. 카드·영상이 동반되면 문구 개요, JSON 등 제작 초안, 렌더·자동 QA, 실제 이미지·영상 시각 검토 상태를 구분해 보고한다. 자동 QA만으로 디자인·법률 검증을 완료했다고 하지 않는다.

## 자가 점검표

- [ ] Primary Objective가 하나이고 게시물이 그것만 요구한다
- [ ] CTA 문장을 지워도 저장·공유할 만한 기준이 남는다 (**먼저 주기 테스트**)
- [ ] 첫 줄만 읽어도 대상과 판단 문제가 보이고, 독자가 무엇을 확인할지 알 수 있다
- [ ] LinkedIn 발행용은 `text` 코드 블록, 실제 빈 줄, 일반 텍스트 목록, 마크다운 구문 없음
- [ ] 공식 근거와 실제 확인일·판본을 내부 검수 기록에 남겼고 U가 없다. 공개 본문·캡션·자막에는 독립 확인 기준일/검증 기준일 라벨이 없으며 법령 시행일·판결일·통계기간은 보존했다
- [ ] 독자의 생각과 오해가 법률 설명·자기 적용·맡길 업무로 연결되며 이름·대화·절차 순서를 공식으로 강제하지 않았다
- [ ] 파생의 새 예시는 원문 보강·검증·승인 후 사용했다
- [ ] 숫자·조문·날짜·한정어가 원문과 같다
- [ ] 경험 창작·과장·공포·직접 연락 유도·채널 부적합 표현이 없다
- [ ] 윤문과 의미 재검증을 마쳤다 (영문·아랍어는 별도 현지화 검수)
- [ ] 확인하지 못한 항목을 사용자에게 알렸다
