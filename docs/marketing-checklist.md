## 1. AI 검색에서 인용되기 (블로그·웹사이트 글)

글감표에서 AI 인용 누적(27,000)이 사람 조회(약 5,100)보다 크므로, 사람이 읽기 좋은 글이 곧 AI가 인용하기 좋은 글이 되도록 쓴다. AI만을 위한 별도 글을 만들거나 글을 잘게 쪼개지 않는다. 같은 글이 사람과 AI 모두에게 읽혀야 한다.

- [ ] **소제목 아래 첫 2~3문장(약 100~150자)이 그 질문의 직접 답이다.** 소제목은 독자가 실제로 묻는 문장으로 쓴다(이미 잘하고 있는 방식).
- [ ] 문단 하나에 생각 하나. 절차는 번호 목록, 비교는 표로 쓴다.
- [ ] **기준일이 맨 앞에 있다.** 법령·제도 글은 "기준일 YYYY년 M월 D일"과 개정 시 최종 확인일을 쓴다. 날짜 없는 글은 인용에서 밀린다.
- [ ] **출처가 본문에 있다.** 조문·판례·기관 자료는 이름과 날짜를 쓰고, 숫자에는 출처를 붙인다. 원문 1차 자료를 우선한다.
- [ ] 저자 표기가 모든 글에서 같다. 같은 사람이 "Jean"과 "지상진"으로 나오면 같은 저자로 인식되기 어렵다.
- [ ] 소개·강연 후기·업무제휴·외부 프로필이 같은 정체성과 업무 범위로 서술돼 있다. 사실이 아닌 수상·후기·언급을 만들거나 부탁하지 않는다.
- [ ] 키워드를 억지로 반복하지 않는다. 읽는 사람이 어색하면 AI도 인용하지 않는다.
- [ ] 같은 주제 묶음(예: E-7 시리즈)은 서로 연결해 주제 전체를 덮는다. 단, 웹사이트용 글은 `website.md`에 따라 각 글이 단독으로 완결돼야 한다.

### 웹사이트 저장소에서 따로 확인할 것 (이 저장소에서 고치지 않는다)

2026-10-05 `ethosattorney.com`을 직접 확인한 결과다.

- `robots.txt`는 모든 크롤러에 공개 글을 허용한다. AI 검색 크롤러를 막고 있지 않다. 학습용 크롤러(GPTBot, ClaudeBot 등)를 따로 허용·차단할지는 정책 결정이다.
- 글 페이지에는 `Article`, `BlogPosting`, `BreadcrumbList`, `LegalService`, `Organization` 구조화 데이터가 이미 있다. `FAQPage`는 보이지 않았다. 효과는 사이트·엔진마다 달라 선택 사항이다.
- 슬러그가 깨진 글이 있고(앞쪽 하이픈, 잘린 끝, `title-…-excerpt-…` 혼입) 저자 표기가 글마다 다르다.

## 2. 카피 (제목·도입·카드 문구)

- [ ] **한 문장에 한 가지 주장.** 같은 문장에 조건·예외를 쉼표로 이어 붙이지 않는다(법률 한정어는 필요한 만큼 유지).
- [ ] **구체적으로.** "빠르게 처리"가 아니라 날짜·건수·기한·기관명으로 쓴다. 단 숫자는 원문 근거가 있는 것만 쓴다.
- [ ] 제목은 결론이나 독자의 상황이 먼저 보이게 쓴다. 40자 안팎. 시리즈 표시는 앞의 대괄호로 짧게.
- [ ] 도입 5줄 안에 독자의 상황과 그 상황에서 무엇을 확인해야 하는지가 나온다. 가정 사례는 가정이라고 쓰고, 지어낸 경험담·금액은 쓰지 않는다.
- [ ] **AI 티 나는 패턴을 줄인다.** `humanize-korean` 규칙집(`vendor/im-not-ai/quick-rules.md`)이 상세 기준이다. 특히 아래 셋을 점검한다.
  - "A가 아니라 B입니다" 식 대비 반전이 연달아 나온다(법적 구분이 꼭 필요한 한 번은 허용).
  - "~도 없고, ~도 없고, ~도 없습니다" 같은 부정 나열.
  - 문장 끝에 설명을 계속 덧붙이는 꼬리 문장.
- [ ] 느낌표, 과장 형용사(완벽, 혁신적), 업계 유행어를 쓰지 않는다. 쓰고 싶으면 그 말이 대신하는 사실을 쓴다.
- [ ] **교체 테스트**: 다른 행정사 사무소의 글에 그대로 넣어도 말이 되면 다시 쓴다. 에토스만의 차별점은 판단 과정(대조·순서·확인 결과)이다. 차별점이 없으면 `[필요: 차별점]`으로 표시하고 지어내지 않는다.
- [ ] 소리 내어 읽어 어색한 문장은 고친다.

## 3. 전환 (무료 검토까지의 경로)

방문자를 문의로 이어 주는 것은 글 끝의 한 문장이 아니라 경로 전체다. 접수 경로·무료 범위는 웹사이트 저장소 운영정책이 정본이다.

- [ ] 한 글에는 다음 행동이 **하나**다(무료 검토).
- [ ] CTA 문구는 독자가 무엇을 보내면(입력 2~3개) 무엇을 확인받는지(결과 1~3개)를 말한다. 무료 범위(가능 여부, 시작 방향, 확인할 기관·자료)를 넘는 약속은 쓰지 않는다.
- [ ] CTA는 글 끝뿐 아니라 **첫 답이 나온 직후**에도 한 번 시험해 볼 만하다. 웹사이트 퍼널이 CTA 위치별 클릭을 추적하므로 위치를 바꾼 뒤 비교한다.
- [ ] 글의 주제와 이어지는 CTA인가("이 글의 상황이라면 무엇을 보내시면 되는지").
- [ ] 신청이 쉬운가: 입력 항목이 필요한 만큼만이고, 모바일에서 끝까지 되는가.
- [ ] 업무 범위 밖 문의를 부르지 않도록 다루는 범위가 글 말미나 소개에 한 줄 있다.
- [ ] 변경은 **한 번에 하나**만 바꾸고 순차 단일변수 학습으로 기록한다(`docs/performance-learning.md`). 표본이 작으면 통계적 A/B라고 부르지 않는다.

## 4. 받을 자료 설계 (lead magnet)

받을 자료는 연락처를 얻기 위한 미끼가 아니라 Proof of Work를 독자 손에 쥐여 주는 한 장이다. 운영 원칙은 `docs/strategy-playbook.md` 3절, 양식은 `content/_TEMPLATE/lead-magnet-checklist.md`·`lead-magnet-process-map.md`.

**에토스에 맞는 형식** (한 자료에 한 형식만 쓴다)

| 형식 | 맞는 글 | 원문에 있어야 하는 것 |
|---|---|---|
| 체크리스트 | 요건·결격·보완 사유를 다루는 글 | 실제 확인 항목과 확인처(서류·기관) |
| 절차 맵 | 신고→허가→사후의무처럼 순서가 핵심인 글 | 판단 순서와 담당 기관 |
| 기한 계산표 | 처분·청구·신고 기한이 있는 글 | 기산일·기간·법령 표기. 표는 "기산일 + 기간 = 마감일" 칸만 두고, 예외·연장은 원문 문장 그대로 덧붙인다 |
| 서류 목록 | 제출서류가 많고 발급처가 흩어진 글 | 서류명·발급처·유효기간(원문에 있는 것만) |

**저장할 만한 자료의 조건**

- [ ] 문제 하나만 푼다. "외국인 고용 가이드"보다 "E-7 신청 전 회사 쪽에서 먼저 확인할 4가지".
- [ ] 10분 안에 다 읽고 바로 써 볼 수 있다. 휴대폰에서 열리고 별도 프로그램이 필요 없다.
- [ ] 여정 단계에 맞다(발견: 해당 여부 점검표, 이해: 절차 맵, 결정: 서류 목록·기한 계산표).
- [ ] 기준일과 근거 법령명이 맨 위에 있다. 날짜가 없는 자료는 오래 쓸수록 위험해진다.
- [ ] "혼자 처리할 수 있는 범위"와 "검토가 필요한 경계"가 끝에 있다. 이 구분이 에토스 자료의 차별점이다.

**공개 정책**

- 핵심 정보는 잠그지 않는다. 글과 카드에서 판단 기준을 모두 공개하고, 자료는 그것을 한 장으로 정리한 편의본으로 둔다.
- 자료를 받는 데 이메일 등 입력을 요구할지는 웹사이트 저장소 운영정책이 정한다. 요구하더라도 필요한 최소 항목만 받고, 자료 안에 "전체 내용은 상담 시 제공" 같은 미완결 장치를 두지 않는다.
- 다운로드 수·"OO명이 받은 자료" 같은 표기는 실제 집계가 있을 때만 쓴다.

## 5. 심리 원리 (윤리적으로 쓸 수 있는 것만)

원칙은 가설이며 성과로 단정하지 않는다(`docs/ethical-persuasion.md`). 아래 예시는 방향을 보여 주는 것이고 실제 문장은 원문 사실에서만 만든다.

| 원리 | 쓰는 방법 | 허용 예 | 금지 예 |
|---|---|---|---|
| 구체성 | 막연한 말 대신 기관·기한·서류명 | "처분이 있음을 알게 된 날부터 90일 이내에 행정심판을 청구해야 합니다"(원문 표기 그대로) | "빠르고 확실하게 해결합니다" |
| 손실 프레임(정직하게) | 원문에 있는 실제 불이익을 그 크기대로 | "신고 없이 영업하면 과태료 대상이 될 수 있습니다"(원문 표현 유지) | "지금 안 하면 사업이 끝납니다", "~될 수 있다"를 "~됩니다"로 바꾸기 |
| 상호성 | 쓸모 있는 자료를 조건 없이 먼저 | 체크리스트 전체를 글에 공개하고 정리본을 따로 제공 | "체크리스트 3번부터는 문의하신 분께만" |
| 인지적 편안함 | 한 문장 한 주장, 쉬운 말, 숫자 순서 | 전문용어 옆에 한 줄 풀이, 절차를 번호 목록으로 | 조문 번호만 나열해 전문성을 과시 |
| 앵커링(실제 숫자만) | 원문에 있는 법정 기준을 기준점으로 | "법정 처리기간 ○일"처럼 법령에 있는 숫자 | 근거 없는 "평균 처리기간", 비싼 가격을 먼저 보여 주기 |
| 선택 줄이기(힉의 법칙) | 한 글에 다음 행동 하나 | 끝에 무료 검토 안내 한 문장 | 저장·공유·DM·전화·방문을 한꺼번에 요청 |
| 시작 부담 낮추기 | 첫 행동을 작게, 보낼 것을 구체적으로 | "처분서 사본과 영업신고증 두 가지만 보내 주시면" | "무엇이든 물어보세요" |
| 결점 인정(프랫폴 효과) | 업무 범위를 먼저 밝힌다 | "소송 대리는 변호사 업무 영역입니다" | 다른 자격사를 깎아내리며 범위 흐리기 |
| 친숙함(단순 노출) | 브랜드 축·색·문체의 일관성 | 같은 시리즈 표기와 기준일 형식 반복 | 같은 문장·광고를 반복 노출 |

다음 원리는 쓰지 않는다: 허위 희소성·마감, 사회적 증거 만들기(후기·건수·로고), 미끼 선택지(decoy), 미완결 효과로 답 숨기기, 손실 과장, 가격 앵커링, 할인·마감 카운트다운.

## 6. 웹사이트 글 구조화 데이터

구조화 데이터(JSON-LD)는 웹사이트 저장소(`Admin-system-`)가 렌더한다. 이 저장소는 MD 본문과 FAQ 후보만 공급하고 JSON-LD를 쓰지 않는다.

- **Article/BlogPosting**: 사이트가 머리말의 `title`·`excerpt`·`date`로 채운다. 이 저장소에서는 머리말이 본문과 정확히 일치하고, 저자 표기가 모든 글에서 같은지만 확인한다.
- **BreadcrumbList**: 사이트가 `category`로 만든다. `category`를 글 내용에 맞게 고르면 된다.
- **FAQPage**: 글에 독자가 실제로 묻는 질문과 답이 2~4개 자연스럽게 있을 때만 후보를 낸다. 답은 본문에 있는 문장을 그대로 쓰고, 본문에 없는 Q&A를 만들지 않는다. FAQ를 위해 글을 Q&A로 쪼개지 않는다. 후보는 MD 파일 밖, 응답 끝에 둔다(`docs/website-md-spec.md` 7절). 적용 여부와 효과 측정은 웹사이트 쪽 결정이다.
- 구조화 데이터는 화면에 보이는 내용과 같아야 한다. 화면에 없는 별점·후기·가격을 표시하지 않는다(`Review`·`AggregateRating`은 쓰지 않는다).

## 7. 가져오지 않은 것과 이유

원본 스킬에는 있지만 에토스 원칙과 부딪혀 뺐다.

| 원본의 권고 | 뺀 이유 |
|---|---|
| "Join 10,000+ teams" 같은 사용자 수·로고·후기 나열 | 확인되지 않은 고객 수·후기 금지. 후기는 웹사이트의 후기 게시 정책을 따른다 |
| 긴급성·희소성, 손실 강조, 마감 카운트다운 | `docs/ethical-persuasion.md`가 허위 희소성·공포 조장을 금지한다 |
| 성공률·"3배 개선" 같은 성과 수치 | 결과 보장·성과 창작 금지 |
| 경쟁사 대비 "최고" 비교 페이지, 자기홍보 listicle | 다른 자격사와의 우열 주장 금지. 원본도 신생 브랜드에는 역효과 가능성을 경고한다 |
| 위키·레딧 등에 인위적으로 언급 만들기 | 가짜·유도 언급 금지. 실제 활동과 사실에 기반한 외부 노출만 |
| 원본의 통계(AI Overview 비율, 인용 증가율 등) | 출처와 시점이 바뀌는 수치라 이 저장소의 근거로 쓰지 않는다 |
| 가격 페이지의 `pricing.md` 파일 | 에토스는 SaaS 가격 비교 대상이 아니다. 상담료는 웹사이트 정책이 정본 |
| 핵심 자료 전면 잠금, 다운로드 수 표시, 팝업·이탈 감지 노출 | 핵심 정보를 숨기지 않는다. 집계 없는 숫자 금지. 노출 방식은 웹사이트 정책 |
| 미끼 선택지, 큰 요청 뒤 작은 요청(door-in-the-face), 9로 끝나는 가격 | 선택을 조작하는 설계는 판단을 돕는 설득이 아니다 |
| `Review`·`AggregateRating`·`Product` 구조화 데이터 | 후기·별점을 만들지 않으며 화면에 없는 내용을 표시하지 않는다 |

## 8. 쓰는 방법

- **글·카드 작성 마지막 단계**에서 1~3절을 훑는다. 받을 자료를 만들 때는 4절, 카피의 설득 장치를 점검할 때는 5절, 웹사이트 MD를 낼 때는 6절을 본다. 결과를 별도 보고서로 만들 필요는 없다.
- 이 목록으로 사실·법률 문장을 바꾸지 않는다. 의심스러우면 원문과 1차 자료가 우선이다.
- 4주 단일변수 측정으로 어떤 항목이 실제로 조회·문의에 영향을 주는지 확인한 뒤, 효과가 확인되지 않은 항목은 삭제한다.
