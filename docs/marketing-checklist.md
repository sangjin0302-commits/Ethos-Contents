## 1. 검색에서 질문과 답을 찾을 수 있게 쓰기

사람이 자기 문제에 대한 답을 찾을 수 있게 쓰는 것이 우선이다. AI 인용을 노리고 글을 잘게 쪼개거나 답을 숨기지 않는다. 문체나 날짜 표기만으로 검색 순위·AI 인용·문의 증가를 보장하지 않는다.

- 제목과 도입이 던진 질문에 직접 답한다. 소제목마다 질문형을 강제하거나 답을 특정 문장 수·글자 수에 맞추지 않는다. 이해에 필요한 상황·비교와 실제 조건은 남긴다.
- 공식 출처와 법령 시행일·판결일은 독자가 찾을 수 있게 제시하고 확인일·판본은 내부 검증 기록에 보존한다. 공개 독립 확인일 라벨은 넣지 않는다. 블로그의 충분한 도입·말미 3줄 요약 위치는 최신 채널 명세를 따른다. 확인되지 않은 최신성을 날짜만 바꿔 표시하지 않는다.
- 검색어는 질문을 분명히 하는 범위에서 자연스럽게 쓴다. 키워드 반복이나 제목 변경이 더 좋은 성과를 낸다고 미리 단정하지 않는다.
- 저자와 사무소 표기는 채널·언어별 승인된 이름을 사용한다. 소개·강연·외부 프로필의 경력과 업무범위도 실제 사실에 맞춘다.
- 관련 글 연결은 채널 규칙을 따른다. 웹사이트용 글은 `docs/website-md-spec.md`에 따라 단독으로 완결한다. 비교를 반드시 표로 만들지 않으며 웹사이트 MD의 표 금지 규칙을 유지한다.

과거에 이 문서에 적힌 조회·AI 인용 누적 수치를 현재 성과로 재사용하지 않는다. 성과 분석이 필요한 작업에서만 글감관리표의 해당 기간·채널·지표 정의를 확인한다. 표를 읽지 못하면 수요나 전환율을 추정하지 않는다. 과거 값은 Git 이력에 남아 있다.

### 웹사이트 기술 확인은 별도 작업

기존 문서의 2026-10-05 사이트 관찰은 현재 운영 상태를 보증하지 않는다. 크롤러 설정, 슬러그, 저자 표시, 구조화 데이터가 실제로 문제되는 작업에서만 `Admin-system-`의 운영정책·코드·공개 페이지를 확인한다. 매 원고 작성 때 사이트 전체를 다시 조사하지 않으며, 이 문서만 수정하고 웹사이트 기능을 고쳤다고 보고하지 않는다.

## 2. 카피: 쉽고 구체적이되 원래 글의 흐름을 살리기

먼저 독자에게 설명하듯 초안을 쓴다. 아래 관점은 다 쓴 뒤 실제로 읽히지 않는 부분에만 적용한다.

- **제목과 도입을 보존한다.** 사용자가 선택한 질문과 시리즈 앞머리, 납품·채용 등 독자의 장면을 기본으로 살린다. 글자 수나 SEO를 이유로 질문의 범위를 좁히거나 도입을 삭제하지 않는다. 제목 길이와 앞부분 형식은 채널 명세를 따른다.
- **질문에 답하고 이유를 잇는다.** 기한 안내나 상담 권유를 직접 답 대신 내놓지 않는다. 한 생각을 설명하는 문장은 자연스럽게 연결하고 낯선 개념이 겹친 부분만 풀어 쓴다. 문장마다 줄을 바꾸거나 같은 확인 지시로 끝낼 필요는 없다.
- **구체성은 수행하는 일에서 만든다.** 막힌 상황에서 어떤 서류의 날짜·이름·항목을 맞추고, 어떤 내용을 정리하거나 문서를 준비하며, 다음에 무엇을 할지 보여준다. 숫자·판례·사례를 늘리는 것과 구체성을 혼동하지 않는다.
- **공식 용어는 뜻을 붙여 남긴다.** 법률상 주체·조건·예외·재량, 숫자와 인용은 보존한다. 필요한 대비나 부정 표현을 사용 횟수만으로 삭제하지 않는다. 반복 때문에 읽기가 막힌 부분만 다듬는다.
- **차별점을 억지로 만들지 않는다.** 다른 사무소에서도 쓸 수 있는 정확한 제도 설명은 그대로 둔다. 실제 제공 업무가 있는 대목에서 자료와 수행 과정을 보여준다. 모든 문단의 독창성이나 사무소 소개를 강제하지 않으며, 없는 실적·보고서·회신기한을 덧붙이지 않는다.
- **이미 읽히는 문장은 유지한다.** 본문의 논리와 연결이 자연스러우면 그대로 둔다. 필요한 윤문은 `docs/language-quality-workflow.md`와 채널 명세의 담당 단계에서 한다. 이 메모를 읽었다는 이유로 외부 윤문 도구를 추가 실행하지 않는다.

설명용 표현 예: "문서 정합성을 검토합니다"보다 "계약서와 신청서의 날짜를 맞춰 보고, 다른 부분을 정리합니다"처럼 쓴다. 원문과 실제 제공 업무가 뒷받침할 때만 사용한다. 문체 예시가 새 서비스나 무료 작성 약속이 되지는 않는다.

## 3. 전환: 맡길 일과 접수 방법을 이해시키기

문의 문구를 늘리기보다 독자가 자기 상황에서 무엇을 맡길 수 있고 어떤 안내를 받을지 알게 한다. 접수 경로·상품·가격·무료 범위는 웹사이트 저장소 운영정책이 정본이다.

- 대표 행동은 글의 역할과 채널에 맞게 하나로 정한다. 저장·공유·전화·방문을 동시에 요구하지 않는다. 무료 검토 안내의 유무와 위치도 채널별 명세를 따른다.
- 블로그의 무료 검토 서술 문단은 후반 한 번이다. 첫 답 직후나 본문 중간에 상담 문구를 추가하지 않는다. 네이버에서는 그 문단 아래 기존 링크형 상담 이미지 4개를 온라인 접수 → 카카오톡 → 이메일 → 텔레그램 순서의 한 영역으로 둔다. 온라인 접수가 대표 경로이며 기존 주소를 임의로 바꾸지 않는다.
- 안내에는 보낼 자료 2~3개와 무료로 먼저 확인할 내용 1~3개를 독자의 말로 쓴다. 개별 전략·서류별 수정 지시·의견서 작성 등 유료 수임 업무를 무료 검토에 포함된 것처럼 표현하지 않는다.
- 실제 맡는 자료 정리·서류 작성과 허가·처분 변경 같은 외부의 결정을 구분한다. 직접 확인할 수 있는 부분과 다른 전문가의 업무가 필요한 경계는 해당 문제에 맞게 설명한다.
- 접수 경로 점검이 요청됐거나 발행 확인이 필요한 때에는 모바일에서 링크와 제출 흐름을 실제로 확인한다. 확인하지 않은 경로·기간·자동 전달 기능은 작동한다고 보고하지 않는다. 링크 위치와 추적값은 채널 명세대로 쓰고 새 식별자를 추측하지 않는다.

보조문서만으로 CTA 위치 실험이나 사이트 정책 변경을 승인하지 않는다. 측정된 성과 없이 이번 문구가 더 많은 문의를 만든다고 단정하지 않는다.

## 4. 받을 자료 설계: 필요한 경우에만

받을 자료는 본문에 있는 확인 기준을 다시 쓰기 편하게 정리한 편의본이다. 모든 글에 별도 파일을 의무적으로 만들거나, 자료가 없다는 이유로 원고를 중단하지 않는다. 실제로 만들고 제공한 자료만 배포한다고 안내한다.

- 요건 비교에는 체크리스트, 선후관계에는 절차 맵, 발급처가 흩어진 경우에는 서류 목록처럼 독자의 문제에 맞는 형식을 고른다. 형식을 채우기 위한 항목은 만들지 않는다.
- 기한 계산표는 원문에서 확인한 기산일·기간·예외·연장을 함께 담는다. 단순 덧셈 표로 법률상 조건을 지우지 않는다. 새로운 계산은 근거와 별도로 확인한다.
- 휴대폰에서 읽고 사용할 수 있게 만들되 검증하지 않은 읽기 시간이나 절약 시간을 약속하지 않는다. 확인일·판본은 내부 기록에 보존하고 자료에는 근거·법률상 날짜, 직접 확인 범위와 개별 검토 경계를 남긴다.
- 핵심 답을 자료나 문의 뒤로 숨기지 않는다. 개인정보 입력 여부는 웹사이트 정책을 따르며 다운로드 수·이용자 수는 실제 집계가 있을 때만 표시한다.

자료를 실제로 만드는 작업에서만 `docs/strategy-playbook.md` 3절과 해당 `content/_TEMPLATE/lead-magnet-*.md` 양식을 참고한다.

## 5. 설득 원리: 효과를 단정하지 않고 필요한 것만

공통 원칙은 `docs/ethical-persuasion.md`다. 심리 기법을 문단마다 배치하거나 기법 수를 채우지 않는다.

- 구체성은 실제 자료와 작업, 확인 가능한 기준을 보여주는 방식으로 쓴다.
- 불이익은 확인된 조건과 크기대로 설명한다. 가능성을 확정된 피해로 바꾸거나 없는 긴급성을 만들지 않는다.
- 유용한 답과 확인 기준을 먼저 제공한다. 상담을 받아야만 핵심 결론을 알 수 있게 만들지 않는다.
- 시작 부담은 보낼 자료와 안내받을 내용을 분명히 해서 낮춘다. 실제 필수 자료를 임의로 줄이거나 서비스를 새로 약속하지 않는다.
- 일관성은 승인된 이름·시리즈·업무범위에서 유지한다. 같은 광고 문장이나 불필요한 전문용어를 반복하는 뜻이 아니다.

허위 희소성, 가상 후기, 확인되지 않은 건수·로고, 미끼 선택지, 가격 앵커링과 마감 카운트다운은 도입하지 않는다. 정직하게 경계를 설명하는 일을 감정 조작 기법으로 취급하지 않는다.

## 6. 웹사이트 글과 구조화 데이터

구조화 데이터(JSON-LD)의 구현·적용 확인은 `Admin-system-`의 별도 작업이다. 콘텐츠 작성에서는 머리말과 본문이 일치하는지 확인하고, 검색 노출이나 기능의 작동을 추정하지 않는다.

- 제목·요약·기준일·분류는 본문과 맞춰 쓴다. 허위 저자·경력·후기·별점·가격을 구조화 데이터에도 만들지 않는다.
- FAQ는 실제 독자 질문과 원문에 있는 답이 자연스럽게 있을 때만 쓴다. 배치는 `docs/website-md-spec.md` 7절에 따라 마지막 무료 검토 안내 앞의 본문에 `Q.`·`A.` 문단으로 둔다. 별도 응답 끝에만 두라는 과거 권고는 적용하지 않는다.
- FAQ를 위해 새 법률 사실을 만들거나 글 전체를 문답으로 쪼개지 않는다. 형식·문항 기준은 웹사이트 명세를 참조하고 여기에서 별도 숫자를 강제하지 않는다.
- 크롤러 설정이나 구조화 데이터의 현재 상태는 필요한 작업에서 실제로 확인한다. 이 보조문서의 과거 관찰로 구현 완료나 검색 효과를 주장하지 않는다.

## 7. 외부 스킬에서 가져오지 않는 것

외부 스킬은 편집 관점의 참고 자료이며 에토스의 작성 명세나 승인된 업무범위를 덮어쓰지 않는다.

- 전체 원고의 반복 재작성, 일괄 다중 에이전트 검수, 점수 미달만으로 발행 차단
- 실제 질문·조건을 지우는 제목 공식, 공통 법률 설명까지 바꾸게 하는 독창성 검사
- 결과 보장, 타 자격사보다 우월하다는 주장, 가상 고객 수·성과·리뷰·외부 언급
- 사실로 확인되지 않은 손실·마감·희소성, 핵심 답 잠금, 선택을 조작하는 가격 장치
- 원본 프로젝트의 시점·대상·출처가 다른 통계를 에토스의 성과로 사용하는 일
- 이번 문서 정리를 이유로 한 외부 도구 설치·유료 API 호출·사이트 기능 변경

## 8. 사용과 종료

필요한 절만 읽고 이미 있는 원고의 약한 부분만 고친다. 블로그의 최종 점검은 `docs/blog-authoring-spec.md`의 세 질문을 유지하며 이 문서가 새 점수표나 별도 검수 단계를 만들지 않는다. SNS·카드·웹사이트는 각 명세의 범위와 담당자를 따른다.

법률·사실·업무범위·인용·필수 형식의 문제가 해결되고, 독자의 질문에 답하며 실제 자료와 작업이 이해되면 편집을 마친다. 발견된 오류는 해당 부분만 다시 확인한다. 더 높은 마케팅 점수, 제목 길이 권고나 문형 비율 때문에 읽히는 글을 계속 다시 쓰지 않는다. 법률 근거가 미확인인 문장을 이 종료 기준으로 발행하는 것은 허용하지 않는다.

성과 검토는 원고 편집과 분리한다. 글감관리표를 읽을 수 있는 별도 분석 작업에서 실제 기간·채널·노출·문의·수임을 구분하고 변경은 한 번에 하나씩 기록한다. 기간을 정해 숫자를 모았다는 이유만으로 인과관계가 입증됐다고 하거나, 데이터가 부족한 항목을 실패로 판정하지 않는다. 새 강제 기간이나 재작성 횟수는 두지 않는다.

### 이번 변경 범위

본문 중간 CTA, 문장 수·글자 수를 맞추는 보조 기준, 공통 설명의 강제 재작성, 과거 수치와 사이트 상태의 현재화, FAQ 배치 충돌을 정리했다. 기존 출처 기록은 유지했다. 이 파일 밖의 원고·채널 명세·렌더 코드·고정 지문·웹사이트 운영정책은 이번 단계에서 변경하지 않는다. 다음 단계의 도구 운용 간소화와 실제 원고 비교는 별도 실행·확인 대상이다.
