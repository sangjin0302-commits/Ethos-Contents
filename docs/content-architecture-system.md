# 에토스 콘텐츠 구조 운영체계

> 목적: 글마다 같은 틀을 반복하지 않으면서 검색 유입, 전문성 증명, 상담 전환이 한 흐름으로 이어지게 한다.
> 적용: 앞으로 기획하는 블로그·홈페이지·LinkedIn·Instagram·카카오·Threads 콘텐츠. 이미 발행 예정인 화장품 세트는 수정하지 않는다.

## 1. 고정할 것과 고정하지 않을 것

모든 콘텐츠에 고정하는 공통 뼈대는 다섯 가지다.

1. 누구의 어떤 상황인지
2. 질문에 대한 직접 답
3. 판단 기준·근거·확인 순서
4. 독자가 직접 할 범위와 개별 검토가 필요한 경계
5. 다음 행동 하나

소제목 이름, 항목 수, 사례 위치, 문단 순서까지 같은 템플릿으로 고정하지 않는다. 독자가 여러 글을 연속으로 읽어도 복제문처럼 느끼지 않게 표현과 전개는 주제에 맞춰 바꾼다.

## 1-1. 같은 전문성, 쉬운 설명

**글의 첫 문장은 제도가 아니라 독자가 놓인 상황에 가깝게 쓴다.** 예를 들어 '행정처분 불복의 요건'보다 '영업정지 통지서를 받았는데 지금 무엇부터 확인할까'가 독자의 질문을 더 직접적으로 보여 준다. 단, 실제 검색어와 대상 고객을 확인하지 않고 모든 제목을 질문형으로 만들지는 않는다.

- 독자의 상황을 제시한 뒤 확인된 답을 먼저 말한다. 답을 감추고 사례만 길게 끌지 않는다.
- 전문용어는 첫 등장에 한 번 풀되 법률상 정확한 명칭과 요건을 남긴다.
- 예시는 필요한 판단의 차이를 보여 줄 때만 쓴다. 가상 상황은 가상이라고 밝히고, 실제 재결례·판결은 사건의 확인된 사실과 분리하지 않는다.
- 사례 뒤에는 '그래서 어떤 서류의 무엇을 확인할까'를 연결한다. **상황 → 답 → 기준 → 확인 행동**은 방향이지 모든 글에 강제하는 틀이 아니다.
- 쉬운 설명만으로 조회가 늘거나 문의가 전환된다고 추정하지 않는다. 역할별 지표와 실제 유효문의·수임 흐름으로 평가한다.

## 1-2. 모든 채널에 같은 판단을, 채널마다 다른 설명을

**공통으로 고정하는 것은 사실과 법률의 의미다.** 독자 질문에 대한 직접 답, 적용 조건과 예외, 공식 출처와 확인 기준일, 직접 할 일과 전문가 검토의 경계, 실제 서비스 범위는 채널을 바꿔도 달라지지 않는다. 반대로 사례 길이·문장 구조·시각화·호칭·전문용어를 풀어 쓰는 깊이는 독자와 채널에 맞춰 바꾼다.

- **세 층의 설명(권고)**: ① 먼저 답을 이해한다 → ② 자기 상황에 적용할 조건과 비교를 확인한다 → ③ 더 필요한 독자는 법령·재결례·예외를 확인한다. 세 문단이나 세 카드로 고정하라는 뜻이 아니다.
- **판단이 갈리는 상황**: 비교할 두 경우가 실제 원문의 사실·법률 근거로 뒷받침될 때만 대조한다. 가상 사례는 가상이라고 표시하고, 존재하지 않는 결과·처분·상담 후기를 만들지 않는다.
- **Source Lock을 넘지 않기**: 승인된 블로그에서 SNS·카드·웹사이트 MD로 옮길 때 독자의 표현은 새로 쓸 수 있어도 사건 사실·숫자·조건·결론은 추가하거나 삭제하지 않는다. 간결하게 만들기 위해 필수 한정어를 버려야 하면 게시물을 나눈다.
- **독자의 익숙한 언어**: 일반 생활 독자에게는 가게 인수·고지서·계약금 등의 장면이, 기업 의사결정자에게는 인사팀의 업무 변경·내부 승인·증빙서류의 불일치가 출발점이 될 수 있다. 소재가 대중적이어야 한다는 뜻은 아니다.
- **끝은 판단에 도움이 되는 행동**: 막연한 '전문가 상담 필요' 대신 독자가 확인할 서류의 항목·담당자·절차 순서를 제시한다. 유료 개별전략이나 법정 대리업무를 무료로 제공하는 듯한 문구는 쓰지 않는다.

이 절은 각 채널의 출력 형식·길이·CTA·승인 단계나 기존 블로그 최종 3질문을 대체하지 않는 **공통 Soft Guide**다. 글마다 새로운 고정 체크리스트를 만들지 않는다.

## 2. 작성 전에 붙이는 역할표

새 콘텐츠의 내부 메모 또는 `brief.md`에 다음 일곱 항목을 적는다.

- 주 독자
- 실제 질문 또는 검색어
- 역할: Traffic / Authority / Revenue 중 하나
- 여정: 발견 / 이해 / 신뢰 / 결정 중 하나
- 직접 답 한 문장
- 다음에 연결할 콘텐츠 또는 자료 하나
- Primary Objective와 CTA 하나

역할을 둘 이상 동시에 달성하려 하지 않는다. 시리즈 전체는 여러 역할을 가질 수 있지만 한 편의 주 역할은 하나다.

## 3. 블로그·홈페이지 구조 선택

### Traffic: 검색 질문에 답하는 입구 글

상황과 직접 답을 첫 5문단 안에 제시한다. 통지서·계약서·창업 준비처럼 독자가 실제 접하는 장면을 필요할 때 활용한다. 이어서 적용 조건, 확인 순서, 흔한 오해, 직접 처리 범위, 관련 Core 글 순으로 전개한다. 검색량만 높은 넓은 단어보다 상담 가능성이 있는 구체 질문을 우선한다.

### Authority: 판단 능력을 보여 주는 핵심 글

서로 헷갈리는 기준 또는 판단 쟁점을 독자의 언어로 먼저 제시하고 결론을 낸다. 공식 근거를 설명한 뒤 필요하면 대비되는 가상 상황으로 적용 차이를 보여 주고, 서류 대조·절차 순서·기관별 확인사항 등 실제 검토 방식을 구체화한다. 이력이나 추상적 전문성 표현이 아니라 판단 과정이 증거가 되어야 한다.

### Revenue: 상담 전 판단을 돕는 서비스 안내

Revenue는 네이버 글을 새로 써야 한다는 뜻이 아니다. 기존 웹 안내·승인상품이 역할을 충족하면 이를 연결한다. 신규 제작 여부는 `docs/strategy-playbook.md` 2-2절을 따른다.

누구에게 필요한지와 필요하지 않은지를 먼저 가른다. 받을 자료, 확인 결과, 진행 단계, 제외 범위, 예상 변수 순으로 설명한다. 확인하지 않은 비용·기간·성공 가능성을 만들지 않는다. 독자가 스스로 해결할 수 있는 정보도 충분히 제공한다. 받을 자료는 실제 서류·파일 이름으로, 확인 결과는 고객이 이해할 수 있는 말로 설명하고 무료 검토 안내는 후반 한 번만 둔다.

### Update: 제도 변경 대응 글

무엇이 언제 바뀌었는지, 누가 영향을 받는지, 기존과 무엇이 다른지, 지금 확인할 행동과 기한은 무엇인지 순서로 쓴다. 기준일과 공식 출처를 표시하고 변경되지 않은 부분도 구분한다. 이 형식은 Traffic·Authority·Revenue 중 주 역할 하나를 별도로 지정한다.

## 4. 채널별 구조

| 채널 | 권장 구조 | 다음 행동 |
|---|---|---|
| LinkedIn 의사결정형 | 기업 상황 → 예상 밖의 결론 → 판단 기준 2~4개 → 업무상 의미 → 근거 | 관련 핵심 글 또는 프로필 |
| LinkedIn 업무과정형 | 흔한 불일치 → 확인 순서 → 필요한 문서·부서 → 경영진이 놓치기 쉬운 지점 | 체크리스트 또는 검토 범위 |
| LinkedIn 제도변경형 | 변경점 → 영향받는 기업 → 실무 영향 → 이번 주 확인사항 → 공식 근거 | 관련 업데이트 글 |
| Instagram·카드 | 한 가지 판단 문제 → 한 가지 기준 → 비교·순서·체크리스트의 시각화 → 경계 | 저장 또는 프로필 |
| 카카오 | 상황 한 문장 → 직접 답 → 주의점 → 다음 확인 행동 | 메시지 또는 관련 글 |
| Threads·X | 구분 또는 관찰 한 문장 → 짧은 근거 → 적용 질문 | 프로필 또는 관련 글 |
| 홈페이지 서비스 | 고객 상황 → 제공 결과 → 진행 절차 → 필요한 자료 → 범위·경계 → CTA | 접수 |

LinkedIn은 블로그 요약문을 붙여 넣지 않는다. B2B 독자가 내부 결정을 내릴 수 있도록 법무·행정 기준이 실제 운영에 미치는 영향으로 다시 쓴다.

### 채널별 설명의 깊이와 독자 행동 (추가 권고)

- **네이버 블로그**: 독자 상황과 답을 앞에 두고, 사례·판단을 가르는 조건·공식 근거와 확인 순서를 충분히 설명한다. 분량과 앞부분 형식은 `docs/blog-authoring-spec.md`가 정본이다.
- **홈페이지 블로그 MD**: 검색자가 제목과 요약만 보고도 답을 찾도록 한다. 본문은 인사·시리즈 목차 없이 독립적인 안내로 만들고, 국·영문 형식은 `docs/website-md-spec.md`를 따른다.
- **홈페이지 서비스 안내**: 제공 결과·필요 자료·포함 및 제외 범위를 고객 언어로 쓴다. 실제 상품·가격·CTA는 웹사이트 저장소 운영정책이 정본이며 이 콘텐츠 저장소에서 임의 변경하지 않는다.
- **인스타그램 카드**: 같은 사실을 반복 설명하지 않고 장면, 조건 대조, 확인 순서를 여러 장에 나누어 시각화한다. 한 장 한 메시지와 법률상 한정어를 지킨다.
- **카카오톡**: 한 가지 실제 질문에 짧게 답하고 독자가 당장 확인할 것 하나를 남긴다. 별도의 긴 사건 이야기와 조문 나열은 필요할 때만.
- **LinkedIn 국·영문·아랍어**: 개인 생활 이야기보다 기업의 실제 의사결정과 문서·담당부서·업무상 영향을 중심으로 쓴다. 한국 법률용어와 조건은 해당 언어의 독자에게 이해되도록 풀되 의미를 바꾸지 않는다.
- **Threads·X**: 한 가지 오해나 조건의 차이를 간결하게 설명한다. 결론에 필요한 조건이 길어지면 생략하지 말고 더 긴 원문으로 연결하거나 게시물을 나눈다.

같은 원문에서 여러 채널로 파생하더라도 모든 채널에 사례 수·문단 수·CTA 형식을 똑같이 적용하지 않는다. 채널별 작성 명세가 길이와 출력 형식을 정한다.

## 5. 콘텐츠 연결 구조

연결 순서와 기존 안내 우선 판단은 `docs/strategy-playbook.md` 2-1~2-2절을 따른다. Traffic·Authority·Revenue는 필요한 역할이지 모든 독자가 세 글을 순서대로 읽어야 한다는 조건이 아니다.

한 글에서 필요한 다음 단계 하나를 고른다. 새 네이버 판매 글·새 페이지·추가 CTA를 자동 요구하지 않는다. 예약 화장품 세트는 그대로 두고 발행 후 공백이 실제로 확인될 때만 기존 자산 연결 또는 후속 콘텐츠를 검토한다.

## 6. 성과에 따른 수정 위치

| 관찰 | 우선 수정할 것 |
|---|---|
| 노출은 있는데 클릭이 적다 | 제목, 검색 의도, 첫 문단 |
| 클릭·조회는 있는데 다음 글 이동이 적다 | 본문 중 판단 기준, 내부 연결 |
| 조회는 있는데 문의가 없다 | 독자 적합성, 받을 자료, CTA의 구체성 |
| 문의는 있는데 상담으로 이어지지 않는다 | 접수 질문, 대상·비대상 구분 |
| 상담은 있는데 수임이 적다 | 제공 범위, 산출물, 일정·비용 설명, 후속 응대 |
| 저장은 많은데 사업 연결이 없다 | 정보형 주제 비중과 Revenue 연결 |

한 지표만으로 문체 전체를 바꾸지 않는다. 최근 90일과 최소 3개 콘텐츠 묶음으로 판단한다.

## 7. 운영 주기

- 매 편: 역할표 작성, 다음 콘텐츠 하나 연결
- 월 1회: Traffic·Authority·Revenue 비중과 끊긴 연결 확인
- 분기 1회: 최근 90일 성과로 유지·수정·중단 결정
- 반기 1회: 핵심 서비스별로 입구·판단 근거·서비스 안내 역할이 기존 자산에서 충족되는지 점검

이 문서는 콘텐츠 포트폴리오와 연결을 설계할 때 읽는다. 개별 원고 작성 규칙은 `docs/blog-authoring-spec.md` 또는 `docs/sns-authoring-spec.md`를 따른다.
