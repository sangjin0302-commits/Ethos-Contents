# 검색 의도·문제 해결·적합 문의 중심 글쓰기

> 적용일: 2026-10-31. 외부 수익 후기를 사실로 채택하지 않고 공식 자료에서 확인되는 원칙만 ETHOS 작업법으로 반영한다.
> 성격: 기존 블로그 명세·법률 검증·Source Lock·채널별 CTA를 보완하는 Soft Guide. 검색 순위·광고 수익·문의 증가를 보장하지 않는다.

## 1. 기본 원칙과 적용 범위

새 블로그·홈페이지 원문은 **독자 질문 → 확인된 직접 답 → 근거 있는 비교·판단 기준 → 독자가 확인할 자료 → 다음 행동 하나**가 연결되도록 쓴다. 이는 판단의 흐름이지 고정 목차·문단 수·글자 수·FAQ 의무가 아니다. 이미 좋은 제목·도입·사례는 보존하고 법률 조건을 빼서 짧게 만들지 않는다.

기존 `docs/blog-authoring-spec.md`의 A/B/C 경로와 `docs/content-architecture-system.md`의 Traffic / Authority / Revenue 역할을 그대로 쓴다. 새 스킬·필수 보고서·점수표·JSON 필드를 만들지 않는다. 기본 원칙은 라우터와 편집 스킬의 요약으로 적용하고, 실제 검색 결과 비교나 성과 진단이 필요한 때에만 이 문서의 상세 절차를 추가로 읽는다. 승인 원문의 파생·번역에서는 새 검색정보로 사실을 바꾸지 않는다.

Google은 독자에게 도움이 되는 독창적이고 신뢰할 수 있는 내용을 권하며, 타 글을 요약·재작성하는 데 그치지 않고 추가 가치를 제공하는지 묻는다. AI 이용 자체가 아니라 가치 없는 대량 생산 등 사용 방식이 문제다. 이것이 특정 문체·템플릿의 순위 보장을 뜻하지는 않는다. [1][2]

## 2. 작성 전: 실제 독자 질문과 업무 적합성

기존 brief 또는 작업 메모에 주 독자, 해결하려는 질문, 직접 답, 이번 글의 추가 가치, 실제 업무와의 관련성, 다음 행동을 짧게 정한다. 기존 글감관리표·`research/`·익명화된 고객 질문·`state/reader-language.md`가 있으면 재사용한다. 제공되지 않은 고객 발언·검색량·유입량은 만들지 않는다.

ETHOS의 기본 목표는 AdSense 광고 수익이 아니라 독자 이해·신뢰·업무범위에 맞는 적합 문의다. 검색량이나 광고 단가만 높은 무관한 금융·보험·법률 주제로 확장하지 않는다. Traffic 글은 관련 독자의 유입, Authority 글은 판단 과정과 신뢰, Revenue 글은 서비스 적합성 판단이라는 각 역할로 평가한다. 모든 글에 즉시 수임이나 영업 문단을 요구하지 않는다.

일상·후기 자체를 저품질로 취급하지 않는다. 해당 독자에게 실제 도움이 될 때만 비교·문제 해결형 질문으로 바꾼다. 예를 들어 '화장품 창업 후기'를 'OEM을 맡길 때 제조업자와 책임판매업자의 서류는 어떻게 구분할까?'라는 검토 질문으로 좁힐 수 있다. 이는 제목 기획 예시이며 법률 결론·실제 사례·확인된 검색수요가 아니다. 답과 적용 조건은 공식 근거로 별도 확인한다.

## 3. 상위 글 분석: 복제가 아니라 빠진 답 찾기

새 주제 기획, 검색 의도 불일치가 의심되는 글, 사용자의 명시적 경쟁 글 분석 요청에서만 필요한 범위의 실제 검색 결과를 확인한다. 매번 모든 원고에 검색·경쟁 분석을 강제하지 않는다.

- 검색어·검색엔진·확인 시점·가능한 언어/지역/기기 조건과 열어 본 URL을 기존 메모에 남긴다. 광고·일반 검색·블로그 영역을 구분하고 관찰 당시 결과일 뿐 고정 순위라고 하지 않는다.
- 제목이 약속한 답, 도입에서 해결하는 질문, 본문의 근거·비교 기준·문단 흐름, 결말의 행동을 읽는다. 검색 스니펫만 봤다면 본문 분석으로 기록하지 않는다.
- 공통 독자 질문과 덜 설명된 조건·예외·서류 대조·후속 행동을 찾아 ETHOS가 근거를 갖고 추가할 내용만 정한다. 제목·표현·문단 배열을 그대로 베끼거나 여러 글을 짜깁기하지 않는다. 상위 노출을 내용의 진실성이나 수익성의 증거로 삼지 않는다.
- **타인의 매출·방문자·전환율은 공개 검증 자료 없이는 알 수 없다.** 외부 글은 구조와 가설만 비교하고 '돈 버는 글'로 단정하지 않는다. 자체 성과 비교도 사용자가 제공하거나 접근을 허용한 실제 자료만 쓴다.
- 검색·본문 접근을 못 했으면 **검색 결과 미확인**이라고 기록한다. 기존 검증 근거로 초안은 쓸 수 있지만 분석한 척하거나 예상 순위·CPC·검색량을 만들어 채우지 않는다.

네이버도 키워드 남용, 낚시성 제목, 저부가가치 대량 생성, 스크래핑 등을 스팸 사례로 안내한다. 따라서 위 분석의 목적은 문장 복제가 아니라 독자의 미해결 질문 발견이다. 웹마스터 정책을 네이버 블로그의 상세 순위 공식으로 확대하지 않는다. [3]

## 4. 집필·편집: 답과 판단을 앞세우되 칼럼의 호흡 보존

제목은 실제 독자의 질문과 본문의 답이 일치하게 쓴다. 자극적인 '무조건', '상위 1%', '3주 수익 보장'을 붙이지 않는다. 네이버의 시리즈명·회차 표시와 홈페이지의 독립 질문형 제목은 기존 채널 명세대로 구분한다.

도입은 독자의 상황을 짚고 확인된 핵심 답을 불필요하게 미루지 않는다. 긴 공포 유발·성과 자랑·배경 설명으로 답을 감추지 않는다. 모든 글을 같은 질문형 첫 문장으로 시작하거나 무조건 한 문단으로 요약하지 않는다.

본문은 독자가 실제로 결정할 비교 기준과 적용 조건을 설명한다. 필요할 때 문서의 어느 항목을 대조할지, 무엇이 달라지면 결론이 바뀌는지, 어떤 자료가 추가로 필요한지 보여 준다. 표·체크리스트·도식은 설명에 도움이 될 때만 쓰며 독창성을 위해 새 사실·수치·상담 경험을 발명하지 않는다. 공식 법률 근거와 경쟁 글의 표현은 구분한다.

끝에서는 독자가 직접 할 범위와 전문가 검토가 필요한 경계를 보여 주고, 허용된 채널에서만 준비 자료와 실제 확인할 내용을 연결한다. 기존 네이버 무료 검토 안내·상담 이미지 4개·3줄 요약·태그 순서를 보존한다. 리멤버 커넥트의 직접 영업 CTA 금지 등 채널 예외도 유지한다. SEO를 이유로 연락처·링크·CTA를 반복 삽입하지 않는다.

기존 편집·윤문·의미 재검증에서 '질문에 답했는가, 조건과 근거가 빠지지 않았는가, 이 글만의 도움이 있는가'를 함께 확인하고 실제 결함이 해결되면 끝낸다. 새로운 필수 심사 단계나 점수 상승을 위한 반복 재작성을 만들지 않는다.

## 5. 방문자·광고 수익·문의 전환은 다른 지표

발행 후에는 `docs/performance-learning.md`와 `docs/topic-log-integration.md`의 기존 기록에 연결한다. 조회수만으로 매출을 추정하지 않는다.

| 목적 | 실제로 확보했을 때만 볼 지표 | 해석 금지 |
|---|---|---|
| 검색 발견 | 같은 플랫폼의 노출·검색 클릭·검색어·페이지별 추이 | 조회수 증가를 곧 수익 증가로 간주 |
| 독자 신뢰·이해 | 이용 가능한 저장·공유·관련 글 이동·질문의 변화 | 제공되지 않는 완독률이나 고객 의도를 추정 수치로 생성 |
| ETHOS 업무 적합성 | 적합 문의·무료 검토 요청·실제 유료 전환의 집계 | 단일 문의를 글쓰기 효과의 인과 증거로 확정 |
| 별도 AdSense 운영 요청 | 동일 기간·범위의 페이지뷰·페이지 RPM·광고 수익 | 광고주 CPC를 게시자 수익으로 대입 |

AdSense 수입은 트래픽뿐 아니라 콘텐츠, 이용자 지역, 광고 설정 등 여러 변수에 좌우된다. Keyword Planner의 입찰가 범위는 광고주 측 지표이며 게시자의 확정 수익이 아니다. 페이지 RPM은 페이지뷰 1,000회당 예상 수익 지표다. 같은 기간·페이지 범위의 페이지 RPM을 쓸 때만 `예상 수익 = 페이지뷰 × 페이지 RPM ÷ 1,000`으로 역산할 수 있으며, 이 식에 광고 노출 RPM이나 광고주 CPC를 섞지 않는다. 확정 정산·입금·순이익과 예상 수익도 구분한다. [4][5][6]

비교 시 기간 길이·요일·채널·유입원·주제·발행 후 경과 시간을 가능한 한 맞추고, 실제 바꾼 변수와 함께 기록한다. 관찰 전후에는 계절성·검색 변화·광고 승인/설정 변화 등이 섞일 수 있다. 적은 표본과 통제되지 않은 전후 비교는 '가설' 또는 '보류'이며 통계적 A/B 테스트나 수익 보장으로 표현하지 않는다. 개인정보·상담 원문·개별 거래 내역은 공개 저장소에 넣지 않는다.

## 6. '저품질 판정' 대신 확인 가능한 문제 진단

네이버는 '저품질 블로그·최적화 블로그·블로그 지수'가 네이버에서 만든 개념이 아니라고 안내한다. AI가 원고를 읽었다는 이유로 숨은 등급이나 제재 여부를 판정했다고 하지 않는다. 실제로 통지된 제재와 편집상의 약점도 구분한다. [7]

네이버 블로그는 공개·검색 허용 설정과 실제 검색 반영 상태를, 소유 웹사이트는 접근 가능한 Search Console 등의 색인·크롤링·보안·수동 조치 정보를 확인한다. 도구가 없는 채널에 존재하지 않는 진단 화면을 요구하지 않는다. Google 트래픽 감소에는 기술 문제·수요와 계절 변화·순위 변동 등 여러 원인이 있으므로 방문자 감소만으로 글의 문제라고 단정하지 않는다. [8][9]

원고에서는 질문과 답 불일치, 근거 없는 주장, 실제 중복 설명, 오래된 정보, 제목의 과장, 무의미한 키워드 반복, 모바일 읽기 문제를 위치와 함께 지적한다. '공식 지침상 우려', '관찰한 편집 문제', '추가 데이터가 필요한 가설'을 나누고 잘되는 문단은 보존한다. 단순 AI 문체 점수로 색인 제외·패널티·수익 저하를 확정하지 않는다.

## 7. 역할 프롬프트와 성과 주장의 한계

'상위 1% 수익형 블로거처럼'은 전문성과 수익을 검증하는 인증이나 성능 보장 설정이 아니다. 역할보다 독자·목표·실제 자료·검증 기준·금지사항을 구체화한다. ChatGPT도 부정확한 사실·인용을 생성할 수 있으므로 중요한 근거는 원문을 확인한다. [10]

실행 지시는 다음 내용을 기존 brief에 반영한다: 'ETHOS 독자의 실제 질문에 답하라. 검색을 했다면 확인한 페이지와 관찰 조건을 남기고 공통 질문·빠진 답을 구분하라. 실제 자료가 없으면 미확인이라고 하라. 검증된 법률 조건을 보존하면서 비교 기준·문서 대조·다음 행동을 설명하라. 승인본과 채널 형식을 유지하고 광고 수익·검색 순위·문의 증가를 보장하지 마라.'
