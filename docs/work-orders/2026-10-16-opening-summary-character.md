# 실행 지시 — 요약 위치·확인일 표시·이름 있는 예시

## 사용자의 이번 요청
- 앞으로 3줄 요약은 맨 뒤로 옮긴다.
- 발행 본문에 확인 기준일을 넣지 않는다.
- 짧고 약한 도입 대신 독자가 자기 상황을 따라갈 수 있게 도입을 충분히 풀어 쓴다.
- 민수 같은 이름을 가진 예시 인물도 사용하여 스토리텔링과 쉬운 설명을 강화한다.

기존 자연스러운 이야기 흐름·법률 전문성·마케팅과 전환이라는 세 원칙은 유지한다. 이번 요청은 기존 문구를 명시적으로 변경하는 사용자 요청이며 이미 승인·발행한 콘텐츠를 소급 수정하라는 뜻은 아니다.

## 실행 범위
최신 main과 AGENTS.md를 기준으로 필요한 명세만 읽고 최소 변경한다. 기존 전 채널 작업을 다시 계획하지 않는다.

1. 블로그의 기본 배치는 제목 → 독자 상황과 인사 → 충분히 풀어 쓴 도입 → 시리즈 목차와 공통 문장 → 본문 → 무료 검토 안내 1회·기존 상담 이미지 영역 → 3줄 요약 → 태그로 정한다. 첫 5문단 안의 직접 답은 요약 없이 일반 문장으로 자연스럽게 제시한다. 3줄 요약을 맨 뒤로 옮겨도 읽기 전에 답을 숨기지 않는다. 마지막 서술 CTA 규칙은 요약이 그 아래에 오는 새 배치와 모순되지 않도록 정리한다. 기존 4개 상담 이미지의 순서·주소·횟수는 변경하지 않는다.
2. 발행 본문·캡션의 독립적인 확인 기준일/검증 기준일 라벨은 빼되 법령 확인 자체를 생략하지 않는다. 실제 확인일과 근거 판본은 내부 research/검수 기록에 보존한다. 법령 시행일, 판결 선고일, 통계 기간 같은 사실의 일부인 날짜는 삭제하거나 바꾸지 않는다. 웹사이트 관리용 날짜 필드와 코드·스키마는 이번에 변경하지 않는다. 공개 확인일 요구와 내부 확인 기록 요구를 구분해 명세의 충돌을 제거한다.
3. 민수 씨와 같은 이름을 설명을 잇는 인물로 사용할 수 있다. 첫 등장에 '민수 씨가 보습크림 브랜드를 준비하면서 샘플을 받았다면…'처럼 예시임이 자연스러운 문맥으로 드러나게 한다. 별도 '가상의 상황입니다' 안내문은 추가하지 않는다. 가상의 이름 사용 자체와 실제 고객·수임·후기·성과 창작을 구분한다. 실제 상담을 받은 인물처럼 소개하거나 가상의 승인을 실제 성과처럼 쓰지 않는다. 매 글에 인물을 강제하거나 모든 문장에 이름을 반복하지 않는다.
4. 도입과 예시에서는 사람이 문서를 받고 읽고, 다른 부분을 발견해 다음 일을 정하는 순서로 설명한다. 이름만 붙인 법령 나열로 되돌리지 않는다. 답·숫자·주체·조건·예외는 유지한다. 긴 도입을 위해 감정·손실액·창업 성과를 만들지 않는다. 새 고정 글자수·점수·예시 개수는 추가하지 않는다.
5. 블로그·웹사이트의 요약 위치와 표현, 카드/SNS의 예시·공개 확인일 문구를 각 빠른 명세에서 일관되게 해석할 수 있도록 필요한 범위만 연결한다. 3줄 요약이 없는 짧은 SNS나 카드에 새 요약 블록을 강제하지 않는다. 카드의 마지막 CTA 등 고유 구조는 유지한다. 승인 원문에 없는 인물이나 사건을 파생 단계에서 새로 만들지 않는다. 언어별 현지화에서도 사실과 업무범위를 유지한다.

## 분업과 보호범위
계획은 확정되어 있다. 지원되는 빠른 하위 에이전트에 A(블로그·웹사이트)와 B(SNS·카드·공통 문체의 충돌)를 분리 배정하고, 조정자가 공통 기록과 결과를 통합한다. 지원하지 않는 모델 배정이나 병렬 실행을 했다고 보고하지 않는다. 필요 문서만 읽고 중복 전면 윤문·새 도구 탐색·전체 원고 재작성·이미지 렌더링은 하지 않는다.

기존 승인/예약 콘텐츠, 렌더러·CSS·스키마·카드 한도, 상품·가격·접수 URL은 변경하지 않는다. 이번 브랜치에서만 작업하고 main 직접 쓰기·자동 병합·발행·새 유료 API 호출은 하지 않는다. 작업지시서 외 현재 원고 파일은 이 PR에 없다. 원문이나 법률 정보가 필요하면 저장소에서 확인 가능한 자료만 이용하고 없는 자료를 채우지 않는다.

## 확인과 제출
- 기존 검사로 지침 충돌을 점검한다. 사용자 요청으로 수정한 고정 명세만 해당 절차에 따라 지문을 갱신하고, 관계없는 freeze 불일치는 별도 보고한다.
- 규칙을 검사 통과용으로 광범위하게 완화하지 않는다. 확인일을 공개 본문에서 내부 검수로 옮기는 의도와 숫자·조건 보호는 유지한다.
- 법률 사실을 새로 만들지 않는 짧은 예시로 도입에서 답이 보이고 이름이 있는 인물을 자연스럽게 따라갈 수 있는지 확인한다. 조건형 예시를 실제 성과처럼 표현하지 않았는지도 확인한다.
- 완료 시 변경 파일, 실제 검사 결과, 대표 변경 문장, 사용한 에이전트 구성, 커밋과 남은 제한만 짧게 보고한다. 문구만 기록한 상태와 구현·검증·main 병합 상태를 구분한다.
