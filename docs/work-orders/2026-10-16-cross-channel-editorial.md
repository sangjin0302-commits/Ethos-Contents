## 1. 목적 — 계획을 다시 만들지 말고 실행

기존 ChatGPT Astra 계획을 실행한다. 이번 화장품 원고 하나가 아니라 앞으로의 새 글·후속편·새 시리즈·수정본과 모든 파생 콘텐츠에서 다음 세 요소를 함께 살린다.

1. 자연스러운 스토리텔링: 독자가 자료를 받고 읽고 막힌 부분을 풀어 다음 일을 정하는 흐름으로 이해한다.
2. 법률적 전문성: 검증된 주체·대상·의무·재량·조건·예외·숫자·출처를 유지하며 어려운 용어를 풀어 설명한다.
3. 마케팅과 전환성: 유용한 답을 준 뒤 직접 할 일, 에토스에 맡길 실제 작업, 다음 행동을 이해할 수 있다.

블로그·웹사이트 칼럼·카드뉴스·카카오톡·LinkedIn·Instagram 캡션·Threads·X·숏폼 대본 및 자막에 공통 적용한다. 국문·영문·아랍어 등 언어가 달라도 의미와 서비스 범위는 같게 유지하고 표현은 현지화한다. 세 요소를 모든 문장에 몰아넣지 않는다. 카드와 숏폼은 세트/대본 전체에서 구현한다.

## 2. 실행 모델과 하위 에이전트 분담 — 이번 사용자의 우선 요구

계획은 이미 작성되었다. 상위 고추론 모델이 같은 계획과 저장소 전체 조사를 길게 반복하지 않는다. 실제 편집·샘플·검사 작업은 사용 가능한 하위 실행 에이전트에 분담한다.

- 이 환경에서 지원하는 빠른 실행 모델을 사용한다. 문서 편집은 낮음 또는 중간 추론 강도를 우선하며 법률 조건 충돌처럼 결론에 영향을 주는 부분만 검토 강도를 높인다. 접근할 수 없는 모델명이나 설정을 추측하지 않는다.
- 실행 조정자는 파일 소유권 배정·통합·최종 보고를 맡는다. 원고 전체를 직접 여러 번 재작성하지 않는다.
- A 에이전트: docs/blog-authoring-spec.md, docs/website-md-spec.md, docs/language-quality-workflow.md의 필요한 조항만 수정한다.
- B 에이전트: docs/card-authoring-spec.md, docs/sns-authoring-spec.md의 필요한 조항만 수정한다.
- C 에이전트: 읽기 전용으로 먼저 충돌·보호범위와 기존 테스트를 확인하고, A/B 결과가 통합되면 실제 검사와 매체별 샘플을 검증한다. 샘플은 examples/writing/cross-channel-three-pillars-20261016.md 한 파일만 담당한다.
- A/B는 서로 다른 파일을 병렬 편집한다. 같은 파일을 두 에이전트가 동시에 고치지 않는다. C의 최종 검증은 수정본 통합 이후에 수행한다.
- AGENTS.md, MANIFEST.md, CHANGELOG.md 및 필요한 고정 지문 갱신은 실행 조정자만 수행한다. 동시 에이전트는 최대 3명, 재귀적인 추가 에이전트 생성은 하지 않는다.
- 하위 에이전트 또는 모델 선택을 실제로 사용할 수 없다면 그 제한을 보고한다. 순차 실행을 병렬 실행으로, 프롬프트의 모델 요청을 실제 모델 배정으로 보고하지 않는다. 이 작업 때문에 전역 설정·새 유료 API·시크릿·권한을 변경하지 않는다.
- 최종 보고에는 실제 생성한 에이전트의 역할, 확인 가능한 실제 모델/추론 설정(확인 불가 시 명시), 변경 파일과 검사 결과를 간단히 남긴다.

## 3. 필요한 지침만 읽기

MANIFEST.md와 AGENTS.md의 최신 기준을 먼저 확인하고 담당 파일만 묶어서 읽는다. examples/writing/README.md는 기존 표현 예시로 활용한다. 긴 guidelines/ 전체, archive/, vendor 전체를 일괄 조회하지 않는다. 특정 충돌이 있을 때만 해당 원문을 추가로 확인한다.

이미 블로그에 업무 흐름·조건형 예시 원칙이 있고 다른 채널에도 쉬운 설명과 실제 수행 업무 원칙이 있을 수 있다. 있는 내용을 재사용한다. 과거의 PENDING 패치를 그대로 덮어쓰지 않는다. 새 공통 문서를 여러 개 만들지 말고 기존 문서에 최소 변경한다.

## 4. 각 채널의 빠른 명세만 읽어도 놓치지 않을 내용

### 이야기와 쉬운 설명

법령 항목을 나열한 뒤 예시를 장식처럼 끼워 넣지 않는다. 실제 업무에서 만나는 상황을 먼저 놓고 답과 이유를 이어간다. 예시 다음 문단도 독자의 말로 설명하며 정합성·적용 가능성·종합 검토 같은 추상어만 반복하지 않는다.

발행 본문·카드·캡션·자막에 '설명을 위한 가상 상황입니다', '가상의 사례입니다', '실제 상담 사례가 아닙니다' 같은 독립 안내문을 넣지 않는다. '신청서와 증명서의 이름이 다르다면?'처럼 조건문으로 예시임을 드러낸다. 안내문만 지우고 허구를 실제 사건처럼 바꾸지 않는다. 꾸며낸 고객 이름·상담 대화·감정·수임 성과는 쓰지 않는다.

모든 글에 같은 등장인물이나 이야기 틀을 강제하지 않는다. 수수료·기한·필수서류는 바로 찾을 수 있는 목록과 설명으로 남긴다. 자연스러움은 문장마다 줄바꿈하거나 짧은 메모체로 만드는 일이 아니다.

### 법률 전문성

법령·판례·통계는 작성 시점의 공식 근거에 따라 확인한다. 이미 확인된 원문의 파생은 Source Lock을 지키고 새로운 조건·수임 사례·서비스를 만들지 않는다. 법정 용어는 뜻을 붙여 유지한다. 법률상 '또는', '이하', '수 있다', 주체·기간·예외를 문체나 압축 때문에 삭제하지 않는다. 법적 판단이 없는 생활 장면을 새로운 법률 결론의 근거로 쓰지 않는다.

### 마케팅과 전환

'검토합니다'에서 멈추지 않고 어느 자료로 어떤 작성·제출 작업을 하는지 보여준다. 실제 제공 범위와 원문에 근거가 있는 작업만 설명한다. 법률을 몰라 막힌 독자와 내용을 이해했지만 서류 작업을 맡기려는 독자를 함께 고려한다.

Traffic·Authority·Revenue는 주된 역할의 구분이지 나머지 두 요소를 생략하라는 분류가 아니다. Traffic 글의 의뢰 판단을 모두 나중의 Revenue 글로 미루지 않는다. 다만 모든 정보에 상담을 억지로 끼워 넣지도 않는다.

무료 사전 검토에 보낼 자료와 먼저 확인할 결과를 구체화하고 유료 작성·제출과 구분한다. 자료를 전부 완성해야 문의할 수 있는 것처럼 쓰지 않되 무자료 검토·미확인 보고서·처리기한·등록 성공·보완 대행을 새로 약속하지 않는다. 채널별 기존 CTA 횟수와 링크 배치를 유지한다.

## 5. 매체별 구현

- 블로그: 기존 제목과 도입 순서를 보존하고 업무 진행과 조건 비교로 읽히게 한다. 본문 8,000~11,000자, 후반 무료 검토 한 번, 기존 상담 이미지 4개와 연결 주소를 유지한다.
- 웹사이트: 확인 기준일과 요약 이후 유용한 상황과 실제 작업을 살린다. 인사·목차를 없앤다는 이유로 예시와 맥락까지 삭제하지 않는다. 기존 MD 규격을 유지한다.
- 카드뉴스: 상황→답→조건 비교→자료와 실제 작업→다음 행동을 세트 전체로 구현한다. 한 장 한 메시지, 쉼 카드, 원문 법률 한정어와 JSON 최소 골격, 글자 한도를 유지한다. 한도 초과는 문구의 불필요한 부분을 줄이거나 기존 허용 구성 안에서 나누며 규칙을 완화하지 않는다.
- 카카오톡: 받은 서류나 막힌 일 한 가지에서 직접 답과 이유로 이어간다.
- LinkedIn: 기업 담당자의 실제 결정 문제를 중심으로 국문·영문·아랍어를 현지화한다. 복사용 text 코드 블록과 실제 빈 줄, 기존 글자수 한도를 지킨다.
- Instagram 캡션: 카드를 전부 되풀이하지 않고 어느 상황에 쓰는 기준인지와 다음 행동을 보탠다.
- Threads·X: 한 상황, 직접 답, 생략하면 안 되는 조건을 짧게 연결한다. 원문/배포 영역은 채널 지침에 따른다.
- 숏폼: 장면과 판단·행동이 이어지는 대본/자막으로 만들며 핵심 법률 조건을 누락하지 않는다.

## 6. 실제 샘플과 기존 오픈소스로 검증

새 지침 문장을 넣은 것만으로 완료하지 않는다. 동일한 원문에서 짧은 비교 샘플을 만든다. 전체 블로그를 다시 쓰거나 HTML·PNG를 렌더링하는 작업은 아니다.

샘플 입력은 저장소에서 확인되는 화장품 시리즈의 기존 원문을 읽기 전용으로 사용한다. ③편 원문이 실제 저장소에 없으면 이전 채팅의 /mnt/data 파일에 접근할 수 있다고 가정하지 말고, 확인 가능한 content/TEST-COSMETICS-MANAGER-02/blog.md와 국문 카드 원문을 대조용으로 사용한다. 테스트 원문을 정식 승인본 또는 실제 수임사례로 표기하지 않는다. 근거가 불확실한 법률 결론은 임의 보강하지 말고 별도 미확인 항목에 둔다.

샘플: 블로그의 3~5문단 전후 비교, 카드 문구 6~10장 개요(실제 카드 JSON/발행 세트 아님), 카카오톡 한 편, LinkedIn 영문 한 편과 핵심 문단 아랍어, Instagram 캡션·Threads 또는 X·숏폼의 짧은 예시 및 웹사이트 요약 연결. 예시 개수는 이번 검증용이지 향후 발행 규칙으로 추가하지 않는다.

예시에서 확인할 것: 장면 이후도 읽히는가, 법률 조건은 같은가, 실제 맡길 작업과 다음 행동이 드러나는가. 새 점수·어미 비율·필수 도구 호출 규칙을 만들지 않는다.

이야기 구조는 초안에서 만든다. 윤문이 필요한 문단에만 examples/writing/README.md와 vendor/im-not-ai/quick-rules.md를 적용한다. 같은 원고를 여러 도구로 전면 재작성하지 않는다. 규칙집 열람, 자동 프로그램 실행, 실제 제안 반영은 구분해 보고한다. 새 도구·유료 API를 설치하는 것이 목적이 아니다.

## 7. 보호범위·검사·종료

이 PR 브랜치에서 작업하고 main에는 직접 쓰지 않는다. 기존 승인/예약 콘텐츠·소재표·콘텐츠ID·상품·가격·접수 경로·렌더러·CSS·글꼴·스키마·글자 제한·검사 임계값은 변경하지 않는다. 외부 계정이나 웹사이트 저장소로 범위를 넓히지 않는다. 역할 분담과 사람의 최종 승인 요건도 유지한다.

실제로 존재하는 검사와 사용법을 확인해 실행한다.

- python scripts/validate_guidelines.py
- 변경한 작성 명세가 고정 대상일 때만: python scripts/design_freeze.py --update --note "사용자 요청: 전 매체의 이야기·법률 전문성·전환성 및 조건형 예시 연결"
- python -m pytest tests/test_design_freeze.py

고정 지문 갱신은 이번에 허용된 문서 변경만 반영한다. 무관한 기존 불일치를 한꺼번에 승인하지 않는다. 검사가 실패하면 원인을 구분해 해당 부분만 고치고 통과를 위해 보호규칙을 낮추지 않는다. 미실행 검사는 미실행으로 보고한다.

완료 시 같은 PR에 구현 커밋을 추가하고 변경 파일, 대표 전후 예시, 실제 테스트 결과, 하위 에이전트 실행 근거, 남은 제한을 짧게 보고한다. 자동 병합·실제 콘텐츠 발행은 금지한다. 단순 PR/지시서 생성과 구현·검증 완료를 구분한다.
