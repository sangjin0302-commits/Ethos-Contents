# 글감관리표 기반 소재 선정

글감관리표는 아이디어 목록이 아니라 발행 이력과 실제 반응을 연결하는 운영 자료다. 소재를 새로 정할 때 docs/topic-discovery.md와 함께 사용한다. 조회수가 높은 제목을 그대로 반복하지 않고, 어떤 문제에서 검색·재방문·문의가 생겼는지 확인해 다음 판단 질문으로 확장한다.

## 입력 자료

기준은 사용자가 지정한 최신 에토스 글감관리표다. 연결된 Google Sheets를 우선하고, 연결할 수 없을 때만 사용자가 제공한 최신 파일을 사용하며 기준일을 밝힌다. 분석 요청만으로 원본을 수정하지 않으며, 편집을 별도 승인받은 경우에도 기존 기록을 재사용한다. 아래 기록·식별자·상품 승인·지표 정의가 시트 연동의 단일 기준이다.

### 소재 관리(블로그 기준)

- 소재명
- 영역
- 상태
- 발행일
- K열 발행 글 URL(현재 글 자체의 네이버 주소; G열 본문 내부링크 대상과 구분)

제목이 없는 예약 행이나 서식만 남은 빈 행은 후보로 사용하지 않는다. 발행완료는 중복 확인과 최신화 판단에 사용하고, 기획은 제목과 근거가 실제로 입력된 행만 신규 후보로 사용한다. 기존 개선 상태·메모에 보류가 지정된 행은 C열이 기획이어도 자동 재편성하지 않는다.

## 기록 재사용과 식별자

- 이미 입력한 발행 URL, 문의 건수, 유입글을 다른 표에 다시 입력하도록 요구하지 않는다. 기존 열·승인 연결·운영 시스템의 기록을 참조하고 중복 집계를 막는다. 열 위치는 현재 헤더와 대조한다.
- 상품 연결의 정본은 시트 `발행글_상품연결`의 명시적으로 승인된 연결이다. `소재 관리(블로그 기준)` L열은 동일 콘텐츠의 승인 상품 ID를 참조해 표시한다. URL이 있다는 이유나 제목 정규식만으로 승인을 만들지 않는다. 다중 승인·충돌·미확인은 임의 선택하지 않고 확인 대상으로 남긴다.
- `content_id`는 저장소·시트·운영 시스템에서 이미 쓰는 실제 콘텐츠키를 우선하고 원본 근거를 확인한다. `BLOG-R<행번호>`처럼 행 위치에서 만든 값은 행 삽입·정렬에 취약하므로 행번호로 다시 계산하거나 안정키로 단정하지 않는다. 기존 키는 재발급하지 않고 원문 URL과 기존 연결을 대조한다.
- 기존 실제 ID가 없고 발행된 네이버 URL을 확인했으면 URL의 실제 `logNo`에서 `naver-<logNo>` 같은 안정 식별자를 검토한다. URL 형식·블로그 소유자·글 일치와 중복을 확인하고 기존 추적키와의 대응을 보존한다. 아직 발행되지 않은 글 번호는 추정하지 않는다. 안정키 전환·별칭 연결은 별도 승인된 동기화 작업으로 다룬다.
- 빈칸은 미입력·미확인, 숫자 `0`은 해당 기간에 없음을 확인한 값이다. 서로 바꾸지 않는다. 링크 상태의 `점검 필요` 역시 링크 오류를 뜻하지 않으며 실제 클릭·목적지를 확인한 뒤 갱신한다.
- GitHub에는 운영규칙과 공개 자료만 기록한다. 실제 문의내용·개인정보·미공개 조회수·문의·수임·매출 데이터를 복제하지 않는다. 익명화만으로 저장소 공개를 허용하지 않으며 근거 카드의 내부 실적은 권한 있는 시트·운영 시스템에 둔다. 공개 가능한 주제·자료와 내부 성과의 저장 위치를 분리한다.

## 발행 확인 후 상품 검토 게이트

새로운 상품 후보 ID와 시험가격은 글감 단계에서 만들지 않는다. 먼저 `소재 관리(블로그 기준)`의 C열이 `발행완료`인지, K열 `발행 글 URL`에 해당 글의 네이버 블로그 주소가 있는지 확인한다. URL이 실제로 열리고 행 제목과 같은 글인지 표본이 아닌 해당 글을 확인한다. 발행 예정일이나 원고 완성만으로 통과시키지 않는다.

`발행글_상품연결`의 J열은 원본 K열 URL을 참조하고 K열은 발행 상태와 URL 형식으로 `상품 검토 가능` 또는 `발행 URL 대기`를 표시한다. `행정상품_후보` S열도 같은 게이트를 콘텐츠키로 조회한다. 이 표시는 후보 검토의 시작 조건일 뿐 법률·업무범위·가격 승인이나 공개 승인이 아니다.

게이트를 통과하면 먼저 기존 승인상품과 공개 웹 안내가 대상·받을 자료·확인 결과·상담 안내를 충족하는지 확인한다. 충분하면 새 상품 ID·새 페이지·중복 네이버 Revenue 글을 만들지 말고 연결만 개선한다. 새로운 고객 문제와 별도 산출물·작업 범위가 확인된 경우에만 신규 상품 후보를 작성한다. 이후 법령·직역 경계, 실제 소요시간, 원가와 공개가격을 검증한 뒤 별도로 판매 승인한다. 발행완료 + 실제 해당 네이버 URL 확인은 검토 시작 조건이고, 명시적 상품 연결 승인 + 판매·공개 승인은 별도 조건이다. 발행만으로 자동 상품화·공개하지 않으며, 미승인 상품 ID를 발행용 CTA 목적지에 넣지 않는다.

미발행·URL 미확인 후보는 내부 아이디어로 보존하고 판매·공개 대상으로 승격하지 않는다. 특정 행번호나 과거 상태를 문서에 고정하지 않고 실행 시 최신 원본과 승인 상태를 확인한다.

### 주간 성과

- 기준주, 조회수, 재방문율, AI 인용 누적
- TOP1~TOP3 제목과 조회수
- 문의 건수와 유입글
- 업무군별 체크, 메모

조회수와 AI 인용은 관심 신호일 뿐 수임·전문성의 증거로 확대하지 않는다. 문의 유입글이 기록되어 있으면 조회수보다 우선하되, 개인정보와 상담 내용을 소재로 옮기지 않는다.

## 검색수요 증거를 먼저 붙이기

신규 시리즈 또는 글감 묶음을 정할 때 `docs/sustainable-growth-system.md`의 검색수요 증거 카드를 작성한다. 최소한 검색어 묶음, 확인일, 비교기간, 상대 추세, 실제 노출·클릭 여부, 내부 문의 신호, 판단과 재검토일을 남긴다.

- 네이버 데이터랩 ratio는 절대 검색량이 아니라 비교기간 내 상대값으로 기록한다.
- 네이버 서치어드바이저는 웹사이트 웹 검색 데이터이며 VIEW·블로그 검색 전체 수요로 확대하지 않는다.
- 도구별 숫자는 범위와 지연이 달라 서로 합산하지 않는다.
- 검색수요가 높고 문의가 아직 없으면 버리지 않고 Entry 역할과 Core·Revenue 연결을 먼저 점검한다.
- 화장품 시리즈는 검색수요 확인 뒤 편성된 기준 사례로 취급하며 예정 발행을 유지한다.

## 후보 만들기

표를 읽은 뒤 후보를 다음 네 유형으로 나눈다.

1. **확장**: 여러 주에 반복해서 TOP3에 든 기존 글을 더 구체적인 조건·문서·순서 질문으로 확장한다.
2. **전환**: 실제 문의 유입글과 연결된 주제를 Reader Boundary, Proof of Work, 구체적 무료 검토 항목이 있는 글로 보강한다.
3. **최신화**: 발행 후 법령·고시·기관 안내가 바뀌었거나 재검토일이 지난 글을 갱신한다.
4. **공백 보완**: 성과가 좋은 Entry 주제와 연결되지만 아직 없는 Core·Composite·Recurring B2B 질문을 만든다.

같은 제목의 후속편을 기계적으로 만들지 않는다. 분류 경계·제도 교차·순서 의존성·문서 정합성·기관 분산·보완 가능성·반복성·국제화 마찰 가운데 새로운 판단 긴장이 있어야 한다.

## 우선순위 점수

점수는 발행을 막는 하드 게이트가 아니라 후보 비교용이다.

| 항목 | 점수 | 판단 기준 |
|---|---:|---|
| 검증된 검색수요 | 0~25 | 상대 추세와 실제 노출·클릭 등 둘 이상의 신호가 있는가 |
| 문의 연결 | 0~25 | 유입글 또는 밀접한 후속 질문이 실제 문의와 연결됐는가 |
| 반복 관심 | 0~15 | 여러 주 TOP3, 재방문 또는 저장·공유 신호가 반복됐는가 |
| 희소성과 브랜드 적합 | 0~15 | 희소성 신호와 신사업 인허가·국제화 축이 만나는가 |
| 전환 가능성 | 0~10 | 받을 자료와 확인 결과를 구체적으로 제시할 수 있는가 |
| 최신성 필요 | 0~5 | 제도 변경 또는 장기 미갱신 때문에 다시 확인할 가치가 있는가 |
| 포트폴리오 공백 | 0~5 | Entry에서 Core·Composite·Recurring B2B로 이어지는 빈칸을 채우는가 |

다음 경우에는 점수와 무관하게 보류한다.

- 공식 1차 자료로 확인할 수 없는 주제
- 기존 글과 판단 질문이 실질적으로 같은 주제
- 경험담·수임 성과·고객 반응을 만들어야만 성립하는 주제
- 현재 자격과 업무 범위를 넘어서는 결론을 요구하는 주제

## 선정 결과 기록

선정한 소재는 brief.md에 다음을 남긴다.

- 어떤 표와 어느 기간을 확인했는지
- 신규·확장·최신화·재가공 가운데 무엇인지
- 반복 관심과 문의 연결 근거
- 기존 글과 달라지는 판단 질문
- 상위 허브, 이전 글, 다음 글, CTA 경로
- 확인일, 갱신 조건, 재검토 예정일

성과표가 없거나 최신 상태를 확인하지 못하면 그 사실을 적고 docs/topic-discovery.md의 질적 기준으로 진행한다. 표가 없다는 이유로 콘텐츠 생성을 중단하지 않는다.

## 마케팅 점검 (주간 성과 탭)

마케팅·성과 분석, 채널·시리즈·표지 방향을 정할 때도 이 표의 **주간 성과** 탭을 기준 자료로 쓴다. 아래 값을 직접 계산해 숫자로 보고한다. 표를 읽지 못했으면 읽은 것처럼 말하지 않는다.

| 지표 | 계산 | 보는 이유 |
|---|---|---|
| 조회 추세 | 최근 3주 평균 ÷ 직전 최고 3주 평균 | 유입이 늘고 있는지 |
| 블로그 문의 참고율 | 같은 기간·같은 블로그 범위의 유입이 확인된 문의 건수 ÷ 해당 블로그 조회수. 분자·분모·귀속 기준·누락을 함께 표시 | 조회수는 방문자 수가 아니므로 방문자 전환율로 부르지 않음 |
| 문의 유입 주제 | 유입글을 영역(비자·인허가·행정심판·법인·계약·강연)으로 묶어 건수 | 무엇이 실제 문의를 만드는지 |
| 조회 상위 주제 | TOP1~3에 두 주 이상 든 주제와 영역 | 무엇이 관심을 끄는지 |
| 관심과 문의의 어긋남 | 유입글이 기록된 기간에서, 조회 상위 주제 중 유입글로 한 번도 기록되지 않은 주제. 유입글이 빈칸·미상인 문의는 "출처 미상 n건"으로 따로 센다 | 표지·CTA·대상 독자를 고칠 후보 |
| 시리즈 성과 | 시리즈별로 TOP3에 든 편 수. 제목에 시리즈명이 있거나 표에 시리즈 열이 있을 때만 계산하고, 소속을 추측하지 않는다 | 어떤 시리즈 형식이 통하는지 |
| AI 인용 증가 | 주간 증가분, 정체 주 수 | 웹사이트·AI 검색 쪽 성과 |

판단 원칙:
- 전체 문의에는 웹사이트·강연·소개·메신저 등 다른 경로가 섞일 수 있다. 전체 문의 ÷ 블로그 조회수를 블로그 전환율로 계산하지 않는다. 기간·범위·귀속이 맞지 않거나 미입력이 있으면 계산 불가 또는 확인된 일부만 표시하고 이유를 적는다. 분모가 0이면 비율은 산출하지 않는다.
- 문의가 기록된 주제를 조회 상위 주제보다 우선한다. 조회만 높은 주제는 표지·대상 독자·마지막 안내를 고칠 후보다. 출처 미상 문의가 많으면 어긋남 결론을 내리지 않고 출처 기록부터 보완한다.
- 이 탭은 전체 추세와 주제 단위 보조 자료다. 세트별 Primary Objective(저장·프로필 방문 등) 판단은 `docs/performance-learning.md`를 따르되 미공개 성과값은 내부 시트·운영 시스템에 두고 GitHub의 성과로그에 복제하지 않는다.
- 표본이 작다(주당 문의 0~2건). 세 주 이상 같은 방향일 때만 결론으로 쓰고, 그 전에는 가설로 적는다(`docs/performance-learning.md`).
- 결과는 "다음 4주에 바꿀 것 1~3개"로 끝낸다. 예: 생활 장면형 표지를 비자 시리즈에 적용, 강연 직후 관련 글 발행.

기존 시리즈명·유입글·문의 건수·채널·`content_id`와 운영 시스템의 상담·견적·수임 기록을 먼저 활용한다. 새 열이나 중복 입력을 기본 해결책으로 제안하지 않는다. 추적 규칙은 `docs/strategy-playbook.md` 5절, 네이버 하단 이미지 링크설정은 `docs/blog-authoring-spec.md` 6-1절을 따른다. `/admin/funnel` 기록도 실제 경로에서 식별자가 보존됐는지 확인한 뒤 기존 유입글과 대조한다. 자동 추적과 수동 기록이 같은 문의면 한 건으로 세며, 충돌하면 확인 대상으로 남긴다. 시트에는 필요한 주간 집계만 참조하고 원래 유입글을 덮어쓰지 않는다.

## 영업 퍼널 확장 열

글감관리표 `주간 성과` 탭의 N:Z는 조회수 다음 단계인 영업 성과의 주간 집계 위치다. 상담·견적·수임의 개별 원본은 운영 시스템에서 재사용하며 사용자에게 중복 입력을 요구하지 않는다.

| 열 | 기록 |
|---|---|
| N~R | 유효문의, 상담·미팅, 견적 발송, 수임, 확인매출 |
| S~T | 유효문의→수임률 자동 계산, 첫응답 24시간 준수율 |
| U~V | 현재 비활성. 공란 허용(제휴 채널 재개 시에만 사용) |
| W~Z | 수임 유입경로, 이번주 병목, 다음주 1순위 영업액션, 실험 결과 |

과거 빈칸을 0으로 추정하지 않는다. 새 주차부터 실제 값만 기록한다. 이번주 병목은 `유입 부족 / 유효문의 부족 / 상담 전환 부족 / 견적 전환 부족 / 수임 전환 부족 / 후속관리 부족 / 정상` 중 하나만 선택한다. 다음주 행동도 한 가지로 제한해 무엇이 영향을 줬는지 알 수 있게 한다.

## 제휴 파이프라인 탭 (현재 비활성)

사용자 결정에 따라 제휴 후보 발굴과 외부 파트너 접촉은 현재 실행계획에서 제외한다. `제휴_파이프라인` 탭은 삭제하지 않고 보관만 하며, 빈 상태를 운영 누락·성과 부진·다음 주 병목으로 판정하지 않는다. 주간 성과의 `제휴 접촉`과 `후속 연락 완료`도 공란을 허용한다.

사용자가 명시적으로 재개하거나 실제 소개 문의가 반복될 때만 기존 단계와 성과값을 다시 사용한다. 재개 전에는 AI가 후보 수, 접촉 건수, 미팅 목표를 제안하지 않는다.
