# 콘텐츠 품질 도구 운용정책

> 2026-10-15 — 개선 2단계: 기본은 가벼운 편집, 복잡한 쟁점만 집중 검토

도구는 반복 검사를 줄이는 수단이지 콘텐츠 판단을 대신하지 않는다. 새 도구는 실제 실패를 줄이는 경우에만 추가하고, 자연스러움·마케팅 점수만으로 발행을 차단하지 않는다.

## 기본 경로와 집중 검토 경로

이 구분은 **도구 사용과 편집의 강도**다. 블로그 명세의 A·B·C는 근거 확인 경로이므로 별도로 유지한다. 가벼운 편집을 선택했다는 이유로 새 법률 주제의 공식 근거 확인이나 변경 여부 확인을 생략하지 않는다.

- **기본 경로**: 채널 명세와 필요한 원문을 읽고 자연스럽게 초안을 쓴다. 초안 뒤에 사실·법률·논리·마케팅을 함께 살펴 수정할 부분을 찾고, 그 부분만 윤문한다. 바꾼 문장과 영향을 받는 요약·결론의 의미를 다시 확인한다. 기본값은 한 작성자가 하는 통합 검토와 부분 편집이며, 항목마다 별도 도구·에이전트·보고서를 만들지 않는다.
- **집중 검토 경로**: 근거끼리 충돌하거나, 여러 법률 조건의 연결이 불분명하거나, 위반차수·기한 계산·업무범위 등 결론을 바꿀 의문이 남을 때 해당 쟁점만 깊게 확인한다. 어떤 결론이 어느 조건 때문에 보류됐는지와 추가로 필요한 근거를 정리하고 공식 자료를 대조한다. 의문이 글 전체에 영향을 미치면 필요한 범위까지 넓히되, 한 문단의 문제 때문에 모든 문체를 다시 쓰지 않는다.
- **오류를 위한 예외는 남긴다**: 한 차례 검토는 기본 운영이지 정확성 검사의 상한이 아니다. 실제 오류나 미확인 근거가 남으면 필요한 확인을 이어간다. 반대로 구체적인 결함이 없으면 점수나 표현 취향 때문에 검토를 반복하지 않는다.

## 도구별 사용 범위

- **im-not-ai v2.3.2 (고정 커밋)**: GitHub PR의 `Prose hints`에서 상위 정량 shim을 읽기 전용으로 실행하여 `route_hint`와 참고 스타일 지표를 남긴다. 이 지표는 AI 작성 판정·법률 검증·발행 승인 근거가 아니다. Codex에서 실제 윤문을 요청받았을 때에는 `.agents/skills/ethos-humanize/SKILL.md`가 상위 공식 전체 경로(진단·윤문·verify_gates·필요 시 finalize)를 연결한다. 기존 `vendor/im-not-ai/quick-rules.md` 직접 부분 편집은 대안으로 유지한다. 도구가 없으면 미실행을 표시하고, 새 유료 API·자동 원고 변경은 활성화하지 않는다. 법률상의 의무·재량·수치·예외와 원문 사례를 보호한다.
- **Solar Human Proofreader MCP (선택형)**: 외부 서비스의 `read_through`·`proofread`·`compare`를 이용하되, 사용자가 요청하거나 기존 통합 검토에서 구체적인 문장·문단 문제를 발견한 경우에만 실행한다. 기본 Prose hints/im-not-ai 검사를 교체하지 않고, 자동 PR 댓글·원문 덮어쓰기·정기 API 호출을 만들지 않는다. GitHub Actions는 사용자 승인 입력이 있는 수동 실행 또는 `docs/human-proofreader-integration.md`의 명시적 요청 브랜치 실행만 허용하며 공개 가능한 국문 원고만 전송한다. 요청 브랜치는 공개 저장과 외부 처리의 동의를 분리하고 원문 SHA-256을 확인한다. 결과만 별도 폴더로 반환하여 ChatGPT가 직접 회수하며 main·승인 원고는 쓰지 않는다. 개인·사건·상담 정보는 외부로 보내지 않는다. 기본 연결은 공개 무료 서비스의 이용가능 범위 내이며 BYOK는 별도 설정·비용 확인 후에만 사용한다. 설정·로컬 법률 토큰 대조·테스트 기준은 `docs/human-proofreader-integration.md`에 둔다. 원격 게이트의 합격이 에토스 의미 재검증을 면제하지 않는다.
- **마케팅 스킬**: 독자의 질문에 답하는지, 어떤 자료로 어떤 일을 하는지, 다음 행동과 무료·유료 범위가 분명한지를 기존 편집에서 함께 본다. `docs/marketing-checklist.md`는 막히는 부분이 있을 때만 참고한다. 외부 스킬의 여러 차례 검토, 전문가 점수 평가, 점수 상승을 위한 재작성은 기본 경로에 가져오지 않는다.
- **논리 점검**: 질문과 답이 이어지는지, 근거가 결론을 뒷받침하는지, 중간에 조건·예외가 빠지지 않았는지를 통합 검토에서 확인한다. 별도 사고 정리 도구는 집중 검토에서도 필요한 경우만 고려한다. 사고 정리 도구의 출력은 법률 근거나 검증 완료의 증거가 아니다.
- **결정론적 검사**: 숫자·조문 비교, JSON 스키마, 링크·렌더 등 각 채널의 필수 검사는 해당 단계의 담당자가 수행한다. 문체 도구를 줄인다고 필수 검사나 사람 승인을 생략하지 않는다. 카드 초안의 역할과 `pass`·`pending` 표기는 카드 명세를 따른다.

이 정책은 새 스킬·MCP 서버의 설치, 유료 API 호출, 시크릿 설정, 외부 서비스로의 비공개 자료 전송을 승인하지 않는다. 이미 운영 중인 자동화의 실행 조건이나 코드도 이 문서만으로 바꾸지 않는다.

## 속도와 종료

요청 유형에 필요한 파일만 한 번에 조회한다. 같은 작업에서 이미 읽은 동일 버전은 재사용하고, 파일이나 근거가 바뀌었을 때 다시 확인한다. 검증된 근거를 재사용할 때에는 출처와 확인 범위를 보존하며 필요한 변경 확인은 유지한다. 읽지 못한 파일을 기억이나 추정으로 채우지 않는다.

새 스킬을 찾는 일, 매번 전체 지침을 읽는 일, 같은 원고를 여러 도구가 차례로 전면 재작성하는 일을 기본 작업에 넣지 않는다. 카드·SNS 파생은 승인 원문을 Source Lock으로 사용한다. 원문에 없는 사실이 필요하면 원문 보강·승인 단계로 되돌린다.

블로그의 8,000~11,000자와 법률적 깊이, 기존 제목의 질문과 유용한 도입·예시는 유지한다. 상한에 가깝게 맞추려 문장을 채우거나, 문형 비율 때문에 줄이고 늘리는 반복은 하지 않는다. 문체 편집에서는 한 생각의 흐름을 살리고 낯선 개념이 겹친 곳만 풀어 쓴다.

정확성·업무범위·인용·필수 형식을 충족하고, 질문에 답하며 실제 자료와 수행 업무가 이해되면 편집을 마친다. 새 오류가 발견되지 않는 한 더 높은 문체·마케팅 점수를 위한 재실행은 하지 않는다. 미확인 법률 결론을 이 종료 기준으로 발행하지 않는다.

기존 작업 메모가 있으면 선택한 경로와 추가 검토 이유, 실제 사용한 도구만 짧게 남긴다. 별도 점수표·보고서·필수 JSON 필드를 만들지 않는다. 처리시간·조회 횟수·수정 횟수는 비교 실험에서 실제로 관측한 값만 기록하고, 이번 설정 변경만으로 속도나 전환이 개선됐다고 보고하지 않는다.

## 현재 사용하는 오픈소스 도구

아래는 저장소에 기록된 도구의 용도다. 목록에 있다는 사실은 현재 대화에서 실행했거나 모든 도구를 매번 실행해야 한다는 뜻이 아니다.

- Playwright: 결정론적 HTML/CSS 렌더와 브라우저 검사
- Pillow: 이미지 크기·축소 시트·시각 회귀
- JSON Schema / jsonschema: 국·영문 card-data 구조 검증
- Lychee: 문서와 출처 링크 무결성 검사
- Vale: 에토스 금지 표현·직접 연락 유도 표현의 비차단 경고
- CSpell: 영문 카드·캡션의 선택적 오탈자 경고
- kiwipiepy (Apache-2.0): 국문 결론 문장 어미의 형태소 분석(비차단 정보)
- proselint (BSD-3-Clause): 영문 카드의 상투어·군더더기 표시(비차단 정보). 설치돼 있지 않으면 건너뛴다. 영문 가독성은 사전 다운로드가 필요한 textstat 대신 `copy_lint.py`가 오프라인으로 근사 계산한다
- epoko77-ai/im-not-ai v2.3.2 (MIT, 커밋 `b37e0206d31fffd9149bf57168d4d62eb2086bee`): 로컬 `vendor/im-not-ai/quick-rules.md`는 AI 윤문 제안 규칙집. GitHub PR에서는 핀 고정 체크아웃과 `scripts/im_not_ai_review.py`로 외부 LLM 없는 정량 참고 힌트를 산출한다. Codex 전체 윤문은 별도 요청 시 `.agents/skills/ethos-humanize/SKILL.md`에 따라 수행한다.
- Anthropic `frontend-design` 스킬 (Apache-2.0, `vendor/anthropic-frontend-design`): 카드 자유 디자인의 과정·위계·자기 검토 기준. 원본 그대로 보관하고 `docs/card-design-guide.md`가 에토스 브랜드에 맞게 적용한다
- Pretendard (SIL OFL 1.1, `fonts/LICENSE-Pretendard.txt`): 자유 디자인 카드 본문용 로컬 글꼴
- greeun/card-news-harness (MIT), Kanghyeop/card-news-simple-skill (ISC), Giii-sik/card-news-publication-workflow (라이선스 표기 없음): 코드·문서를 복사하지 않고 한글 타이포 규칙·평가 방식·작업 단계만 참고해 `docs/card-design-guide.md`, `docs/card-evaluation-rubric.md`에 다시 썼다
- marketingskills (MIT, 참고 출처만): `docs/marketing-checklist.md`는 원문 복사가 아니라 에토스 윤리 원칙에 맞게 걸러 다시 쓴 요약이다
- Anthropic Python SDK (MIT): `scripts/ai_polish.py`의 Claude API 호출. 시크릿이 있을 때만 실행

버전은 재현 가능성을 위해 고정한다. 외부 디자인 프레임워크는 브랜드 구도를 획일화할 수 있어 기본 의존성으로 추가하지 않는다.

## 콘텐츠 스킬

아래는 필요할 때 선택할 수 있는 역할 목록이며 실행 의무 목록이 아니다.

- `content-strategy`: 소재·발행 순서 자체를 설계하는 작업에 한정
- `social`: 채널 명세만으로 재구성이 해결되지 않는 경우의 보조
- `copywriting`·`copy-editing`: 새 카피나 기존 원고의 구체적인 약점에 필요한 부분만
- `humanize-korean`: 사실 검토 뒤 필요한 부분의 윤문을 돕는다. 자연스러움 검수는 필수지만 외부 스킬 호출은 필수가 아니며, 수정할 곳이 없으면 변경하지 않는다

사용 가능한 도구를 먼저 확인하고, 없는 스킬을 찾거나 설치하느라 일반 원고 작성을 멈추지 않는다. 사용하지 못했으면 사용한 것처럼 기록하지 않는다. 보호 범위와 자동 제안의 수락·롤백 기준은 `docs/language-quality-workflow.md`를 따른다. 이 참조는 매 원고마다 문서를 추가 조회하라는 뜻이 아니다.

## 추가 도구 도입 기준

Vale 같은 오픈소스 문체 린터는 금칙어·용어 통일·반복 표현 검사에 쓸 수 있다. 다만 한국어 법률 문장은 조건과 인용이 많아 범용 규칙의 오탐 가능성이 크다. 실제 발행 원고에서 반복 오류와 예외 표본을 먼저 모은 뒤, 에토스 전용 규칙을 비차단 경고로 검증한 경우에만 도입한다.

현재 저장소에는 최소한의 `.vale.ini`와 `styles/ETHOS/` 규칙을 둔다. 국문 문체 힌트는 MuncheKit v0.2.0(MIT, `.munche.json`)과 ko-mt-lint(MIT, 커밋 고정)를 `Prose hints` 워크플로에서만 돌린다(2026-10-06 실측: 기존 블로그 3편에서 12건, 잡음 규칙 KO-POSS·KO-PARA·KO-END는 끔). hunspell-ko는 데이터 일부가 비영리 라이선스라, KSTE는 기술 문서용이라 쓰지 않는다. 영문은 별도 `.vale-en.ini`(Microsoft·write-good·proselint, 수동태·한정어 지적은 끔)로 카드·웹사이트 영문의 장황한 표현과 긴 문장만 info로 알린다(`docs/language-quality-workflow.md`). 이는 자동 수정이나 발행 차단에 사용하지 않는다. 경고가 법률용어·인용·조문·수치 또는 사실관계를 건드리면 사람이 원문과 대조한 뒤 거부한다.

영문 카드와 캡션은 `cspell.json` 범위에서 CSpell을 선택적으로 사용한다. 고유명사와 행정·법률 용어는 프로젝트 사전에 추가하고 자동 수정하지 않는다. LanguageTool은 공식 지원 언어에 한국어가 포함되지 않으므로 한국어 맞춤법·문체 검사기로 사용하지 않는다.

다음 도구는 즉시 추가하지 않는다.

- 한국어 지원과 오탐을 확인하지 않은 문법 교정기
- 글자 수를 줄이기 위해 법률 의미를 바꾸는 자동 요약기
- 출처·라이선스를 추적하지 않는 이미지 수집기
- 마케팅 점수를 하드 게이트로 만드는 자동 평가기

## 채택 질문

1. 실제로 반복되는 실패를 줄이는가?
2. 기존 도구와 기능이 겹치지 않는가?
3. 사실·법률·개인정보를 외부로 보내지 않고 사용할 수 있는가?
4. 오탐이 콘텐츠 생성을 막지 않는가?
5. 유지보수 비용보다 얻는 이익이 큰가?

답이 불명확하면 도구 대신 현재 지침과 사람 검수를 유지한다.
