# 웹사이트 블로그 MD 명세 (국문·영문)

웹사이트(`Admin-system-` 저장소, ethosattorney.com/blog)에 올릴 글을 **국문 1개, 영문 1개 MD 파일**로 만든다. 관리자 편집기의 입력 칸과 공개 페이지의 마크다운 변환(remark + remark-html, 2026-10-06 확인)에 맞춘 형식이다. 요청에 "웹사이트용"이 있으면 이 명세대로 두 파일을 자동으로 함께 낸다.

새 글·후속편·새 시리즈·수정본 모두 **읽기 쉬운 법률 칼럼**을 기본으로, 독자의 생각과 질문에서 오해를 풀고 중심 관점·법률 근거·조건 비교·자기 적용·실제 맡길 업무를 연결한다. 자료 받기→작성→제출을 모든 글의 기본 구조로 강제하지 않는다. 절차·비용·기한은 보조 정보로 보존하며 명시적으로 요청된 매뉴얼은 요청 형식을 따른다. Traffic·Authority·Revenue는 강조점일 뿐 나머지를 생략하는 분류가 아니다. 국문·영문 및 별도 요청된 아랍어 현지화에서도 의미와 서비스 범위는 유지한다. 아랍어 적용 원칙이 기존 국·영문 두 파일이나 MD 스키마를 바꾸지는 않는다.

## 1. 파일

- `content/<ID>/website.ko.md`, `content/<ID>/website.en.md` (ChatGPT에서는 같은 이름의 다운로드 파일 두 개로 낸다)
- 기본 전달은 실제 다운로드 파일 링크다. 장문 웹사이트 MD를 채팅에 전체 펼쳐 보이지 않는다. 사용자가 특정 언어 하나 또는 raw MD 직접 출력을 요청했다면 그 요청을 우선한다. 파일을 생성하지 못했으면 가짜 링크를 제공하지 않는다.
- 맨 위 YAML 머리말(`---` 사이)은 관리자 편집기의 입력 칸에 그대로 옮겨 적는 값이다. 그 아래가 "본문 (Markdown)" 칸에 붙여 넣을 내용이다.
- 양식: `content/_TEMPLATE/website.ko.md`, `website.en.md`. 검사: `python scripts/validate_website_md.py content/<ID>`

## 2. 머리말 (관리자 입력 칸과 1:1)

| 키 | 관리자 칸 | 규칙 |
|---|---|---|
| `slug` | 슬러그 (국·영 공통 하나) | 영문 소문자·숫자·하이픈, 100자 이내, 제목·요약 원문을 붙이지 않는다(웹사이트 `blog-slug-policy`). 두 파일에 같은 값 |
| `title` / `titleEn` | 제목 / 영문 제목 | 단독 글은 국문 30자 안팎, 영문 12자 이상으로 검색 의도가 보이게 쓴다. 시리즈 글은 `[정식 시리즈명 전체+회차] 이번 글의 검색 질문` 형식으로 시작한다. 영문은 정식 시리즈명을 자연스럽게 현지화하고 같은 회차를 보존한다. 시리즈 글에는 30자 안팎 권고를 이유로 정식 명칭이나 회차를 생략하지 않는다 |
| `excerpt` / `excerptEn` | 요약 / 영문 요약 | 검색결과 설명문. 국문 80~150자, 영문 60자 이상 160자 이하. 대상과 직접 답을 담는다 |
| `category` | 분류 | `visa` `appeal` `contract` `license` `corporate` `other` 중 하나(두 파일 같은 값) |
| `tags` / `tagsEn` | 태그 / 영문 태그 | **쉼표로 구분한 한 줄**(`비자, 외국인 고용, 체류자격`). `#`을 붙이지 않는다(관리자 칸이 쉼표로 나눠 글자 그대로 저장하므로 `#`이 태그에 들어간다). 4~10개. 같은 낱말의 변형은 3개까지로 하고, 핵심어·제도명·독자가 실제로 검색하는 표현·상황·절차어를 섞는다(`docs/blog-authoring-spec.md` 10절). 영문은 영어로 같은 형식 |
| `date` | 기록용 | 확인 기준일(YYYY-MM-DD) |

## 3. 본문 마크다운 규칙

- 제목(`#`)은 본문에 쓰지 않는다. 제목은 머리말에 있다. 소제목은 `##`, 그 아래는 `###`.
- 굵게(`**…**`)는 쓸 수 있다. 반드시 짝을 맞춘다(관리자 편집기가 짝이 안 맞으면 경고한다). 한 문단에 한 번 이내.
- 목록(`-`, `1.`), 인용(`>`), 구분선(`---`), 이미지(`![대체 텍스트](업로드 주소)`)를 쓸 수 있다.
- **마크다운 표(`| a | b |`)는 쓰지 않는다.** 웹사이트가 표 문법을 변환하지 않아 글자로 보인다. 비교는 목록이나 소제목으로 쓴다.
- 본문에 연락처·버튼·메신저·이메일 링크를 넣지 않는다. 다른 글로 가는 시리즈 링크도 넣지 않고 글 하나로 완결한다(`guidelines/channels/website.md`).
- 출처는 "국가법령정보센터, 2021경기행심1356(2021. 12. 6.)"처럼 이름으로 쓴다. 링크를 붙인다면 정식 주소만 쓰고 `utm_`·`OC=` 같은 값이 붙은 주소는 쓰지 않는다.
- 충분한 도입 → 칼럼 본문 → 무료 검토 안내 한 문장 → `> 3줄 요약` 인용 상자(줄마다 핵심 하나) 순서. 도입에 요약을 중복하지 않는다. 공개 본문에는 독립적인 확인 기준일/검증 기준일 라벨을 넣지 않고 실제 확인일·판본은 내부 검증 기록에 보존한다. 법령 시행일·판결일·통계기간과 관리자용 `date` 필드는 유지한다.
- 네이버 블로그 원고(`blog.md`)와 달리 인사말과 시리즈 목차는 넣지 않는다.

### 독자가 답을 찾는 웹사이트 편집 (국·영문 공통, Soft Guide)

- 네이버 블로그처럼 인사·목차·긴 공통 도입으로 시작하지 않는다. 독자의 상황과 질문을 충분히 보여 주는 도입에서 핵심 답을 일반 문장으로 일찍 제시하고 본문에서 이유와 조건 차이를 푼다. 인사·목차 제거를 도입 축소로 해석하지 않는다.
- `title`·`titleEn`에는 시리즈 글의 정식 시리즈명과 회차를 표시하고, 그 뒤에 해당 글의 핵심 검색 질문을 둔다. `excerpt`·`excerptEn`에는 확인된 답을 나타낸다. '무조건 해결' 같은 확정적 결과 약속이나 본문에 없는 질문을 SEO용으로 추가하지 않는다.
- 처음 등장한 한국 법률용어는 필요한 범위에서 쉬운 말로 설명한다. 본문에서는 독자가 마주한 서류·절차와 법령상 판단 기준을 연결하고, 서로 다른 경우의 비교는 목록·소제목·짧은 문단으로 풀어 쓴다(마크다운 표 금지).
- 승인 원문의 민수·지연·준호 등 다양한 예시 인물과 짧은 인물 간 대화를 활용할 수 있다. ‘예를 들어’나 조건형 도입 등 문맥에서 예시임을 자연스럽게 드러내며 독립적인 ‘가상의 상황입니다/실제 상담 사례가 아닙니다’ 고지문은 쓰지 않는다. 서로 다른 이름은 서로 다른 생각·상황을 드러낼 때 의미가 있으며 이름·대화·장면→조문→CTA를 고정 공식으로 만들지 않는다. 대사 속 오해는 인접한 설명에서 풀고 법률 결론은 공식 근거에 맞춘다.
- 허구를 실제 상담·수임·후기·성과로 주장하거나 에토스가 성공시킨 고객 이야기, 공무원·판사·기관 인용을 창작하지 않는다. 예시 대화 자체의 금지와 구분한다. 실제 사건을 옮길 때 원자료에 없는 대화·감정·피해액·결과를 덧붙이지 않는다. 승인된 Source Lock의 사실·조건·법률 의미·서비스 범위를 보존한다. 새 인물·장면·대화가 필요하면 원문을 보강하고 의미 검증·승인을 거쳐 Source Lock에 포함한 뒤 파생한다. FAQ는 7절의 실제 질문과 원문 내 답변이 있을 때만 추가한다.
- 국문·영문은 문장을 직역하지 않고 해당 독자에게 익숙한 생활·업무 상황과 표현을 사용한다. 다만 법률상 주체·조건·예외·숫자·출처·한정어의 의미는 원문과 같다.

### 쉽게 읽히면서 실제 맡길 일이 보이는 글 (2026-10-15 보강, Soft Guide)

공통 철학의 정본은 `docs/brand-philosophy.md`이다. 매번 정본을 더 읽지 않고 이 요약을 적용한다. **독자의 문제 → 실제 자료 → 수행 작업 → 준비되는 문서나 다음 행동**을 승인 원문의 범위 안에서 연결한다.

- 제목의 질문과 본문의 답을 일치시킨다. 변환 과정에서 인사와 목차를 뺀다는 이유로 유용한 납품·채용 장면이나 비교 예시까지 삭제하지 않는다. 도입과 본문의 상황 설명은 본문의 이해에 필요한 만큼 살린다.
- '검토·지원·대응'만 반복하지 않고 어느 서류의 무엇을 맞춰 어떤 내용을 정리하는지 풀어 쓴다. 예시 사이 문단도 비전문가가 읽을 수 있게 잇고, 설명과 이유를 모두 '확인하세요'라는 지시로 바꾸지 않는다. 전문용어와 법률상 한정은 뜻을 붙여 유지한다.
- 행정사에게 맡길 수 있는 작업은 원문과 실제 제공 범위에 근거해 설명한다. 작업으로 준비되는 문서와 허가·처분 변경 같은 외부의 결정을 구분하고, 제공하지 않는 보고서·보완 대응·처리기한을 새로 약속하지 않는다. 승인 원문에 서비스 범위가 없으면 추측하지 않고 원문 보강사항으로 남겨 확인·승인 후 반영한다. 단순 정보 글에도 영업 문단을 억지로 끼워 넣지 않는다.
- 무료 검토 안내는 3줄 요약 바로 앞의 마지막 서술 문장 안에서 보낼 자료와 먼저 확인할 안내를 독자의 말로 연결한다. 자료를 전부 완성해야 문의할 수 있는 것처럼 쓰지 않되 무자료 검토를 약속하지 않는다. 유료 작성·제출 업무를 무료 검토의 결과처럼 묶지 않는다. 법률을 몰라 막힌 독자와 내용을 이해했지만 서류 작업을 맡기려는 독자 모두 자신의 다음 행동을 알 수 있게 한다. 연락처·링크·상품·가격 규칙은 바꾸지 않는다.

처음 읽는 사람도 이해하도록 한 문장에서 가급적 한 가지만 말한다. 어려운 법률용어는 쉬운 뜻을 먼저 설명하고, 답·이유·조건은 필요하면 문장을 나눠 쓴다. 다만 문장마다 줄을 바꾸는 메모체가 아니라 한 가지 생각을 자연스러운 짧은 문단으로 잇는다. 국문에서는 '정하는 일이 여기에 연결됩니다'처럼 비어 있는 연결말과 어색한 명사형을 피하고 누가 무엇을 해야 하는지 직접 쓴다. 영문도 한국어를 직역하지 않고 영어 독자에게 자연스러운 동사와 문장으로 옮긴다. 국문과 영문에 동일한 문장 틀이나 사례 개수를 강제하지 않으며, 법률 의미·숫자·조건·예외·서비스 범위는 보존한다. 검색·문의 성과가 개선됐다는 평가는 실제 자료 없이는 하지 않는다.

이 명세는 **웹사이트 블로그 MD**에만 적용한다. 홈페이지 서비스 안내의 상품·가격·접수 경로는 `Admin-system-` 운영정책이 정본이며, 설명 전략은 `docs/content-architecture-system.md`의 홈페이지 서비스 항목을 참고한다.

## 4. 영문 본문

- 국문을 직역하지 않고 영문 독자 기준으로 다시 쓴다. 사실·숫자·조건·한정어는 같아야 한다.
- 행정사는 **Administrative Attorney**, 사무소는 **Ethos Administrative Attorney Office**(`docs/en-legal-glossary.md`).
- 웹사이트의 영문 색인 기준을 넘긴다: 본문 1,200자 이상, 영어 단어 180개 이상, 한글 20자 이하(한글 비율 3% 이하). 재결례 번호처럼 한글이 꼭 필요한 곳만 남긴다.
- 한국 법령명은 첫 언급에 영문 설명과 한글 원명을 함께 둔다: Licensed Real Estate Agents Act(「공인중개사법」).

## 5. 작성 순서

1. 승인된 원문을 Source Lock으로 삼는다. 원문 초안 전에는 중심 질문과 관련된 실제 판결·재결·공식 질의회신·통계·보도·행정자료를 우선 검토한다(`docs/evidence-gate.md`). 기존 `research/`를 재사용하고 필요한 채택·제외 이유만 짧게 남긴다. 종류별 의무 개수는 없으며 적합한 자료가 없으면 검증된 법령·공식 안내를 쓴다. 변환 단계에서 새 자료를 임의로 더하지 않고 근거가 부족하면 원문 보강·검증·승인으로 돌린다. 같은 요청에서 작성한 미승인 블로그 원고를 바탕으로 작업하면 파생물도 미승인 초안으로 유지하고 원문 검증·승인을 먼저 완료한다.
2. 국문 MD: 네이버 원고에서 인사말·목차·이미지 자리표시를 빼고, 소제목을 `##`로 바꾸고, 머리말을 채운다. 검색 질문에 대한 답과 실제 조건이 먼저 읽히도록 구성하되 Source Lock의 사실을 새로 만들지 않는다. 채택한 실제 근거가 쟁점·조건 비교·쉬운 설명을 이끄는 연결을 보존하며 출처를 끝에 붙이는 것으로 대신하지 않는다. 문장은 `docs/blog-authoring-spec.md`와 같은 기준으로 다듬는다.
3. 영문 MD: 4절 기준으로 다시 쓴다.
4. 원문과 각 언어의 요약·본문·마지막 안내에서 주체·대상·의무/재량·조건·예외·숫자·출처·서비스 범위를 대조한다. '또는', '이하', '수 있다'의 의미를 압축이나 직역 회피 때문에 없애지 않는다. 새 법률 판단이 필요하면 원문 작성 단계에서 공식 근거를 확인하며, 생활 장면 자체를 법률 결론의 근거로 쓰지 않는다.
5. `python scripts/validate_website_md.py content/<ID>`(실행할 수 없으면 아래 자가 점검표).

## 6. 자가 점검표

- [ ] 두 파일의 `slug`·`category`가 같다
- [ ] 본문에 `#` 제목, 마크다운 표, 짝이 안 맞는 `**`, 연락처·추적 링크가 없다
- [ ] 국문 요약 80~150자, 영문 요약 60자 이상
- [ ] 영문 본문 1,200자·180단어 이상, 한글 20자 이하, 행정사 = Administrative Attorney
- [ ] 충분한 도입과 핵심 답, 본문 뒤 무료 검토 안내 한 문장 → 3줄 요약 순서이며 공개 확인일 라벨이 없다(내부 확인일·관리자 date·법률상 날짜 보존)
- [ ] 채택한 실제 근거(적합한 자료가 없으면 검증된 법령·공식 안내)가 쉬운 설명·조건 비교·자기 적용을 이끌고 승인된 범위의 의뢰 판단으로 이어진다. Source Lock 밖 장면·서비스는 없으며 부족한 부분은 원문 보강사항으로 남겼다

## 7. 자주 묻는 질문 (선택, AI 검색 인용용)

웹사이트는 본문에서 `Q.`로 시작하는 줄과 바로 다음의 `A.`로 시작하는 줄을 찾아 `FAQPage` 구조화 데이터를 자동으로 넣는다(Admin-system `src/app/blog/[slug]/page.tsx` `extractFaqPairs`, 기능 스위치 `faq_schema_auto` 기본 켜짐, 2026-10-06 확인). 그래서 FAQ는 MD 본문 안에 이 형식으로 쓴다.

- 독자가 실제로 묻는 질문이 2~4개 자연스럽게 있을 때만 넣는다. 질문 표현은 `state/reader-language.md`(실제 검색어)에서 고른다.
- 위치: 마지막 무료 검토 안내 바로 앞, `## 자주 묻는 질문`(영문 `## Common questions`) 아래.
- 형식: 질문과 답을 각각 한 문단으로, 줄 맨 앞에 `Q. `와 `A. `를 쓴다. 굵게(`**Q.**`)·목록(`- Q.`)으로 쓰면 인식되지 않는다.
- 답은 본문 문장을 줄여 쓴다. 본문에 없는 사실·숫자를 더하지 않는다. 한 답은 1~2문장.

```markdown
## 자주 묻는 질문

Q. 사전통지서의 업무정지 6개월은 확정된 기간인가요?

A. 아닙니다. 사전통지는 처분 전 단계이고, 의견제출 결과에 따라 최종 기간이 달라질 수 있습니다.
```

`scripts/validate_website_md.py`가 `Q.` 뒤에 `A.`가 없거나 형식이 깨진 곳을 알려 준다.
