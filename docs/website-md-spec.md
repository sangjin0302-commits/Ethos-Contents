# 웹사이트 블로그 MD 명세 (국문·영문)

웹사이트(`Admin-system-` 저장소, ethosattorney.com/blog)에 올릴 글을 **국문 1개, 영문 1개 MD 파일**로 만든다. 관리자 편집기의 입력 칸과 공개 페이지의 마크다운 변환(remark + remark-html, 2026-10-06 확인)에 맞춘 형식이다. 요청에 "웹사이트용"이 있으면 이 명세대로 두 파일을 자동으로 함께 낸다.

## 1. 파일

- `content/<ID>/website.ko.md`, `content/<ID>/website.en.md` (ChatGPT에서는 같은 이름의 다운로드 파일 두 개로 낸다)
- 맨 위 YAML 머리말(`---` 사이)은 관리자 편집기의 입력 칸에 그대로 옮겨 적는 값이다. 그 아래가 "본문 (Markdown)" 칸에 붙여 넣을 내용이다.
- 양식: `content/_TEMPLATE/website.ko.md`, `website.en.md`. 검사: `python scripts/validate_website_md.py content/<ID>`

## 2. 머리말 (관리자 입력 칸과 1:1)

| 키 | 관리자 칸 | 규칙 |
|---|---|---|
| `slug` | 슬러그 (국·영 공통 하나) | 영문 소문자·숫자·하이픈, 100자 이내, 제목·요약 원문을 붙이지 않는다(웹사이트 `blog-slug-policy`). 두 파일에 같은 값 |
| `title` / `titleEn` | 제목 / 영문 제목 | 국문 40자 안팎. 영문 12자 이상, 검색 의도가 보이게 |
| `excerpt` / `excerptEn` | 요약 / 영문 요약 | 검색결과 설명문. 국문 80~150자, 영문 60자 이상 160자 이하. 대상과 직접 답을 담는다 |
| `category` | 분류 | `visa` `appeal` `contract` `license` `corporate` `other` 중 하나(두 파일 같은 값) |
| `tags` / `tagsEn` | 태그 / 영문 태그 | 3~6개 배열 |
| `date` | 기록용 | 확인 기준일(YYYY-MM-DD) |

## 3. 본문 마크다운 규칙

- 제목(`#`)은 본문에 쓰지 않는다. 제목은 머리말에 있다. 소제목은 `##`, 그 아래는 `###`.
- 굵게(`**…**`)는 쓸 수 있다. 반드시 짝을 맞춘다(관리자 편집기가 짝이 안 맞으면 경고한다). 한 문단에 한 번 이내.
- 목록(`-`, `1.`), 인용(`>`), 구분선(`---`), 이미지(`![대체 텍스트](업로드 주소)`)를 쓸 수 있다.
- **마크다운 표(`| a | b |`)는 쓰지 않는다.** 웹사이트가 표 문법을 변환하지 않아 글자로 보인다. 비교는 목록이나 소제목으로 쓴다.
- 본문에 연락처·버튼·메신저·이메일 링크를 넣지 않는다. 다른 글로 가는 시리즈 링크도 넣지 않고 글 하나로 완결한다(`guidelines/channels/website.md`).
- 출처는 "국가법령정보센터, 2021경기행심1356(2021. 12. 6.)"처럼 이름으로 쓴다. 링크를 붙인다면 정식 주소만 쓰고 `utm_`·`OC=` 같은 값이 붙은 주소는 쓰지 않는다.
- 맨 앞에 확인 기준일 한 줄, 맨 끝은 무료 검토 안내 한 문장.
- 네이버 블로그 원고(`blog.md`)와 달리 인사말과 시리즈 목차는 넣지 않는다.

## 4. 영문 본문

- 국문을 직역하지 않고 영문 독자 기준으로 다시 쓴다. 사실·숫자·조건·한정어는 같아야 한다.
- 행정사는 **Administrative Attorney**, 사무소는 **Ethos Administrative Attorney Office**(`docs/en-legal-glossary.md`).
- 웹사이트의 영문 색인 기준을 넘긴다: 본문 1,200자 이상, 영어 단어 180개 이상, 한글 20자 이하(한글 비율 3% 이하). 재결례 번호처럼 한글이 꼭 필요한 곳만 남긴다.
- 한국 법령명은 첫 언급에 영문 설명과 한글 원명을 함께 둔다: Licensed Real Estate Agents Act(「공인중개사법」).

## 5. 작성 순서

1. 승인된 원문(또는 같은 요청에서 쓴 블로그 원고)을 Source Lock으로 삼는다.
2. 국문 MD: 네이버 원고에서 인사말·목차·이미지 자리표시를 빼고, 소제목을 `##`로 바꾸고, 머리말을 채운다. 문장은 `docs/blog-authoring-spec.md`와 같은 기준으로 다듬는다.
3. 영문 MD: 4절 기준으로 다시 쓴다.
4. `python scripts/validate_website_md.py content/<ID>`(실행할 수 없으면 아래 자가 점검표).

## 6. 자가 점검표

- [ ] 두 파일의 `slug`·`category`가 같다
- [ ] 본문에 `#` 제목, 마크다운 표, 짝이 안 맞는 `**`, 연락처·추적 링크가 없다
- [ ] 국문 요약 80~150자, 영문 요약 60자 이상
- [ ] 영문 본문 1,200자·180단어 이상, 한글 20자 이하, 행정사 = Administrative Attorney
- [ ] 맨 앞 확인 기준일, 맨 끝 무료 검토 안내 한 문장

## 7. FAQ 후보 (선택)

웹사이트는 MD 본문만 읽으므로 FAQ 블록을 MD 파일에 넣지 않는다. 글에 독자가 실제로 묻는 질문과 답이 2~4개 자연스럽게 있을 때만, 두 파일을 낸 뒤 응답 끝(파일 밖)에 "FAQ 후보"로 국문·영문 Q&A를 적는다. 답은 본문 문장을 그대로 쓰고 본문에 없는 내용을 더하지 않는다. `FAQPage` 적용 여부는 웹사이트 저장소가 정한다(`docs/marketing-checklist.md` 6절).
