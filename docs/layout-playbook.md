# ETHOS BRIEF Layout Playbook

규칙을 맞추기 위한 레이아웃 목록이 아니라, 메시지에 가장 자연스러운 구도를 고르기 위한 플레이북이다. 기준 이미지는 `references/golden/game-overseas-en/`이다.

## 선택 순서

1. 이 카드에서 기억할 문장을 하나만 정한다.
2. 그 문장이 질문·근거·비교·구분·기준·행동 중 무엇인지 고른다.
3. 아래 구도 중 하나를 선택하고, 정보가 넘치면 글자를 줄이지 말고 다음 카드로 나눈다.
4. 같은 구도를 반복할 수는 있지만 세트 전체가 양식집처럼 보이지 않게 크기·여백·배경 리듬을 바꾼다.

## 검증된 구도

| 메시지 역할 | 권장 구도 | 가까운 레퍼런스 | 핵심 미감 |
|---|---|---|---|
| 표지 질문 | 대형 세리프 질문 + 짧은 결론 패널 | 01 | 설명보다 질문을 크게, 요소 3개 이하 |
| 판례·공식 근거 | 근거 라벨 + 흰 패널 + 한 줄 결론 | 02 | 권위는 이력이 아니라 자료로 표현 |
| 당사자·개념 구분 | 2×2 균형 그리드 + 하단 결론 | 03 | 네 칸의 구조와 문장 길이를 맞춤 |
| 두 상황의 차이 | A/B 카드 + 중앙 대비 기호 + 결론 | 04 | 서로 같은 정보 구조, 결론은 한 번만 |
| 두 규정·두 기준 | 가로 구획 2개 + 하단 핵심 문장 | 05 | 박스보다 타이포그래피와 선으로 구분 |
| 판단 질문 | 설명 패널 + 3개 질문 셀 + 결론 | 06 | 질문은 짧게, 셀은 같은 무게로 |
| 역할과 한계 | 좌우 2열 + 하단 경고·결론 | 07 | 무엇을 하는지와 대체하지 않는 것을 대비 |
| 수치 기준 | 큰 수치 라벨 + 설명 행 + 결과 | 08 | 숫자는 원문 그대로, 장식이 아니라 탐색점 |
| 자가 확인 vs 검토 | 좌우 2열 체크 + 종합 결론 | 09 | 독자가 자기 위치를 바로 찾게 함 |
| 마지막 행동 | 2열 체크리스트 + 절제된 CTA | 10 | 판매 문구보다 판단 항목, CTA는 한 번 |

## 선택 가능한 구성 방향

아래 명칭은 템플릿 수를 강제하는 스키마가 아니라 구도를 고르는 편집 언어다.

- **Editorial Brief**: 정책·법령·전문 해설
- **Bold Typography**: 짧은 오해 교정이나 핵심 결론
- **Story / Scenario**: 원문에 실제 사례나 명시된 가상 상황이 있을 때
- **Split Comparison**: 혼동되는 두 개념이나 두 문서 비교
- **Case File / Evidence**: 공개 근거와 문서 대조
- **Checklist / Toolkit**: 저장할 준비 항목·점검표
- **Diagram / Process**: 판단 순서와 관계
- **Photo-led Hybrid**: 사진이 국가·산업·장소·업무 맥락을 실제로 보탤 때
- **Minimal Statement**: 근거 있는 결론 하나와 넓은 여백

한 세트의 주된 방향은 하나로 두고 다른 방향은 필요한 장면에만 섞는다. 종류를 채우려고 원문에 없는 사례·수치·도식을 만들지 않는다. 사진과 외부 자산은 `docs/asset-policy.md`를 따른다.

## 데이터가 모양을 정하는 컴포넌트

렌더러는 페이지 번호가 아니라 card-data 필드로 모양을 고른다.

- `flow`: 역할·단계의 사슬. `body`는 `{key, text}` 항목, `note`로 한 줄 보충. 4개 이상이면 세로 배치. 역할 관계를 상자 넷으로 나열하던 `concept`보다 먼저 고려한다.
- `table`: `head` 두 칸 + `{key, text}` 행. '질문 → 정하는 것'처럼 저장해 두고 대조할 때 쓴다. 세로 높이 때문에 6행이 상한이고 값은 한 줄 안팎으로 쓴다.
- `cover.promise`: 표지 하단의 한 줄 약속(예: `출시 전에 답할 6가지 질문`). 장수를 쓰려면 원문 근거가 있는 숫자만 쓴다.
- `checklist.layout`: `questions`(질문 그리드)·`thresholds`(`key` 라벨 표)·`numbered`. 미지정이면 `key`가 있을 때 thresholds.
- `icon` / `art` / 항목별 `icon`: 제목 줄 우상단 원형 배지, 표지의 아이콘 원 2~3개(점선 연결), `flow`·`concept` 항목 앞 작은 원. `assets/icons/lucide` 이름만 받는다(`docs/asset-policy.md`).
- `checklist.layout: "stats"`: 큰 숫자·키워드가 주연인 행. 임계값·금액·건수처럼 숫자가 판단 기준일 때 쓴다.
- `takeStyle`: `bar`(박스) 또는 `close`(구분선 한 줄). 미지정이면 cover·cta·comparison은 bar.

## 밀도 보정과 일러스트 (v2.0 세트)

- `body_chars + 22 × 항목 수`로 카드를 low / mid / high로 나눈다(국문 150·230, 영문 260·400). low는 글자와 패널을 키워 빈 공간을 채우고 mid는 약간 키운다. high는 그대로다. 기준은 `scripts/build_cards.py`의 `DENSITY_LIMITS`.
- `illustration`은 low 카드이고 제목이 짧을 때만 나온다. 표지는 `coverStyle: "panel"`일 때 일러스트 패널, `"stat"`일 때 큰 숫자(`hero`)를 쓴다.
- `legacy` 세트는 이 보정을 받지 않아 기존 승인 카드의 모양이 바뀌지 않는다.

## 세트 리듬

- 기본 배경은 Navy → Cream → Navy → Cream의 리듬을 출발점으로 삼되 메시지 역할에 따라 바꿀 수 있다.
- 한 카드의 지배적 시각 요소는 하나다: 큰 질문, 큰 숫자, 비교, 리스트, 결론 중 하나만 주연으로 둔다.
- Gold는 시선을 여는 번호·키워드·선에 제한한다. 긴 본문 전체를 Gold로 칠하지 않는다.
- 카드 사이에 밀도 차이를 만든다. 모든 장을 같은 양의 텍스트와 같은 박스로 채우지 않는다.
- 270px 축소 시트에서 첫 시선의 위치와 배경 리듬이 자연스럽게 이어지는지 본다.

## 자유롭게 바꿔도 되는 것

- 카드 수, 권고 글자 수, 제목 줄 수, 영역 수, 여백 크기
- 메시지에 맞춘 행·열 비율과 패널 위치
- 같은 디자인 계보 안에서의 세리프 크기와 줄바꿈

## 바꾸면 안 되는 것

- 사실·숫자·한정어의 의미
- 로컬 폰트, 브랜드 팔레트, 공통 프레임
- 오버플로·클리핑 없는 1080×1080 출력
- 카드당 하나의 핵심 판단과 국·영문 간 사실 구조
