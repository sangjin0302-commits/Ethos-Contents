# 외부 AI 도구에서 채택한 편집 기법

이 문서는 도구 사용 의무가 아니라 에토스의 기존 Source Lock·근거 검증·사람 승인 흐름에 붙이는 작업법이다. 참고 목록: [스킬북 AI 모음집](https://www.getskillbook.com/ai.html) (2026-10-31 확인). 외부 서비스에 비공개 상담자료를 업로드하지 않는다.

## 1. Napkin AI식 설명 도식 — 카드 디자인

승인 원고에 **두 문서의 차이, 조건의 분기, 시간 순서, 주체 사이의 관계**가 있을 때만 그림의 뼈대를 제안한다. 먼저 원고의 해당 문장을 `sourceTrace`와 함께 찾고, 노드마다 원문의 주체·문서·조건을 하나씩 대응시킨다. `table`·`flow`·`comparison` 등 기존 카드 유형과 `layout` 안에서 구현한다. 연결선은 법률상 인과·순서·의무 관계를 새로 주장할 수 있으므로 원문에 없는 화살표를 넣지 않는다. 축소 시트와 개별 PNG에서 읽힘·잘림·법률 의미를 함께 검수한다. 자동 생성된 그림을 그대로 발행하지 않는다.

## 2. Promptfoo식 동일 입력 후보 비교 — 카드·블로그

같은 승인 원고와 동일한 조건 목록에서 후보 A·B를 별도 폴더로 만든다. `scripts/editorial_compare.py --baseline <승인 폴더> --draft <A> --candidate <B>`는 조건 발췌의 카드 노출 여부와 문자 밀도를 같은 기준으로 나란히 기록한다. 정확히 일치하는 발췌만 검사하므로 의미 동등성·자연스러움·선호도를 자동 판정하지 않는다. 사람은 원문 대조, 실제 렌더, 첫 화면의 질문·답, 연속 카드 반복, CTA의 실제 업무 범위를 보고 선택한다. 블로그 후보는 승인 문서의 해시를 보존하고 문단·소제목·근거 사용을 화면에서 비교한다. 새 점수표나 기계적 승자 선정은 하지 않는다.

## 3. DeepL Write식 영문 표현 대안 — 영문 카드·블로그

먼저 국문 승인 원고와 영문 초안의 카드별 질문 방향·주체·의무/재량·조건·예외·숫자·출처를 대조한다. 그다음 어색한 문장에 한해 1~2개 대안을 제시하고, 독자에게 자연스러운 표현을 고른다. `Administrative Attorney`와 `Administrative Attorney Office` 등 고정 번역어는 유지한다. 외부 제안은 원고의 근거가 아니며, 의미를 넓히거나 `may`·`must`·`or`·`up to`를 바꾼 대안은 폐기한다. 마지막에 `scripts/validate_bilingual.py`와 영문 카드 렌더를 확인한다.

## 4. NotebookLM식 근거 묶음 질문 — 조사·집필

주제별 `research/<시리즈>.md`에 중심 질문과 채택한 1차 자료의 제목·링크·기준일·관련 구절·채택/제외 이유를 함께 둔다. 질문별로 어느 근거가 답하는지 표시하고, 원문에 없는 결론은 채택하지 않는다. 법령·판례·공식 안내의 판본과 시점을 직접 확인한다. 카드의 `sourceTrace`는 승인 블로그의 해당 근거 구절을 가리키게 한다. 근거 묶음은 탐색을 돕는 색인이며 법률 검증이나 전문가 판단을 대체하지 않는다.
