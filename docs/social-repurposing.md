# 블로그에서 SNS로 재가공하기

SNS 글은 블로그를 짧게 줄인 요약문이 아니다. 승인된 원문에서 하나의 독립된 질문과 보상을 꺼내 채널에 맞게 다시 쓴다.

## 추출할 수 있는 콘텐츠 단위

- 독자가 처한 구체적 상황 하나
- 자주 혼동하는 두 개념의 차이
- 준비자료나 확인 항목 3~5개
- 서류·절차를 보는 Proof of Work 한 장면
- 공식자료나 판례·재결례에서 확인되는 기준 하나
- 직접 처리할 수 있는 범위와 검토가 필요한 경계
- 법령·제도 변경이 기존 판단에 미치는 영향

한 게시물에는 하나만 선택한다. 블로그의 모든 소제목을 한 게시물에 압축하지 않는다.

## 재가공 순서

1. 원문에서 사실·법률·수치·조건을 잠근다.
2. Revenue Cluster와 독자의 구매 단계를 정한다.
3. 한 질문과 한 행동을 고른다.
4. Hook 후보를 만들되 실제 정보 보상을 숨기지 않는다.
5. 채널 형식에 맞춰 새로 쓴다.
6. 직접 처리 범위와 검토 경계를 나눈다.
7. 필요한 경우 한 번의 구체적인 무료 검토 안내로 끝낸다.
8. 한국어는 사실 검토 후 `docs/language-quality-workflow.md`를 적용한다.

## 채널별 역할

- Instagram 캐러셀: 비교·순서·체크리스트·판단 경계처럼 저장할 구조
- LinkedIn: 블로그 요약이 아니라 B2B 의사결정 자료로 다시 쓴다. ① 기업 상황→결론→판단 기준→업무상 의미, ② 불일치→확인 순서→문서·부서→놓치기 쉬운 지점, ③ 변경점→영향 기업→실무 영향→이번 주 확인사항 중 하나를 고른다.
- 카카오: 짧은 상황, 정확한 답, 주의점, 다음 확인 행동
- Threads·X: 한 문장 관찰이나 구분과 짧은 근거. 근거 없는 논쟁 유도 금지
- 숏폼: 첫 3초의 대상·문제, 한 가지 기준, 한 가지 행동. 빠른 편집을 위해 법률 한정어를 삭제하지 않는다.

원문마다 Traffic·Authority·Revenue 역할 하나와 다음 콘텐츠 하나를 정한다. 포트폴리오 연결은 `docs/content-architecture-system.md`를 따른다.

## 금지

- 모든 채널에 같은 캡션 복사
- 실제 경험이 없는 Story Hook 창작
- 블로그에 없는 사례·수치·판례 추가
- 반응을 위해 결론을 숨기는 가짜 오픈루프
- `논쟁적 의견`, `충격`, `손해`를 근거 없이 확대
- 모든 원문을 모든 채널에 발행
