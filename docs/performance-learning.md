# 카드뉴스·SNS 성과학습

성과 기록의 목적은 보고서를 길게 만드는 것이 아니라 다음 콘텐츠에서 무엇을 바꿀지 결정하는 것이다. 노출·좋아요만으로 성공을 판단하지 않는다.

## 기록할 맥락

- Content ID, 원본 글, 주제·시리즈
- 채널·언어·발행일
- Primary Objective와 구매 단계
- 대상 독자와 Revenue Cluster
- 소재 가치 유형: Entry·Core·Composite·Recurring B2B
- 희소성 신호: 분류 경계·제도 교차·순서 의존성·문서 정합성·기관 분산·보완 가능성·반복성·국제화 마찰
- Hook 유형과 Visual Family
- 카드 수·출력 비율·제작 시간
- CTA 유형과 입력자료·확인결과
- 주된 신뢰 장치: 공식 근거·Authority Demonstrate·Proof of Work·체크리스트
- 인간 판단 증거를 사용했다면 사실관계·문서 정합성·절차 설계·대응 중 어떤 가치를 보여줬는지
- 이번에 바꾼 변수 하나

개인정보, 상담 내용, 민감한 사실관계는 기록하지 않는다.

## 행동 지표

채널에서 실제로 제공하는 지표만 사용한다.

- 도달·노출
- 마지막 장 도달 또는 이용 가능한 완독 대체 지표
- 저장·공유·댓글
- 프로필 방문·링크 클릭
- 무료 검토 요청
- 업무범위에 맞는 적합 문의
- 유료 상담·수임

서로 다른 채널의 숫자를 같은 기준으로 직접 비교하지 않는다. 외부 벤치마크는 초기 가설일 뿐이며 실제 계정의 일관된 측정값을 우선한다.

## 진단표

| 관찰 | 먼저 점검할 것 |
|---|---|
| 도달이 낮다 | 주제 적합성, 채널, 표지의 대상·문제 표현 |
| 넘김·저장이 낮다 | 2~3장의 실익, 카드 밀도, 정보 보상 |
| 저장은 높지만 프로필 방문이 낮다 | Proof of Work, 전문가 검토가 필요한 이유 |
| 프로필 방문은 있지만 문의가 낮다 | CTA가 요구하는 자료와 확인 결과의 구체성 |
| 문의는 있지만 적합도가 낮다 | Hook의 대상 범위, 서비스 범위, 구매 단계 |
| Entry는 유입되지만 적합 문의가 적다 | 관련 Core·Composite 콘텐츠로 이어지는 내부 연결 |
| Composite는 반응이 낮지만 적합 문의가 있다 | 도달보다 문의의 질과 후속 전환을 우선 평가 |
| AI 대비 문구는 반응이 높지만 적합 문의가 낮다 | AI 비교를 줄이고 독자의 문제·사람이 판단할 항목을 앞세움 |
| 인간 판단 증거에서 프로필 방문이 높다 | 같은 표현을 반복하지 말고 다른 소재에서도 작업 방식의 가치를 확인 |
| 무료 검토 뒤 유료 전환이 낮다 | 자료 요구, 실제 제공 범위, 상담·수임 경계 |
| 제작 시간이 길고 성과 차이가 작다 | 카드 수와 디자인 변주를 줄이고 검증된 구도 재사용 |

한 게시물의 결과만으로 규칙을 확정하지 않는다. 결과가 낮다고 사실·법률·브랜드 기본값을 바꾸지 않는다.

## 단일변수 학습

한 번에 하나만 바꾼다.

- Hook 유형
- 표지 구도
- 카드 수
- 4:5와 1:1
- Visual Beat 또는 사진·도식 사용
- CTA의 입력자료·확인결과 표현
- 원문 카피와 의미가 같은 범위의 humanize 처리 여부

대상 독자, 핵심 주제, 사실·법률, 무료 검토 정책을 동시에 바꾸지 않는다. 표본이 적을 때에는 이를 통계적 A/B 테스트라고 부르지 않고 `순차 단일변수 학습`으로 기록한다.

## 실제 고객 언어

무료 검토, 상담, 댓글, 검색어에서 반복되는 질문을 익명화해 다음 콘텐츠 후보로 기록한다. 검색어는 Search Console·네이버 서치어드바이저 CSV를 `python scripts/reader_phrases.py <CSV…> --questions <질문.txt> --out state/reader-language.md`로 모은다(전화·이메일 형태 줄은 자동 제외). 상담 질문은 이름·연락처를 빼고 한 줄에 하나씩 적는다.

- 독립된 실제 자료 3개 이상에서 자발적으로 반복: 높은 신뢰도
- 2개 자료 또는 질문 후 확인: 중간 신뢰도
- 한 사람이나 한 자료에서만 관찰: 검증할 가설

실제 발언을 공개 인용하려면 별도 동의를 확인한다. 조회·저장만으로 고객 요구를 확정하지 않는다.

## 표지 시험 (altCover)

표지가 도달과 저장을 가장 크게 좌우하므로, 세트마다 같은 내용으로 Hook 유형이 다른 대안 표지를 하나 만들 수 있다(`altCover`, `docs/card-authoring-spec.md`). 한 게시물 안에서는 A/B를 나눌 수 없으므로 이렇게 비교한다.

- 기본 표지는 주 채널(인스타그램)에, 대안 표지는 다른 채널(LinkedIn·스레드)이나 2주 뒤 재게시에 쓴다.
- `performance-log.csv`의 `cover_hook_type`(situation·question·contrast·number)과 `variable_tested=cover`로 기록한다.
- 세트 3개 이상 같은 방향이면 이긴 Hook 유형을 다음 시리즈 기본으로 삼는다. 그 전에는 가설로 둔다.

## 다음 변수를 정하는 규칙

기록만 쌓지 않고 정해진 시점에 한 가지를 결정한다.

1. **세트 3개마다** 같은 채널·같은 목적의 세트를 모아 본다. 한 세트의 숫자로 결론 내리지 않는다.
2. 비교는 한 번에 변수 하나(Hook 유형, CTA 입력자료 표현, 카드 수 중 하나)만 바꾼 세트끼리 한다. 대상 독자·주제·사실·무료 검토 정책은 같게 둔다.
3. Primary Objective 지표만 본다. 저장이 목적이면 저장, 무료 검토가 목적이면 요청 수. 다른 지표가 올라도 목적 지표가 오르지 않았으면 성공으로 기록하지 않는다.
4. 결정은 셋 중 하나로 `performance-log.csv`의 `decision` 열에 적는다: `유지`(다음 세트도 같은 방식), `변경`(변수 하나를 바꿔 시험), `보류`(표본 부족, 세트 3개 더). 표본이 3세트 미만이면 `보류`다.
5. 무료 검토 요청이 실제로 들어왔는데 적합하지 않았다면 CTA의 입력자료·확인결과 표현이 범위를 넘었는지 먼저 점검한다.
