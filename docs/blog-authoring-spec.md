# 블로그 작성 명세 (ChatGPT 한 장 요약)

블로그·홈페이지 글을 요청받으면 긴 지침보다 이 문서를 먼저 읽는다. 이 문서는 `guidelines/channels/blog.md`(v3.1)와 상위 지침의 **작업 순서와 적용 강도**를 정한다. 사실·법률·윤리 규칙의 내용은 바꾸지 않으며, 어떤 문서를 언제 읽고 어떤 규칙을 어느 강도로 적용할지만 정한다. 이 문서로 해결되지 않는 충돌이 있을 때만 blog.md와 상위 지침을 열고 그쪽을 따르되, 아래 "경로"와 "Hard Gate / Soft Guide" 구분은 그 문서들의 적용 방법으로 읽는다.

> **사실과 법률에는 엄격하게, 문체에는 여유를 준다.** 모델이 규칙을 관리하느라 글이 늦어지고 보고서처럼 굳는 것이 가장 큰 위험이다. 초안을 쓰면서 모든 규칙을 동시에 지키려고 하지 않는다.

> **전환 장치**: 원문에 근거가 있는 실제 기한(예: 사전통지서의 의견제출기한)을 독자 상황 바로 뒤에 둔다. 마지막 무료 검토 안내에는 보낼 자료와 받을 결과를 함께 쓴다. 확인되지 않은 서비스 사실(회신 기간 등)은 쓰지 않는다. 받을 자료가 있으면 `content/<ID>/lead-magnet.md`로 만든다(`docs/card-authoring-spec.md` "전환 장치").

## 1. 먼저 경로를 고른다

요청을 받으면 아래 중 하나로 분류하고, 한 줄로 어느 경로인지 알린 뒤 시작한다.

| 경로 | 언제 | 하는 일 |
|---|---|---|
| **A. 일반 경로**(기본) | 같은 시리즈 후속편, 이미 검증된 원고의 수정·재작성, 제목·도입·문체 개선, 법률 쟁점이 하나뿐인 글 | `research/`의 조사 잠금을 재사용하고 **변경 여부만** 확인. 새로 찾는 자료는 이 글에 꼭 필요한 근거만 |
| **B. 심층 조사 경로** | 새 법률 주제, 판례·통계·제재 사례까지 필요한 글, 조사 잠금이 없거나 기준일이 지나 법령이 바뀌었을 가능성이 큰 글 | 공식 1차 자료로 근거를 잠그고 `research/<시리즈>.md`에 저장한 뒤 작성 |
| **C. 파생** | 승인된 블로그를 카드·SNS·웹사이트 MD로 옮길 때 | 승인된 블로그 원문이 Source Lock. 법률 재조사 없음 |

판단이 애매하면 A로 시작하고, 근거가 부족하다고 확인된 부분만 B 방식으로 보강한다.

## 2. 읽을 파일 (적을수록 빠르다)

파일 하나를 읽을 때마다 조회가 한 번 일어나 시간이 든다. **필요한 파일은 한 번에 함께 요청하고**, 아래에 없는 파일은 읽지 않는다.

- 경로 A·C: **이 문서 하나**. 해당 시리즈의 `research/<시리즈>.md`가 있으면 함께, `state/reader-language.md`(제목·첫 문장·FAQ 질문에 쓸 실제 검색어)는 제목을 정할 때만.
- 경로 B: 이 문서 + `docs/evidence-gate.md`(근거 잠금 요약). 이 둘이면 새 법률 주제를 쓰기에 충분하다.
- 읽지 않는다: `MANIFEST.md`, `guidelines/core/top-level.md`·`definitive-style.md`·`master.md`, `guidelines/channels/blog.md`(44KB), `docs/topic-discovery.md`, `docs/legal-verification.md`, `docs/brand-philosophy.md`(아래 "브랜드 핵심"에 요약됨). 사용자가 요청하거나, 이 문서와 `evidence-gate.md`로 해결되지 않는 충돌·세부가 있을 때만 해당 원문을 연다. 소재를 고르는 요청이면 `docs/topic-discovery.md`와 글감관리표를 읽는다. 주제가 신규 전문가·국제화·중동·일상 소재·신규 업역일 때만 해당 모듈을 더한다.

조회하지 못한 파일은 사용자에게 알린다. 구버전 사본으로 대신하지 않는다.

## 브랜드 핵심 (`docs/brand-philosophy.md` 요약, 충돌하면 원문)

- 신사업·국제사업의 한국 행정문제를, 사람이 사실관계·문서·절차까지 직접 검토하는 서비스. 독자가 어려워하는 것은 서류 목록이 아니라 **자기 사업구조에 어떤 제도와 순서가 적용되는지**다.
- 신뢰는 판단 과정(입력자료·대조·순서·확인 결과)과 날짜(기준일·개정일)로 만든다. 자격·경력의 우월성을 주장하지 않는다.
- 목소리: 차분하고 정확하며 과장하지 않는다. 답을 먼저, 근거를 뒤에. 쓰는 말: 판단·대조·순서·확인·보완·최신 근거·업무범위. 쓰지 않는 말: 완벽·무조건·성공 보장·모든 업무·업계 최고·다른 자격사보다 우수.
- 설득의 윤리: 유용한 답을 먼저 주고, CTA를 지워도 글이 유익해야 한다. 허위 희소성·마감, 부풀린 공포, 없는 후기·건수, 낚시성 질문을 쓰지 않는다. 한 글에 다음 행동은 하나.
- 경계: 결과 보장 금지, 법정 업무범위를 넘는 대리 약속 금지, 다른 자격사와는 우열이 아니라 사건에 필요한 업무축으로 구분한다. 일반 정보·생성형 AI 정보를 폄하하지 않는다.
- 전환: 글의 끝은 받을 자료 2~3개와 확인해 줄 결과 1~3개를 쓴 무료 검토 안내. 무료 범위(가능 여부·시작 방향·확인할 기관·자료)를 넘는 약속을 하지 않는다. 범위·가격·접수 경로의 정본은 웹사이트 저장소 운영정책이다.

## 3. Hard Gate: 어기면 발행하지 않는 것

이 항목에 문제가 있을 때만 막는다.

1. 법령·판례·통계의 정확성. 확인되지 않은 사실·법률 결론은 쓰지 않는다(U 표시 문장 금지).
2. 경험·후기·성과·건수·성공률·"심사자 시각"을 만들지 않는다.
3. 행정사 업무범위를 넘지 않는다. 다른 자격사와의 우열 주장·소송 대리를 암시하는 표현 금지.
4. 처리위탁과 제3자 제공처럼 핵심 법률 구분을 흐리지 않는다.
5. 독자가 직접 확인할 수 있는 범위와 전문가 검토가 필요한 경계를 구분한다.
6. CTA는 후반 **한 번**. 무료 검토 범위를 넘는 약속·연락처·버튼·링크를 본문에 넣지 않는다.
7. 숫자·조문·날짜·"수 있다/또는/이하" 같은 한정어를 바꾸지 않는다.
8. 마지막에 의미 재검증을 한다(법률 의미가 처음 확인한 근거와 같은가).

## 4. Soft Guide: 자연스러울 때 적용하는 것

제목 공식, 소제목 수, 문단 길이, 질문형 소제목, 사례 배치, SEO 키워드, 마케팅 기법은 전부 권고다. 필수 체크박스로 만들지 않는다. 글이 자연스러울 때 쓰고, 다 쓴 뒤 약한 부분만 고친다. 점수를 매겨 재작성을 강제하지 않는다(점수는 내부 참고용).

## 5. 작성 순서

1. **근거 잠금**: 경로 A는 `research/`의 조사 잠금에서 기준일 이후 법령 변경, 새 판례·제재 사례, 기존 인용의 유효성만 확인. 경로 B는 `docs/evidence-gate.md`에 따라 공식 1차 자료를 확인하고 조사 잠금을 저장한다.
2. **자연 초안**: 독자에게 설명하듯 끝까지 한 번에 쓴다. 이 단계에서는 규칙을 의식하지 않는다.
3. **법률 의미 검증**: 초안의 법률 문장이 잠근 근거와 같은지 확인한다.
4. **제목·도입·차별점·CTA만 편집**: 다른 부분은 건드리지 않는다.
5. **어색한 문장만 윤문**: 필요한 곳만. 전체를 다시 쓰지 않는다. 윤문 규칙집(`vendor/im-not-ai/quick-rules.md`)은 이 단계에서만 읽는다.
6. **숫자·조문·한정어 재확인**.

통계·판례·제재 사례는 각각 하나의 실무 쟁점을 설명하는 데 필요한 만큼만 쓴다.

## 6. 최종 점검은 세 질문뿐

완성 뒤에 이것만 확인하고, 약한 곳이 있으면 그 부분만 고친다.

1. 첫 5문단 안에 독자의 상황과 핵심 답이 나오는가?
2. 다른 사무소 글과 구별되는 실제 검토 방식(순서·대조·확인 결과)이 보이는가?
3. CTA 문단과 마지막 안내를 지워도 저장할 정보가 남는가?

점수·스킬 이름·작업 보고는 사용자가 요청할 때만 덧붙인다. 확인하지 못한 항목이 있으면 그것만 짧게 알린다.

## 7. 조사 잠금(`research/`)

한 번 검증한 법령·판례·통계는 시리즈 단위로 저장해 다음 편에서 처음부터 다시 찾지 않는다. 형식과 갱신 규칙은 `research/README.md`. 경로 B가 끝나면 조사 잠금 파일 내용을 함께 낸다(저장소에는 사용자나 Codex가 커밋한다).

## 8. 글의 뼈대 (Core 6)

1. 검색 의도에 맞는 진입부: 첫 화면에서 대상 독자와 판단 문제가 보인다.
2. 질문에 대한 직접 답: 확인된 것은 맞다·틀리다를 분명히 답하고 근거를 잇는다. 근거 없는 양시론·양비론으로 결론을 피하지 않는다. 결론이 달라지는 실제 조건이 있을 때만 구분한다.
3. 검증된 핵심 정보: 법령명·조문·기관·기한을 원문 표기대로.
4. 구체적 적용 상황 하나 이상(가정 사례는 가정이라고 쓴다).
5. 일반론과 개별 판단이 갈리는 지점.
6. 후반부에 직접 확인할 수 있는 범위와 전문가 검토가 필요한 상황의 구분 + 자연스러운 무료 검토 안내 문단 **한 번**(받을 자료 2~3개, 확인해 줄 결과 1~3개. "무료 상담" 금지).

## 9. 고정 규칙 요약

- 영문에서 행정사는 항상 **Administrative Attorney**(사무소는 Administrative Attorney Office). 다른 번역(administrative agent, scrivener 등)을 쓰지 않는다.
- 확인된 사실은 단정하고 조건·재량·추론만 한정한다(`guidelines/core/definitive-style.md`).
- 권위는 이력 나열이 아니라 판단 과정(법령 조건 구분, 서류 대조, 절차 순서)으로 보인다.
- 고정 발행 빈도·복수 CTA·"정확히 3개" 같은 과거 규칙은 쓰지 않는다. 같은 구조에 제목만 바꾼 글을 반복하지 않는다.
- 말투는 `examples/writing/README.md`의 "고치기 전 → 고친 후" 예시로 잡는다.

## 10. 태그

**쓰기 전에 5가지 묶음으로 나눠 고른다.** 한 묶음에서만 고르면 같은 말의 변형이 되어 검색에 걸리는 폭이 좁아진다.

| 묶음 | 예 | 개수(블로그 기준) |
|---|---|---|
| ① 핵심 주제어 | `#행정사업무범위` `#영업정지` | 2~3 |
| ② 제도·법령·기관 이름 | `#행정심판법` `#민사소송법` `#국가법령정보센터` | 2~3 |
| ③ **독자가 실제로 검색하는 표현**(`state/reader-language.md`, 질문형·롱테일) | `#행정심판대리` `#소송대리인자격` `#허가거부대응` | **4 이상** |
| ④ 독자 상황·업종·대상 | `#식당사장님` `#폐기물처리업` `#처음인허가` | 2~3 |
| ⑤ 절차·단계 단어 | `#보완요구` `#불복기간` `#사전통지` | **3 이상** |

- **네이버 블로그 태그**(`blog.md` 맨 끝, 본문과 한 줄 띄움): `#태그`를 공백으로 이어 **12~20개**.
- **같은 낱말의 변형은 3개까지.** `#행정사 #행정사업무범위 #행정사변호사차이 #행정사와변호사`처럼 한 낱말(예: 행정사)이 4개 이상 태그에 들어가면 린터가 알린다. 띄어쓰기만 다른 같은 태그도 한 번만 쓴다.
- **웹사이트 태그**(`website.ko.md`·`website.en.md` 머리말 `tags`·`tagsEn`): `#` 없이 **쉼표로만** 구분한 한 줄, 4~10개(`영업정지, 과징금 전환, 사전통지`). 같은 규칙으로 묶음을 섞는다. 형식은 `docs/website-md-spec.md`.
- 쓰지 않는다: 확인되지 않은 효과·"최고"류 단어, 다른 사무소 이름, 본문에 없는 주제.
- 점검: `python scripts/copy_lint.py content/<ID>`(블로그 끝 `#태그`)와 `python scripts/validate_website_md.py content/<ID>`(웹사이트 태그)가 개수·중복·낱말 쏠림을 안내한다. 안내이며 발행을 막지 않는다.

## 11. 발행 형식

- **글의 앞부분 순서**: 제목(30자 안팎, 독자 상황과 답이 보이게) → **독자 상황 한 줄**(가정이면 가정이라고 밝힘) → 인사 한 줄("안녕하세요, 행정사 지상진입니다.") → **3줄 요약**("3줄 요약" 다음에 줄마다 핵심 하나, 숫자·조건은 본문과 같게) → 시리즈 목차(이번 글 표시) → 본문. 검색 결과와 미리보기의 첫 줄이 인사가 아니라 독자의 상황이 되게 한다.
- **필수 두 가지(윤문 단계)**: 문장 첫머리 "따라서"는 글 전체에서 3번까지. 쉼표로 끝나는 줄을 이어 쓰는 목록은 번호나 글머리 목록으로 바꾼다. 린터가 `so-many-therefore`·`comma-list`로 알린다.
- 출처는 본문에 "국가법령정보센터, 2021경기행심1356(2021. 12. 6.)"처럼 기관·사건번호·날짜로 쓴다. 링크를 붙일 때는 국가법령정보센터의 정식 주소만 쓰고, `utm_…` 추적값이나 `OC=` 같은 API 키가 붙은 주소는 쓰지 않는다. 출처 사이트 이름을 지어내지 않는다.
- 네이버 블로그 원고에는 `**굵게**` 같은 마크다운 기호를 쓰지 않는다. 웹사이트 MD는 `docs/website-md-spec.md` 규칙을 따른다.
