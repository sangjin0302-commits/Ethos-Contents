# 블로그 작성 명세 (ChatGPT 한 장 요약)

블로그·홈페이지 글을 요청받으면 긴 지침보다 이 문서를 먼저 읽는다. 이 문서는 `guidelines/channels/blog.md`(v3.1)와 상위 지침의 **작업 순서와 적용 강도**를 정한다. 사실·법률·윤리 규칙의 내용은 바꾸지 않으며, 어떤 문서를 언제 읽고 어떤 규칙을 어느 강도로 적용할지만 정한다. 이 문서로 해결되지 않는 충돌이 있을 때만 blog.md와 상위 지침을 열고 그쪽을 따르되, 아래 "경로"와 "Hard Gate / Soft Guide" 구분은 그 문서들의 적용 방법으로 읽는다.

> **사실과 법률에는 엄격하게, 문체에는 여유를 준다.** 모델이 규칙을 관리하느라 글이 늦어지고 보고서처럼 굳는 것이 가장 큰 위험이다. 초안을 쓰면서 모든 규칙을 동시에 지키려고 하지 않는다.

> **전환 장치**: 원문에 근거가 있는 실제 기한(예: 사전통지서의 의견제출기한)을 독자 상황 가까이에 짧게 안내하되, 독자가 제기한 질문의 직접 답을 기한 안내로 대체하지 않는다. 마지막 무료 검토 안내에는 보낼 자료와 받을 결과를 독자의 말로 함께 쓴다. 확인되지 않은 서비스 사실(회신 기간 등)은 쓰지 않는다. 받을 자료가 있으면 `content/<ID>/lead-magnet.md`로 만든다(`docs/card-authoring-spec.md` "전환 장치").

**새 글·후속편·새 시리즈·수정본의 공통 기준**: 자연스러운 업무 흐름, 법률 근거와 조건·예외, 실제 맡길 작업과 다음 행동을 글 전체에서 함께 살린다(4-1·4-2절). 국문·영문·아랍어 모두 주체·대상·의무/재량·조건·예외·숫자·출처와 서비스 범위는 같게 유지하고 표현은 현지화한다. 카드·SNS·웹사이트로 옮길 때도 이 연결을 보존하되 각 채널의 길이·구성·CTA 규칙을 따른다. 모든 문장에 세 요소를 몰아넣지 않는다.

## 1. 먼저 경로를 고른다

요청을 받으면 아래 중 하나로 분류하고, 한 줄로 어느 경로인지 알린 뒤 시작한다.

| 경로 | 언제 | 하는 일 |
|---|---|---|
| **A. 일반 경로**(기본) | 같은 시리즈 후속편, 이미 검증된 원고의 수정·재작성, 제목·도입·문체 개선, 법률 쟁점이 하나뿐인 글 | `research/`의 조사 잠금을 재사용하고 **변경 여부만** 확인. 새로 찾는 자료는 이 글에 꼭 필요한 근거만 |
| **B. 심층 조사 경로** | 새 법률 주제, 판례·통계·제재 사례까지 필요한 글, 조사 잠금이 없거나 기준일이 지나 법령이 바뀌었을 가능성이 큰 글 | 공식 1차 자료로 근거를 잠그고 `research/<시리즈>.md`에 저장한 뒤 작성 |
| **C. 파생** | 승인된 블로그를 카드·SNS·웹사이트 MD로 옮길 때 | 승인된 블로그 원문이 Source Lock. 법률 재조사 없음 |

판단이 애매하면 A로 시작하고, 근거가 부족하다고 확인된 부분만 B 방식으로 보강한다.

## 2. 읽을 파일 (적을수록 빠르다)

파일 하나를 읽을 때마다 조회가 한 번 일어나 시간이 든다. **필요한 파일은 한 번에 함께 요청하고**, 아래에 없는 파일은 읽지 않는다.

- 경로 A·C: **이 문서 하나**. 해당 시리즈의 `research/<시리즈>.md`가 있으면 함께, `state/reader-language.md`(제목·첫 문장·FAQ 질문에 쓸 실제 검색어)는 제목을 정할 때만.
- 경로 B: 이 문서 + `docs/evidence-gate.md`(근거 잠금 요약). 이 둘이면 새 법률 주제를 쓰기에 충분하다.
- 읽지 않는다: `MANIFEST.md`, `guidelines/core/top-level.md`·`definitive-style.md`·`master.md`, `guidelines/channels/blog.md`(44KB), `docs/topic-discovery.md`, `docs/legal-verification.md`, `docs/brand-philosophy.md`(아래 "브랜드 핵심"에 요약됨). 사용자가 요청하거나, 이 문서와 `evidence-gate.md`로 해결되지 않는 충돌·세부가 있을 때만 해당 원문을 연다. 소재를 고르는 요청이면 `docs/topic-discovery.md`와 글감관리표를 읽는다. 주제가 신규 전문가·국제화·중동·일상 소재·신규 업역일 때만 해당 모듈을 더한다.

조회하지 못한 파일은 사용자에게 알린다. 구버전 사본으로 대신하지 않는다.

## 브랜드 핵심 (`docs/brand-philosophy.md` 요약, 충돌하면 원문)

- 신사업·국제사업의 한국 행정문제를, 사람이 사실관계·문서·절차까지 직접 검토하는 서비스. 독자가 어려워하는 것은 서류 목록이 아니라 **자기 사업구조에 어떤 제도와 순서가 적용되는지**다.
- 포지셔닝: 복잡한 행정문제를 쉽게 설명하고, 실제 자료로 필요한 서류와 절차를 구체적으로 준비하는 문제 해결형 전문직. 직업명이나 구호보다 실제 수행 업무를 보여 준다. 제공하지 않는 서비스나 해결 실적으로 확대하지 않는다.
- 신뢰는 판단 과정(입력자료·대조·순서·확인 결과)과 날짜(기준일·개정일)로 만든다. 자격·경력의 우월성을 주장하지 않는다.
- 목소리: 차분하고 정확하며 과장하지 않는다. 답을 먼저, 근거를 뒤에. 판단·대조·확인 같은 말도 그 자체를 반복하기보다 누가 어떤 자료를 맞춰 무엇을 알아보는지 풀어 쓴다. 쓰지 않는 말: 완벽·무조건·성공 보장·모든 업무·업계 최고·다른 자격사보다 우수.
- 설득의 윤리: 유용한 답을 먼저 주고, CTA를 지워도 글이 유익해야 한다. 허위 희소성·마감, 부풀린 공포, 없는 후기·건수, 낚시성 질문을 쓰지 않는다. 한 글에 다음 행동은 하나.
- 경계: 결과 보장 금지, 법정 업무범위를 넘는 대리 약속 금지, 다른 자격사와는 우열이 아니라 사건에 필요한 업무축으로 구분한다. 일반 정보·생성형 AI 정보를 폄하하지 않는다.
- 전환: 글의 마지막 서술 문단은 받을 자료 2~3개와 확인해 줄 결과 1~3개를 쓴 무료 검토 안내. 그 아래에는 기존 링크형 상담 이미지 4개와 태그가 올 수 있다. 무료 범위(가능 여부·시작 방향·확인할 기관·자료)를 넘는 약속을 하지 않는다. 범위·가격·접수 경로의 정본은 웹사이트 저장소 운영정책이다.

## 3. Hard Gate: 어기면 발행하지 않는 것

이 항목에 문제가 있을 때만 막는다.

1. 법령·판례·통계의 정확성. 확인되지 않은 사실·법률 결론은 쓰지 않는다(U 표시 문장 금지).
2. 경험·후기·성과·건수·성공률·"심사자 시각"을 만들지 않는다.
3. 행정사 업무범위를 넘지 않는다. 다른 자격사와의 우열 주장·소송 대리를 암시하는 표현 금지.
4. 처리위탁과 제3자 제공처럼 핵심 법률 구분을 흐리지 않는다.
5. 독자가 직접 확인할 수 있는 범위와 전문가 검토가 필요한 경계를 구분한다.
6. 무료 검토를 권하는 서술 문단은 후반 **한 번**. 서술 본문 중간에는 연락처·상담 버튼·링크를 반복 넣지 않는다. 네이버 블로그는 마지막 무료 검토 문단 바로 아래에 사용자가 운영 중인 링크형 상담 이미지 4개를 **하나의 CTA 영역**으로 붙인다(온라인 접수 우선, 카카오톡·이메일·텔레그램은 보조). 이미지 4개를 영업 문단 4회로 세지 않는다.
7. 숫자·조문·날짜·"수 있다/또는/이하" 같은 한정어를 바꾸지 않는다.
8. 마지막에 의미 재검증을 한다(법률 의미가 처음 확인한 근거와 같은가).

## 4. Soft Guide: 자연스러울 때 적용하는 것

제목 공식, 소제목 수, 문단 길이, 질문형 소제목 개수, 사례 배치, SEO 키워드, 마케팅 기법은 전부 권고다. 필수 체크박스로 만들지 않는다. 글이 자연스러울 때 쓰고, 다 쓴 뒤 약한 부분만 고친다. 점수를 매겨 재작성을 강제하지 않는다(점수는 내부 참고용).

## 4-1. 독자가 자기 일처럼 이해하는 글쓰기 (Soft Guide)

**기본 독자는 해당 분야의 법률을 처음 접하는 사람이다.** 쉬운 낱말 몇 개나 예시의 존재만으로 쉬운 글이라고 판단하지 않는다. 독자가 "이게 내 계약서·통지서·채용 상황에서 무슨 뜻이지?"를 본문 끝까지 따라가며 이해할 수 있어야 한다. 법률의 조건과 예외, 기존 근거와 깊이는 유지하고 설명 순서를 바꾼다. 분량 축소나 새로운 사례 개수·소제목 개수를 강제하지 않는다.

**초안부터 업무의 흐름으로 쓴다(2026-10-16 사용자 피드백).** 절차·서류형 글은 독자가 자료를 받고, 내용을 읽고, 서로 다른 부분을 찾아 다음 일을 정하는 흐름을 기본으로 한다. 법령 항목을 먼저 나열한 뒤 예시를 장식처럼 끼워 넣지 않는다. 수수료·기한·필수서류는 바로 찾을 수 있게 남긴다. 모든 글에 등장인물이나 같은 이야기 틀을 강제하지 않는다.

**가정은 조건문으로 드러내며 별도 안내문을 쓰지 않는다.** 발행 본문에 "설명을 위한 가상 상황입니다", "가상의 사례입니다", "실제 상담 사례가 아닙니다" 같은 독립된 문장을 넣지 않는다. "제조업체에서 받은 양식에 우리 회사에는 없는 품질관리팀이 적혀 있다면?"처럼 `~라면`, `~인 경우`로 조건을 문장 안에 담는다. 이런 표현이면 가정임을 밝힌 것으로 본다. 안내문만 지우고 지어낸 일을 실제 사건처럼 서술하지 않는다. 꾸며낸 고객 이름·직접 대화·상담·수임·성과는 쓰지 않고, 실제 사건은 확인된 출처와 사실로 구분한다. 이 해석을 아래 Core 6과 발행 형식의 가정 표시에 함께 적용한다.

- **기존 제목의 질문과 도입을 보존**: 수정 작업에서는 사용자가 선택한 제목의 질문, 시리즈 앞머리, 독자의 상황을 보여 주는 도입과 유용한 예시를 기본으로 살린다. SEO·30자 안팎·중복 제거·"최대한 강화"를 이유로 질문의 범위를 바꾸거나 장면을 삭제하지 않는다. 검색어는 자연스러운 보완으로 넣고, 제목의 뜻이나 도입의 역할을 바꿔야 하면 변경 이유를 따로 밝힌다. 근거 없이 새 제목의 검색·전환 성과가 더 좋다고 단정하지 않는다.
- **눈앞의 상황으로 출발**: 독자가 실제로 받는 통지서, 작성하는 계약서, 지급하는 돈, 납품·배차·채용 일정처럼 익숙한 생활·업무 장면을 쓴다. 업종 글의 일상은 그 독자의 업무에서 찾는다. 무관한 장보기·학교 비유나 감정 서사를 억지로 넣지 않는다. 기존 11절의 앞부분 형식은 유지한다.
- **던진 질문에는 그 답을 먼저**: 차량을 계속 쓸 수 있는지 물었다면 먼저 그 질문에 답한다. 기한 확인이나 "검토가 필요하다"는 말로 답을 대신하지 않는다. 실제 조건에 따라 달라지면 "A라면 X, B라면 Y"로 설명하고 근거 없는 예외는 만들지 않는다. 3줄 요약이 답을 준 뒤에는 목차 다음에서 상황과 이유를 자연스럽게 풀어도 된다.
- **예시를 설명의 중심에**: 어려운 개념은 익숙한 상황이나 조건이 다른 비교에서 시작해, 무슨 차이가 생기는지 설명한 뒤 공식 용어와 근거를 연결한다. 예시가 필요한 문단만 고치고 모든 절을 같은 공식으로 만들지 않는다. 앞의 사례를 이어 쓸 수 있으면 재사용한다. 예시는 조건문으로 가정임을 드러내며 실제 상담·수임·처분 사례나 고객의 직접 발언으로 꾸미지 않는다.
- **전문용어는 뜻을 붙여 남기기**: 통지서에서 만날 공식 용어는 삭제하거나 부정확한 비유로 대체하지 않는다. '위반차수'는 '이번 일이 법령상 첫 번째 위반인지, 두 번째 위반인지'처럼 먼저 풀어 준다. '당연무효·가중처분·선행 처분'처럼 낯선 개념이 한 문장에 겹치면 설명을 나눠 연결한다. 단순히 문장을 짧게 자르는 데 그치지 않는다.
- **예시 사이의 본문도 독자의 말로**: 예시만 쉽고 다음 문단이 추상적인 법률 설명으로 돌아가면 아직 수정이 끝난 것이 아니다. '관련 사실관계', '검토할 쟁점', '적용 가능성' 대신 무엇이 언제 일어났고, 어떤 서류의 무엇을 알아보는지 적는다. 용어가 정확한 판단에 필요한 곳에서는 뜻과 함께 유지한다.
- **판례는 사건의 문제와 결론부터**: 독자가 궁금해할 상황, 실제 사건의 문제와 결론, 이유, 자기 자료에서 확인할 부분 순으로 풀어 쓴다. 사건번호·기관·날짜·현재 적용의 한계는 숨기지 않는다. 파기환송과 확정, 경감 가능성과 보장, 감차와 과징금 전환 등 법률적 구분은 쉬운 설명에서도 보존한다.
- **확인 행동과 결과를 구체적으로**: "검토가 필요합니다"에서 멈추지 않고 어떤 서류의 어느 날짜·이름·항목을 맞춰 무엇을 알아보는지 이어 쓴다. CTA에서도 '처분대상 범위와 위반차수 검토'보다 '어느 차량이 대상인지, 2차 위반으로 계산한 이유를 먼저 살펴봐야 하는지'처럼 받을 안내를 독자의 말로 쓴다. 무료·유료 범위와 다른 전문가의 업무 경계는 유지한다.
- **마케팅과 구별**: 이해를 돕는 예시와 구체적인 판단 과정을 통해 신뢰를 만든다. 감정 자극·가상의 고객 대화·확인되지 않은 손실 금액·실적을 만들지 않는다. 분량을 줄이거나 상담 문구를 늘리는 것을 쉬운 글·전환 강화와 동일시하지 않는다.

흐름은 대체로 **독자의 상황 → 그 질문의 직접 답 → 상황 비교와 쉬운 설명 → 공식 용어·근거 → 독자가 확인할 자료와 순서 → 검토 경계**를 권장한다. 사건 해설·제도 변경·서비스 안내처럼 다른 전개가 더 자연스러우면 그쪽을 쓴다. 사례를 넣거나 문장을 쉽게 바꾼 뒤에도 숫자·조문·조건·한정어의 법률적 의미를 다시 확인한다. 근거가 부족한 법률 결론을 예시로 보충하거나 새 법률 사실을 윤문 속에 몰래 추가하지 않는다.

## 4-2. 구체적인 수행 업무로 문제 해결형 전문성을 보여주기 (Soft Guide)

에토스의 콘텐츠는 법률을 쉽게 설명하는 데서 그치지 않는다. 행정사가 어떤 일을 하는지 모르는 독자도 자기 문제에서 무엇을 맡길 수 있는지 이해하도록 **막힌 상황 → 확인할 자료 → 실제 수행 작업 → 준비되는 문서나 안내 → 다음 행동**을 필요한 만큼 연결한다. 공통 철학은 `docs/brand-philosophy.md`이며 이 절만으로 작성할 수 있다. 매번 정본을 추가로 읽지는 않는다.

- **검토 이후의 일을 보여 준다.** '검토·지원·대응합니다'에서 멈추지 않고 어떤 자료의 어느 항목을 맞추고, 그 결과 어떤 내용을 정리하거나 문서를 작성하는지 설명한다. 서류 작성 자체를 낮춰 말하지 않는다.
- **구체성은 정보량과 다르다.** 숫자·판례·사례를 늘리는 대신 실제 자료와 작업, 준비할 것의 관계를 보여 준다. 수행과정을 설명하는 예시는 조건문으로 가정임을 드러내고 실제 수임사례·성과로 꾸미지 않는다. 기존 제목의 질문과 도입, 유용한 예시와 법률적 깊이는 유지한다.
- **수행 업무와 결과를 구분한다.** 자료 정리·문서 작성처럼 실제 맡은 작업은 분명하게 설명하되 허가나 처분 변경 등 외부의 결정은 보장하지 않는다. 실제 제공하지 않는 보고서·보완 대응·회신기한을 구체화라는 이유로 추가하지 않는다. 무료 검토와 유료 수임범위, 다른 전문가의 업무 경계는 그대로다.
- **이해와 의뢰 판단을 함께 돕는다.** 법률을 몰라 막힌 독자에게는 직접 확인할 기준을, 내용을 이해했지만 서류 작업을 맡기려는 독자에게는 원문과 실제 제공 범위에 있는 작성·제출 작업을 보여 준다. 자료를 전부 완성해야 문의할 수 있는 것처럼 쓰지 않되, 자료 없이 검토할 수 있다고 약속하지 않는다. 무료로 먼저 확인할 내용과 유료 작성·제출은 구분한다.
- **문단마다 같은 틀을 강제하지 않는다.** 글의 중요한 문제에서 필요한 연결만 자연스럽게 보여 준다. 이 원칙 때문에 새 사례 수·산출물 수·점수·상담 문단을 추가하지 않는다. 파생 콘텐츠는 승인 원문에 있는 수행 업무만 재구성한다.

설명 방식의 예: 의견서 작성이 실제 수임범위에 포함된 경우 '통지서의 날짜와 이름을 운행기록에 맞춰 보고, 확인된 사실과 증빙을 연결해 의견서에 담을 내용을 정리합니다'처럼 쓴다. 이 문장 자체를 모든 사건에 적용되는 서비스 약속이나 무료 작성 안내로 사용하지 않는다.

## 5. 작성 순서

1. **근거 잠금**: 경로 A는 `research/`의 조사 잠금에서 기준일 이후 법령 변경, 새 판례·제재 사례, 기존 인용의 유효성만 확인. 경로 B는 `docs/evidence-gate.md`에 따라 공식 1차 자료를 확인하고 조사 잠금을 저장한다.
2. **자연 초안**: 독자에게 설명하듯 끝까지 한 번에 쓴다. 이 단계에서는 규칙을 한꺼번에 의식하지 않는다. 필요한 곳에 독자의 구체적 상황, 첫 전문용어 풀이, 판단 기준을 보여 주는 조건형 예시를 자연스럽게 포함한다. 사례 수와 위치를 미리 고정하지 않는다.
3. **법률 의미 검증**: 초안의 법률 문장이 잠근 근거와 같은지 확인한다.
4. **제목·도입·차별점·CTA 편집**: 기존 제목의 질문과 도입의 역할을 보존하고 약한 곳만 보완한다. 이 단계에서 나머지 본문을 다시 쓰지 않는다.
5. **어려운 설명·어색한 문장만 윤문**: 개념이 겹친 문단은 4-1절에 따라 예시와 설명 순서를 부분 편집한다. 읽히는 문단까지 전부 다시 쓰거나 깊이를 줄이지 않는다. 윤문 규칙집(`vendor/im-not-ai/quick-rules.md`)은 이 단계에서만 읽는다.
6. **숫자·조문·한정어 재확인**.

통계·판례·제재 사례는 각각 하나의 실무 쟁점을 설명하는 데 필요한 만큼만 쓴다.

## 6. 최종 점검은 세 질문뿐

완성 뒤에 이것만 확인하고, 약한 곳이 있으면 그 부분만 고친다.

1. 기존 제목의 질문과 도입의 역할을 살리면서, 첫 5문단 안에 독자의 상황과 그 질문의 핵심 답이 전문용어를 몰라도 이해되게 나오는가?
2. 예시뿐 아니라 그 사이의 본문과 판례 설명도 비전문가가 따라갈 수 있고, 어떤 자료로 무슨 작업을 하며 어떤 문서나 다음 절차를 준비하는지 구체적으로 보이는가?
3. CTA 문단과 마지막 안내를 지워도 저장할 정보가 남는가?

점수·스킬 이름·작업 보고는 사용자가 요청할 때만 덧붙인다. 확인하지 못한 항목이 있으면 그것만 짧게 알린다. 원고의 편집 완료와 실제 검색·문의·수임 성과 검증을 구분하고, 근거 없이 "최대한 강화", "더 이상 개선할 곳 없음"으로 평가하지 않는다.

## 6-1. 네이버 블로그 말미 CTA 운영

- 순서: 분야별 직접 확인 범위와 개별 검토 경계 → 주제에 맞는 무료 검토 안내 문단 1개 → `온라인 접수로 상담 요청하기` 이미지 → `말미_카카오_무료검토`·`말미_이메일_무료검토`·`말미_텔레그램_무료검토` 이미지(보조 선택지) → 태그. 이미지는 각 운영 중인 실제 접수 경로에 연결한다. 이미지 순서는 기본값이며, 현장 성과가 확인되면 한 변수씩 조정한다.
- 안내 문단에는 **독자 상황·보낼 자료 2~3개·무료로 먼저 확인할 결과 1~3개**를 자연스러운 문장으로 쓴다. 분야명만 바꾼 고정 문구, 결과 보장, 무료 상담·무료 대행으로 읽히는 표현은 피한다. 무료와 유료 업무의 경계를 흐리지 않는다.
- 네 이미지가 같은 목적의 접수 수단임을 보이도록 연속 배치한다. 온라인 접수를 대표 경로로 먼저 두고 `다른 접수 방법` 같은 짧은 안내 아래 보조 3개를 묶을 수 있다. 네 이미지를 동일한 우선순위의 반복 영업 문구처럼 본문 여러 곳에 흩뿌리지 않는다. 독자가 선택할 수 있도록 기존 이미지·연결 경로는 임의로 삭제하거나 바꾸지 않는다.
- 발행 전 각 이미지의 클릭 대상이 맞는지, 모바일에서 순서와 가독성이 유지되는지 확인한다. 접수 경로별 문의·적합 문의·수임을 비교할 수 있으면 분기마다 검토한다. 4개가 1개보다 성과가 좋다고 미리 단정하지 않는다.
- 원고(`blog.md`·Google 문서)의 발행 본문과 **발행용 별도 링크설정 메모**를 분리한다. 메모는 본문·이미지에 인쇄하지 않고 편집기의 이미지 링크 대상(metadata)을 설정하는 용도로만 제공한다. 예약된 세트와 기존 승인 콘텐츠는 이 규칙 때문에 재작성하지 않는다.

### 발행용 별도 링크설정 메모 (네이버 하단 배너 정본)

CTA를 새로 추가하는 규칙이 아니라 기존 하단 온라인 접수 이미지의 연결 정보를 제공하는 규칙이다. 서술 본문에 원시 추적 URL·`utm_`·`OC=`를 노출하지 않는 원칙은 그대로다. SNS·카드의 프로필·첫 댓글 규칙과 구분하며, `naver_blog/profile`은 프로필 링크의 위치값이지 하단 이미지 연결을 금지하는 규칙이 아니다.

| 메모 필드 | 제공할 값 |
|---|---|
| 적용 위치 | 기존 온라인 접수 이미지의 link destination; 이미지·CTA 수와 순서 유지 |
| `content_id` / 확인 근거 | 기존 실제 콘텐츠키와 확인한 원본 위치. 식별자 안정성 기준은 `docs/topic-log-integration.md`의 「기록 재사용과 식별자」 |
| `package_id` / 승인 근거 | 시트의 승인된 연결 상품 ID와 승인 확인 위치. 미승인·미확인이라면 생략하고 확인 필요로 표시 |
| `destination_url` | 아래 계약에 확인된 값을 넣은 실제 주소. 미확정 값을 채운 것처럼 제공하지 않음 |
| 보조 3개 이미지 | 현재 운영 중인 각 연결 주소 유지; 외부 메신저에 지원하지 않는 추적 매개변수를 임의로 붙이지 않음 |
| 발행 확인 | 온라인 접수의 글·상품 정보 전달, 보조 채널 목적지, 모바일 순서 확인 여부 |

온라인 접수 주소 계약:
`https://ethosattorney.com/intake?source=ethos-contents&channel=naver_blog&content_id=<확인된-기존ID-또는-naver-logNo>&package_id=<승인상품ID>&placement=footer-ko`

- 위 꺾쇠 값은 설명용 자리표시자다. 확인한 ID를 URL 인코딩해 대입한다. 승인상품이 없으면 `package_id` 전체를 생략한다. 상품 연결 승인과 식별자 근거를 확인하지 못하면 추측하지 않는다.
- 발행 전 네이버 URL이 없으면 기존 실제 콘텐츠ID를 우선한다. 그것도 없으면 글 번호를 예측해 넣지 않고 기존 접수 경로를 유지하며 메모에 추적 미설정 사유를 적는다. 발행 뒤 실제 URL로 안정 식별자를 검토한다.
- 확인된 법률 근거·무료 범위·받을 자료만 CTA 문구에 반영한다. 링크 설정을 이유로 법률 내용, 가격, 서비스 범위, 기한 약속을 만들거나 변경하지 않는다.

## 7. 조사 잠금(`research/`)

한 번 검증한 법령·판례·통계는 시리즈 단위로 저장해 다음 편에서 처음부터 다시 찾지 않는다. 형식과 갱신 규칙은 `research/README.md`. 경로 B가 끝나면 조사 잠금 파일 내용을 함께 낸다(저장소에는 사용자나 Codex가 커밋한다).

## 8. 글의 뼈대 (Core 6)

1. 검색 의도에 맞는 진입부: 첫 화면에서 대상 독자와 판단 문제가 보인다.
2. 질문에 대한 직접 답: 확인된 것은 맞다·틀리다를 분명히 답하고 근거를 잇는다. 근거 없는 양시론·양비론으로 결론을 피하지 않는다. 결론이 달라지는 실제 조건이 있을 때만 구분한다.
3. 검증된 핵심 정보: 법령명·조문·기관·기한을 원문 표기대로.
4. 구체적 적용 상황 하나 이상(가정은 4-1절의 조건문으로 드러내고 실제 상담처럼 꾸미지 않는다). 그 상황에서 독자가 무엇을 확인할지 이어 쓴다.
5. 일반론과 개별 판단이 갈리는 지점.
6. 후반부에 직접 확인할 수 있는 범위와 전문가 검토가 필요한 상황의 구분 + 자연스러운 무료 검토 안내 문단 **한 번**(받을 자료 2~3개, 확인해 줄 결과 1~3개. "무료 상담" 금지).

### 역할에 따른 구조 선택

초안 전에 이 글의 주 역할을 **Traffic(검색 유입)·Authority(판단 능력 증명)·Revenue(상담 전 판단 지원)** 중 하나로 고른다. 업데이트 글도 세 역할 중 하나를 함께 지정한다.

주 역할은 강조점의 구분이다. Traffic도 독자가 맡길 작업과 의뢰 여부를 판단할 정보를 모두 후속 Revenue 글로 미루지 않으며, Authority·Revenue도 유용한 직접 답과 쉬운 설명을 생략하지 않는다. 기존 후반 CTA 한 번을 유지하고 모든 정보에 상담을 끼워 넣지 않는다.

- Traffic: 상황·직접 답 → 조건·확인 순서 → 흔한 오해 → 관련 Authority 글
- Authority: 판단 쟁점·결론 → 공식 근거 → 서류 대조·절차 순서 같은 Proof of Work → 적용 경계
- Revenue: 대상·비대상 → 받을 자료·확인 결과 → 진행 단계·제외 범위 → 후반 CTA 한 번

공통 뼈대는 Core 6으로 고정하되 소제목 이름과 전개 순서는 주제에 맞춘다. 시리즈 설계나 내부 연결을 정할 때만 `docs/content-architecture-system.md`를 함께 읽는다. 이미 발행 예정인 세트는 이 규칙 때문에 다시 쓰지 않는다.

## 9. 고정 규칙 요약

- 영문에서 행정사는 항상 **Administrative Attorney**(사무소는 Administrative Attorney Office). 다른 번역(administrative agent, scrivener 등)을 쓰지 않는다.
- 확인된 사실은 단정하고 조건·재량·추론만 한정한다(`guidelines/core/definitive-style.md`).
- 권위는 이력 나열이 아니라 판단 과정(법령 조건 구분, 서류 대조, 절차 순서)으로 보인다.
- 고정 발행 빈도·복수 CTA·"정확히 3개" 같은 과거 규칙은 쓰지 않는다. 같은 구조에 제목만 바꾼 글을 반복하지 않는다.
- 말투는 `examples/writing/README.md`의 "고치기 전 → 고친 후" 예시로 잡는다.

## 10. 태그

**쓰기 전에 5가지 묶음으로 나눠 고른다.** 한 묶음에서만 고르면 같은 말의 변형이 되어 검색에 걸리는 폭이 좁아진다.

| 묶음 | 예 | 개수(블로그 기준) |
|---|---|---|
| ① 핵심 주제어 | `#행정사업무범위` `#영업정지` | 2~3 |
| ② 제도·법령·기관 이름 | `#행정심판법` `#민사소송법` `#국가법령정보센터` | 2~3 |
| ③ **독자가 실제로 검색하는 표현**(`state/reader-language.md`, 질문형·롱테일) | `#행정심판대리` `#소송대리인자격` `#허가거부대응` | **4 이상** |
| ④ 독자 상황·업종·대상 | `#식당사장님` `#폐기물처리업` `#처음인허가` | 2~3 |
| ⑤ 절차·단계 단어 | `#보완요구` `#불복기간` `#사전통지` | **3 이상** |

- **네이버 블로그 태그**(`blog.md` 맨 끝, 본문과 한 줄 띄움): `#태그`를 공백으로 이어 **12~20개**.
- **같은 낱말의 변형은 3개까지.** `#행정사 #행정사업무범위 #행정사변호사차이 #행정사와변호사`처럼 한 낱말(예: 행정사)이 4개 이상 태그에 들어가면 린터가 알린다. 띄어쓰기만 다른 같은 태그도 한 번만 쓴다.
- **웹사이트 태그**(`website.ko.md`·`website.en.md` 머리말 `tags`·`tagsEn`): `#` 없이 **쉼표로만** 구분한 한 줄, 4~10개(`영업정지, 과징금 전환, 사전통지`). 같은 규칙으로 묶음을 섞는다. 형식은 `docs/website-md-spec.md`.
- 쓰지 않는다: 확인되지 않은 효과·"최고"류 단어, 다른 사무소 이름, 본문에 없는 주제.
- 점검: `python scripts/copy_lint.py content/<ID>`(블로그 끝 `#태그`)와 `python scripts/validate_website_md.py content/<ID>`(웹사이트 태그)가 개수·중복·낱말 쏠림을 안내한다. 안내이며 발행을 막지 않는다.

## 11. 발행 형식

- **분량은 평소 깊이를 유지한다**: 네이버 블로그 본문은 공백 포함 **8,000~11,000자**(승인된 글은 약 1만 자). 경로 A·B 모두 같다. 짧게 줄이는 것은 사용자가 요청할 때만이며, 7,000자 미만이면 린터가 `short-blog`로 알린다. 분량을 채우려고 같은 말을 되풀이하지 않고, 사례·판단 순서·확인 자료·예외를 더해 깊이로 채운다.
- **글의 앞부분 순서**: 제목(30자 안팎; **시리즈 글은 아래 고정 앞머리 규칙 우선**, 단발 글은 검색 질문·핵심 쟁점을 앞에) → **독자 상황 한 줄**(계약서·통지서·사업장·기한 같은 눈앞의 상황으로 쓰고, 가정은 `~라면` 등 조건문으로 표시하며 별도 안내문을 넣지 않음) → 인사 한 줄("안녕하세요, 행정사 지상진입니다.") → **3줄 요약**("3줄 요약" 다음에 핵심 답과 실제 적용 조건, 확인할 행동 중 필요한 내용을 쉬운 말로 세 줄에 정리하되, 숫자·조건은 본문과 같게) → 시리즈 목차(이번 글 표시) → 본문(시리즈 글은 목차 다음에 짧은 공통 도입 포함). 독자의 상황과 직접 답을 앞에서 제시한다.
- **필수 두 가지(윤문 단계)**: 문장 첫머리 "따라서"는 글 전체에서 3번까지. 쉼표로 끝나는 줄을 이어 쓰는 목록은 번호나 글머리 목록으로 바꾼다. 린터가 `so-many-therefore`·`comma-list`로 알린다.
- 출처는 본문에 "국가법령정보센터, 2021경기행심1356(2021. 12. 6.)"처럼 기관·사건번호·날짜로 쓴다. 링크를 붙일 때는 국가법령정보센터의 정식 주소만 쓰고, `utm_…` 추적값이나 `OC=` 같은 API 키가 붙은 주소는 쓰지 않는다. 출처 사이트 이름을 지어내지 않는다.
- 네이버 블로그 원고에는 `**굵게**` 같은 마크다운 기호를 쓰지 않는다. 웹사이트 MD는 `docs/website-md-spec.md` 규칙을 따른다.

### 시리즈 글의 고정 제목·공통 도입 (향후 회차부터 적용)

- **기본값은 둘 다 적용**: 한 시리즈는 모든 회차에서 동일한 짧은 제목 앞머리와 1문장 공통 도입을 사용한다. 시리즈마다 새로 정하되, 해당 시리즈 안에서는 약칭·문장 표현을 회차마다 바꾸지 않는다.
- **제목 형식**: `[시리즈 약칭 ⑫] 이번 편의 구체적 검색 질문`. 앞머리에는 실제 핵심 검색어가 들어가야 하고, 그 뒤에는 이번 회차의 독자 문제와 답의 방향이 보이게 한다. 전체는 가능하면 30자 안팎으로; 너무 긴 정식 시리즈명은 앞머리에 반복하지 않고 목차에 표기한다. 검색어와 핵심 질문이 밀리거나 제목이 부자연스러우면 짧게 다듬는다.
- **E-7 시리즈의 고정 앞머리**: `[E-7 비자 ①]`, `[E-7 비자 ②]` … `[E-7 비자 ⑬]`. 정식 시리즈명은 「외국인 고용계약서와 E-7 비자」로 목차와 공통 도입에 유지한다. 예: `[E-7 비자 ⑫] 연봉·직무·근무지 변경, 신고해야 할까요?`.
- **공통 도입의 위치**: 본문 앞 순서(제목 → 독자 상황 → 인사 → 3줄 요약 → 시리즈 목차)를 바꾸지 않는다. 목차 바로 다음 **본문의 첫 문장**에 시리즈 전체를 설명하는 고정 문장 1개를 두고, 그다음 한 문장으로 이번 편의 구체적 판단 문제와 직접 답을 연결한다. 길고 동일한 서론이나 반복 영업 문구를 넣지 않는다.
- **E-7 시리즈의 공통 첫 문장**: `「외국인 고용계약서와 E-7 비자」 시리즈에서는 외국인 채용부터 허가 후 고용관리까지 계약서와 실제 업무, 출입국 절차의 관계를 살펴봅니다.` 그 뒤의 이번 편 소개 문장은 각 편의 상황에 맞게 별도로 작성한다.
- **중복·SEO·전환 보호**: 공통 도입은 최대 2문장(고정 1 + 회차별 1). 이 제한은 반복되는 시리즈 소개에만 적용하며, 뒤에 이어지는 이번 회차의 상황 설명·납품이나 채용 같은 장면·판단 예시까지 두 문장으로 제한하거나 삭제하라는 뜻이 아니다. 독자의 상황과 직접 답은 첫 5문단 안에 이미 보여야 한다. 발행한 이전 회차를 이 형식 때문에 소급 수정하지 않는다.
- **채널별 파생**: 네이버 블로그 원고에 적용한다. 웹사이트 MD는 인사·목차를 제거하는 해당 명세를 우선하며, 카드·SNS는 각 채널의 제목·표지 규칙을 따른다. 다만 시리즈 정식명과 회차번호의 의미는 유지한다. 쉬운 설명을 파생할 때도 상황·직접 답·법률 조건의 연결은 보존하되, 블로그의 장문 도입이나 전체 구조를 다른 채널에 강제하지 않는다.

## 12. 짧은 요청문 예시

새 법률 주제(경로 B):
```
블로그 작성 경로 B(심층 조사)로 진행해 주세요. docs/blog-authoring-spec.md를 읽고 이 주제에 필요한 법률 근거만 공식 1차 자료로 검증한 뒤 research/<시리즈>.md로 정리하세요. 작성 순서는 근거 잠금 → 자연 초안 → 법률 검증 → 제목·도입·차별점·CTA 편집 → 어색한 문장 윤문 → 숫자·조문·한정어 재확인입니다. 문체 권고는 자연스러울 때만 적용하고, 마지막에 3가지 질문만 점검하세요.
```

후속편(경로 A):
```
블로그 작성 경로 A로 진행해 주세요. research/<시리즈>.md의 조사 잠금을 재사용하고 기준일 이후 변경 여부만 확인하세요. 처음부터 다시 조사하지 마세요.
```
