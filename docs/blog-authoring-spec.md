# 블로그 작성 명세 (ChatGPT 한 장 요약)

블로그·홈페이지 글을 요청받으면 긴 지침보다 이 문서를 먼저 읽는다. 이 문서는 `guidelines/channels/blog.md`(v3.1)와 상위 지침의 **작업 순서와 적용 강도**를 정한다. 사실·법률·윤리 규칙의 내용은 바꾸지 않으며, 어떤 문서를 언제 읽고 어떤 규칙을 어느 강도로 적용할지만 정한다. 충돌하면 blog.md와 상위 지침이 이기되, 아래 "경로"와 "Hard Gate / Soft Guide" 구분은 그 문서들의 적용 방법으로 읽는다.

> **사실과 법률에는 엄격하게, 문체에는 여유를 준다.** 모델이 규칙을 관리하느라 글이 늦어지고 보고서처럼 굳는 것이 가장 큰 위험이다. 초안을 쓰면서 모든 규칙을 동시에 지키려고 하지 않는다.

## 1. 먼저 경로를 고른다

요청을 받으면 아래 중 하나로 분류하고, 한 줄로 어느 경로인지 알린 뒤 시작한다.

| 경로 | 언제 | 하는 일 |
|---|---|---|
| **A. 일반 경로**(기본) | 같은 시리즈 후속편, 이미 검증된 원고의 수정·재작성, 제목·도입·문체 개선, 법률 쟁점이 하나뿐인 글 | `research/`의 조사 잠금을 재사용하고 **변경 여부만** 확인. 새로 찾는 자료는 이 글에 꼭 필요한 근거만 |
| **B. 심층 조사 경로** | 새 법률 주제, 판례·통계·제재 사례까지 필요한 글, 조사 잠금이 없거나 기준일이 지나 법령이 바뀌었을 가능성이 큰 글 | 공식 1차 자료로 근거를 잠그고 `research/<시리즈>.md`에 저장한 뒤 작성 |
| **C. 파생** | 승인된 블로그를 카드·SNS·웹사이트 MD로 옮길 때 | 승인된 블로그 원문이 Source Lock. 법률 재조사 없음 |

판단이 애매하면 A로 시작하고, 근거가 부족하다고 확인된 부분만 B 방식으로 보강한다.

## 2. 읽을 파일

경로 A·C는 이것만 읽는다.
1. 이 문서
2. `docs/brand-philosophy.md`
3. 해당 시리즈의 `research/<시리즈>.md`(있으면)
4. `state/reader-language.md`(제목·첫 문장·FAQ 질문 표현, 비어 있으면 건너뜀)

경로 B는 위에 더해 `MANIFEST.md`, `guidelines/core/top-level.md` 4절(Evidence Gate), `guidelines/core/definitive-style.md`, `docs/legal-verification.md`를 읽는다. `guidelines/channels/blog.md`는 전체를 읽지 않고 필요한 PART(리서치·Evidence Gate, 제목, 전환, 발행 전 QA)만 조회한다. `docs/topic-discovery.md`와 글감관리표는 **소재를 고르는 요청**일 때만 읽는다. 주제가 해당할 때만 모듈(신규 전문가·인간 판단·국제화·중동·일상 소재·신규 업역)을 더한다.

조회하지 못한 파일은 사용자에게 알린다. 구버전 사본으로 대신하지 않는다.

## 3. Hard Gate: 어기면 발행하지 않는 것

이 항목에 문제가 있을 때만 막는다.

1. 법령·판례·통계의 정확성. 확인되지 않은 사실·법률 결론은 쓰지 않는다(U 표시 문장 금지).
2. 경험·후기·성과·건수·성공률·"심사자 시각"을 만들지 않는다.
3. 행정사 업무범위를 넘지 않는다. 다른 자격사와의 우열 주장·소송 대리를 암시하는 표현 금지.
4. 처리위탁과 제3자 제공처럼 핵심 법률 구분을 흐리지 않는다.
5. 독자가 직접 확인할 수 있는 범위와 전문가 검토가 필요한 경계를 구분한다.
6. CTA는 후반 **한 번**. 무료 검토 범위를 넘는 약속·연락처·버튼·링크를 본문에 넣지 않는다.
7. 숫자·조문·날짜·"수 있다/또는/이하" 같은 한정어를 바꾸지 않는다.
8. 마지막에 의미 재검증을 한다(법률 의미가 처음 확인한 근거와 같은가).

## 4. Soft Guide: 자연스러울 때 적용하는 것

제목 공식, 소제목 수, 문단 길이, 질문형 소제목, 사례 배치, SEO 키워드, 마케팅 기법은 전부 권고다. 필수 체크박스로 만들지 않는다. 글이 자연스러울 때 쓰고, 다 쓴 뒤 약한 부분만 고친다. 점수를 매겨 재작성을 강제하지 않는다(점수는 내부 참고용).

## 5. 작성 순서

1. **근거 잠금**: 경로 A는 `research/`의 조사 잠금에서 기준일 이후 법령 변경, 새 판례·제재 사례, 기존 인용의 유효성만 확인. 경로 B는 `docs/legal-verification.md`로 공식 1차 자료를 확인하고 조사 잠금을 저장한다.
2. **자연 초안**: 독자에게 설명하듯 끝까지 한 번에 쓴다. 이 단계에서는 규칙을 의식하지 않는다.
3. **법률 의미 검증**: 초안의 법률 문장이 잠근 근거와 같은지 확인한다.
4. **제목·도입·차별점·CTA만 편집**: 다른 부분은 건드리지 않는다.
5. **어색한 문장만 윤문**: 필요한 곳만. 전체를 다시 쓰지 않는다. 윤문 규칙집(`vendor/im-not-ai/quick-rules.md`)은 이 단계에서만 읽는다.
6. **숫자·조문·한정어 재확인**.

통계·판례·제재 사례는 각각 하나의 실무 쟁점을 설명하는 데 필요한 만큼만 쓴다.

## 6. 최종 점검은 세 질문뿐

완성 뒤에 이것만 확인하고, 약한 곳이 있으면 그 부분만 고친다.

1. 첫 5문단 안에 독자의 상황과 핵심 답이 나오는가?
2. 다른 사무소 글과 구별되는 실제 검토 방식(순서·대조·확인 결과)이 보이는가?
3. CTA 문단과 마지막 안내를 지워도 저장할 정보가 남는가?

점수·스킬 이름·작업 보고는 사용자가 요청할 때만 덧붙인다. 확인하지 못한 항목이 있으면 그것만 짧게 알린다.

## 7. 조사 잠금(`research/`)

한 번 검증한 법령·판례·통계는 시리즈 단위로 저장해 다음 편에서 처음부터 다시 찾지 않는다. 형식과 갱신 규칙은 `research/README.md`. 경로 B가 끝나면 조사 잠금 파일 내용을 함께 낸다(저장소에는 사용자나 Codex가 커밋한다).

## 8. 글의 뼈대 (Core 6)

1. 검색 의도에 맞는 진입부: 첫 화면에서 대상 독자와 판단 문제가 보인다.
2. 질문에 대한 직접 답: 확인된 것은 맞다·틀리다를 분명히 답하고 근거를 잇는다. 근거 없는 양시론·양비론으로 결론을 피하지 않는다. 결론이 달라지는 실제 조건이 있을 때만 구분한다.
3. 검증된 핵심 정보: 법령명·조문·기관·기한을 원문 표기대로.
4. 구체적 적용 상황 하나 이상(가정 사례는 가정이라고 쓴다).
5. 일반론과 개별 판단이 갈리는 지점.
6. 후반부에 직접 확인할 수 있는 범위와 전문가 검토가 필요한 상황의 구분 + 자연스러운 무료 검토 안내 문단 **한 번**(받을 자료 2~3개, 확인해 줄 결과 1~3개. "무료 상담" 금지).

## 9. 고정 규칙 요약

- 영문에서 행정사는 항상 **Administrative Attorney**(사무소는 Administrative Attorney Office). 다른 번역(administrative agent, scrivener 등)을 쓰지 않는다.
- 확인된 사실은 단정하고 조건·재량·추론만 한정한다(`guidelines/core/definitive-style.md`).
- 권위는 이력 나열이 아니라 판단 과정(법령 조건 구분, 서류 대조, 절차 순서)으로 보인다.
- 고정 발행 빈도·복수 CTA·"정확히 3개" 같은 과거 규칙은 쓰지 않는다. 같은 구조에 제목만 바꾼 글을 반복하지 않는다.
- 말투는 `examples/writing/README.md`의 "고치기 전 → 고친 후" 예시로 잡는다.

## 10. 발행 형식

- 시리즈 글은 제목, 첫 인사 한 줄, 시리즈 목차(이번 글 표시)를 앞부분에 둔다. 앞 편과 같은 형식을 따른다.
- 출처는 본문에 "국가법령정보센터, 2021경기행심1356(2021. 12. 6.)"처럼 기관·사건번호·날짜로 쓴다. 링크를 붙일 때는 국가법령정보센터의 정식 주소만 쓰고, `utm_…` 추적값이나 `OC=` 같은 API 키가 붙은 주소는 쓰지 않는다. 출처 사이트 이름을 지어내지 않는다.
- 네이버 블로그 원고에는 `**굵게**` 같은 마크다운 기호를 쓰지 않는다. 웹사이트 MD는 `docs/website-md-spec.md` 규칙을 따른다.

## 11. 짧은 요청문 예시

새 법률 주제(경로 B):
```
블로그 작성 경로 B(심층 조사)로 진행해 주세요. docs/blog-authoring-spec.md를 읽고 이 주제에 필요한 법률 근거만 공식 1차 자료로 검증한 뒤 research/<시리즈>.md로 정리하세요. 작성 순서는 근거 잠금 → 자연 초안 → 법률 검증 → 제목·도입·차별점·CTA 편집 → 어색한 문장 윤문 → 숫자·조문 재확인입니다. 문체 권고는 자연스러울 때만 적용하고, 마지막에 3가지 질문만 점검하세요.
```

후속편(경로 A):
```
블로그 작성 경로 A로 진행해 주세요. research/<시리즈>.md의 조사 잠금을 재사용하고 기준일 이후 변경 여부만 확인하세요. 처음부터 다시 조사하지 마세요.
```
