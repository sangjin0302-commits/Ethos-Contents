# 블로그 작성 명세 (ChatGPT 한 장 요약)

블로그·홈페이지 글을 요청받으면 긴 지침보다 이 문서를 먼저 읽는다. 이 문서는 `guidelines/channels/blog.md`(v3.1)를 대체하지 않는다. 충돌하면 blog.md와 상위 지침이 이긴다. 여기에 없는 세부(제목 유형, 비용 문단, 특수 글 유형, 홈페이지 전환 등)가 필요할 때만 blog.md의 해당 PART를 조회한다.

## 읽을 파일 (이 순서, 이것만)

1. `MANIFEST.md`
2. 이 문서
3. `docs/brand-philosophy.md` (철학·CTA 원칙)
4. `docs/legal-verification.md` (사실·법률 검증)
5. 소재를 새로 고르는 경우에만 `docs/topic-discovery.md`(+ 글감관리표가 있으면 `docs/topic-log-integration.md`)
6. 주제가 해당할 때만 모듈(신규 전문가·인간 판단·국제화·중동)

조회하지 못한 파일은 사용자에게 알린다. 구버전 사본으로 대신하지 않는다.

## 작성 순서

1. 내부 메모(원고에 노출 금지): 독자, 질문, 직접 답, 근거, 판단 경계, 다음 행동 한 가지, 확인 기준일.
2. 공식 1차 자료로 사실을 잠근다(`docs/legal-verification.md`). 확인 못 한 것은 U로 두고 발행하지 않는다.
3. 자연 초안을 쓴다. 이 단계에서는 규칙을 한꺼번에 의식하지 않는다.
4. 사실·법률 → 마케팅 → 금지 표현 → 윤문 → 의미 재검증 순서로 별도 패스를 돈다(`docs/language-quality-workflow.md`).
5. 아래 자가 점검표를 통과한 뒤 완성본만 낸다. 점수·스킬 이름·작업 보고는 사용자가 요청할 때만 덧붙인다.

## 글의 뼈대 (Core 6)

1. 검색 의도에 맞는 진입부: 첫 화면에서 대상 독자와 판단 문제가 보인다.
2. 질문에 대한 직접 답: 결론 먼저, 근거 다음.
3. 검증된 핵심 정보: 법령명·조문·기관·기한을 원문 표기대로.
4. 구체적 적용 상황 하나 이상.
5. 일반론과 개별 판단이 갈리는 지점.
6. 후반부에 직접 확인할 수 있는 범위와 전문가 검토가 필요한 상황의 구분 + 자연스러운 무료 검토 안내 문단 **한 번**.

## 고정 규칙 요약

- 확인된 사실은 단정하고 조건·재량·추론만 한정한다(`guidelines/core/definitive-style.md`).
- 경험하지 않은 상담·수임·후기·성과·"심사자 시각"을 만들지 않는다. 확인되지 않은 수치·AI 활용 홍보 표현을 쓰지 않는다.
- 본문에 연락처·버튼·카카오톡·텔레그램·이메일 링크를 넣지 않는다.
- CTA는 본문 후반 한 번. 마지막 문장은 앞에서 다룬 자료·판단과 연결된 무료 검토 안내(받을 자료 2~3개, 확인해 줄 결과 1~3개). "무료 상담" 금지.
- 권위는 이력 나열이 아니라 판단 과정(법령 조건 구분, 서류 대조, 절차 순서)으로 보인다.
- 고정 발행 빈도·복수 CTA·"정확히 3개" 같은 과거 규칙은 쓰지 않는다. 같은 구조에 제목만 바꾼 글을 반복하지 않는다.

## 자가 점검표 (완성본 앞에 한 번만 짧게)

- [ ] 대상 독자와 핵심 질문이 첫 화면에 있다
- [ ] CTA 문단과 마지막 안내를 지워도 저장할 만한 체크리스트·기준·순서가 남는다 (**먼저 주기 테스트**)
- [ ] 독자가 이 글만 읽고 오늘 해 볼 행동이 하나 이상 있다
- [ ] 모든 법률·제도 문장에 확인 기준일과 공식 근거가 있다. U 표시 문장이 없다
- [ ] 숫자·조문·날짜·"수 있다/또는"이 원문과 같다
- [ ] 경험 창작, 성과·건수·성공률, 다른 자격사 비교 우위 표현이 없다
- [ ] CTA는 한 번이고 무료 검토 범위를 넘는 약속이 없다
- [ ] 윤문과 의미 재검증을 마쳤다 (스킬 사용 불가 시 `manual-equivalent`로 기록)
- [ ] 확인하지 못한 항목을 사용자에게 알렸다
